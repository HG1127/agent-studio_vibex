# Windows 电脑连接体验 — preview.6

保留原员工工作台的页面、路由和业务功能。桌面连接状态由 App 级 Provider
维护，在 SiteShell 主内容顶部显示“当前电脑”选择、在线状态、暂停/恢复和管理按钮。
管理区域直接在主页面展开，不创建额外 BrowserWindow 或管理 Dialog。

首次连接使用原“连接电脑与浏览器”向导，依次核对用途、选填网站和本机文件范围，
在同一个向导中确认并启动。网站留空不会启用浏览器，也不要求安装 Chrome；
后续通过主界面管理授权添加具体网站时才检查 Chrome。不存在默认任意网站授权。

仅选择当前员工服务端返回的已绑定、未撤销设备。本地偏好按服务器和已验证员工
身份隔离。启动时恢复最近明确选择的电脑；首次升级没有偏好时选择最近使用的
本地连接。主动暂停保留暂停状态。远程电脑出现在清单时不会在本机启动其运行时。
切换电脑会同步文件工作区；未处理的文件/授权草稿会阻止切换。

私有 IPC、主窗口来源检查、服务端身份、权限修订、文件选择和逐操作审批继续生效。
普通网页版保留其原有连接器流程。此次没有部署服务器或改变数据库架构。

验收：

- `node --test desktop/tests/*.test.cjs tests/local-connection-setup.test.mjs`
- `node desktop/tests/connection-flow.integration.mjs`：生产前端、真实隔离 PB、真实
  连接器子进程；只有系统文件夹选择器使用固定临时测试目录适配器。覆盖首次向导、
  网站留空、真实文件读取、内联授权、后加网站、切换和重启恢复。
- `pnpm check` 与 `pnpm test:e2e:parallel -- --workers=1`
- `node desktop/audit.mjs` 与安装包/安装后 EXE 的 `packaged-smoke.mjs --system-temp`。

旧版本窗口/托盘进程仍运行时，系统不会强行终止它或重复启动另一组连接器。
升级前需从旧版本托盘选择“退出并停止本机连接”，再运行新版安装程序。
主界面显示实际桌面版本，便于识别是否仍打开旧程序。
