[Agent Studio Preview27 — WorkBuddy 本机操作与任务结果可靠性]
- WorkBuddy 已处于前台时，apps.observe 直接只读观察，不再重复弹出无动作的激活确认；后台激活仍需本人确认。
- apps.launch / apps.windows 返回明确的授权应用 ID 与窗口 ID，便于后续观察准确引用。
- 本机确认超时、不可用、取消及工具参数错误提供明确中文原因码；不自动重放不确定副作用。
- 修复完整本机工具回执持久化及重跑 Attempt 结果隔离，避免同一运行 ID 的新旧结果互相覆盖。
- 修复空评估对象被误认为缓存，以及评分/反馈 JSON 未正确投影到运行记录 API 的问题。
- Agent 创建前需求预览按 HTTP 状态区分登录失效、权限不足、后端接口缺失、超时和服务端异常；HTTP 404 明确提示服务端 Hooks 版本未同步，不再误导员工反复登录。
- 若原始需求保存成功但能力预览接口缺失，保留需求原文和幂等请求编号；后续重试复用同一记录，不重复保存、不提前调用模型。
- 移除 Agent 选择框下方重复的资源设置说明，保留统一「资源与设置」入口。
- 配套后端源码包包含原始需求保存、能力依赖预览及 Agent 生命周期所需 Hooks；客户端不自动部署 PocketBase/Worker，业务后端须按公司 LAN 发布规程经 main CI、备份和人工审批后部署。
- 已通过需求错误诊断单测 2/2、真实隔离 PocketBase/SQLite 集成、Chrome 需求预览失败恢复与正常生成回归、TypeScript/Vite 构建和 119 项生产资源隔离检查。
- 真实 WorkBuddy 研究任务仍需在更新后的员工客户端与后端环境中完成最终实机验收。
