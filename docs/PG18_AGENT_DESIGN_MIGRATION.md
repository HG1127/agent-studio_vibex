# Optional Native Agent design migration

The independent generate/revise domain adds natural-language Agent design to
the Native PostgreSQL pilot. It preserves the full seven-field model result:
name, goal, task scope, deliverables, tool suggestions, task plan and completion
criteria. The default output budget is 4096; choosing 8192 or 16384 requires the
same separate explicit model-fee confirmation. Existing review, optimization
and generic Agent token budgets are unchanged.

This source adds optional migration062 after061. It does not run that migration
or add it to default fresh050 initialization. PocketBase remains the current
runtime. No production migration, deployment or paid provider execution is
authorized by this implementation.

The Native routes belong to `/api/v2/agent-design`. They use the verified
employee Cookie, same-origin/CSRF checks and current owner/resource validation.
They provide source and sending previews, explicit submission, original
receipt recovery, result reads, cancel/erase, editable save previews and a
separate save confirmation. Capability hints do not replace server checks.

New requests persist private input and actual model/resource row snapshots.
A distinct design Worker claims metadata and calls the existing private7459
service family over mTLS using a design-specific proof and route. An
independent minimal dispatch role commits a one-use reservation before any
credential read or provider POST. Real Native governance, source, model and
resource checks repeat before credential access, after DNS and after POST.
No business transaction is held through the provider wait. An uncertain
outcome never authorizes a second automatic reservation or provider POST.

Only the original independent model broker can read encrypted model material.
The new design roles cannot select private input/output tables or model
ciphertext. Migration062 grants only thirteen fixed RPCs and installs no login
memberships. Its exact installed catalog and predecessor audit chain must be
verified on the original authenticated connection. Any genuine CI repair must
keep the matching SQL and catalog/body pins consistent.

The same review-service lifecycle optionally hosts the separate design path;
its original approval and the additional design execution approval are both
required. Design uses separate Worker/dispatch login credentials and pools.
The combined service closes both real claim gates before reporting drain,
joins both loops before ending pools, and closes both private clients. The
existing eight telemetry kinds and original review proof domain are unchanged.

Saving is independent of model execution. A new Agent starts with empty
executable resources and requires approval. A revision keeps the actual
existing runtime model, HTTP/MCP tools, knowledge and approval configuration.
Only six descriptive fields change; tool suggestions grant no capabilities.
Agent changes, original045 history, audit and the immutable save receipt commit
in the same transaction. Original receipt recovery precedes new-write and live
source checks. Cancel/erase cannot promise a refund or undo an external effect;
erasing design bodies does not erase an explicitly saved Agent.
