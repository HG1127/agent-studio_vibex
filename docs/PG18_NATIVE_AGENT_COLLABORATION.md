## 员工操作

原生员工菜单通过独立 Cookie / CSRF 登录访问本人及已共享的角色。
所有者按现有员工邮箱授予读者或编辑者、调整权限、撤销，并核对授权版本。
读者只能读安全描述；编辑者只能提交带说明的安全描述提案。共享不授予角色执行、
凭据、模型、工具、知识或原始配置的访问权限。员工停用及所有者停用立即参与权限检查。

所有者核对当前完整配置指纹、提案指纹及明确确认后才能采纳；拒绝提案与撤销权限
在关闭配置写入后仍可进行。配置或授权变化使旧提案失效，恢复旧授权不会恢复提案。
描述历史只有所有者可读；恢复仅合并五项安全描述，保留当前模型、工具、知识等绑定。
它不替代完整配置快照、发布、归档、模板市场及集成调用能力。

网络响应丢失时，界面冻结原操作内容，可只读核对回执或由员工明确重交同一请求。
只读核对从不实施操作。切换菜单保留当前员工待确认请求，退出登录后销毁。
明确的请求拒绝允许刷新和重新核对；不明结果继续保留原请求。

## 描述容量与执行边界

五项安全字段为目标、范围、交付物、任务计划和完成标准。目标最多 3000 UTF-16 单元，
范围 4000，各列表最多 30 项、每项 500；编辑 / 提案的紧凑 JSON 总量最多 23000。
只读投影可以显示已存在的合法完整描述。前端、普通角色配置、私有模型输入及 Agent
规划路径使用同一字段上限，任务计划会进入实际模型输入。

工具权限列表仍保持原有 20 项 / 每项 300 的上限；任务输入 2000、单次私有 RPC
16 KiB、单次模型提示 12000、Agent 规划提示 131072 等总预算保持独立。
同时填满所有描述字段可能超过单次模型总预算，此时明确拒绝而不截断文本。

## 数据库与验证

四张私有表均 FORCE RLS；独立 `agentstudio_collaboration` 辅助角色不可登录、
没有成员关系，API、Worker、Broker 和认证角色无账本直读权限。17 个固定函数及
精确角色配置触发器接受启动审计，功能关闭时也检查权限变化。
完整配置指纹包含所有者、配置、名称及单调版本，避免配置改回后的旧授权重用。
操作回执绑定操作者、请求、目标及规范化意图；接收人解析后在事务锁内再次核对回执。
角色、提案状态、历史、审计和回执同一事务提交，回执失败全部回滚。

嵌入式 SQL、Native Cookie、SDK 和私有 mTLS 验证覆盖安全投影、并发 / 重放、授权
变更、停用员工、私有字段保留、恢复及事务故障。真实 PG18 独立服务登录与受限浏览器
验证仅在 GitHub 合成环境运行；必须核对候选同一提交的成功结果后才算通过。
实际员工 UAT、目标访问控制、长时间 Worker 和备份恢复仍需目标验收。
