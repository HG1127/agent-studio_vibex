# Agent Studio 公司运行监控与负责人代审批（独立版）

更新：2026-10-15。适用于 `agent_studio_vibex版本` 当前独立 PocketBase + SQLite 运行链路。**目前只有源码与隔离集成测试结果，不代表已部署到公司服务器。**

## 业务目标与权限边界

- 员工在 `/internal-overview` 查看**自己的** Agent / Workflow 运行、异常、工具写入待复核及调度状况。
- 公司管理员在 `/manager` 查看员工的**汇总运行元数据**：任务运行数、待审批数、失败数、超期计划和 Worker 心跳。默认**不能**以管理员身份读取员工完整 Prompt、运行结果、知识库原文、模型密钥或其他员工的私有记录。
- 员工可针对**某一次、某一个正在等待批准的 Agent 步骤**显式委托一名当前激活的管理员进行批准或拒绝。默认没有代审批授权。
- 授权带指定负责人、待审批步骤的完整 SHA-256 指纹、失效时间（API 最多 72 小时，当前 UI 使用 24 小时）。到期或员工撤销后立即不可审批。步骤变化时必须重新委托，不能沿用旧授权。
- 代审批只更改原员工所属运行的审批状态；不会将任务所有权、模型连接、工具写入权限或知识库读写权授予负责人。其批准不代表外部服务已经成功执行，继续执行仍由原 Runner/Worker 负责。
- 授权、撤销、批准、拒绝均写入专用 `agent_studio_review_audit`，记录所有者、负责人、操作人、时间及步骤序号。**不会将工具参数、API Key 或原文写入新审计表。**
- 审批列表只包含该管理员被明确委托且尚有效的项目。待审批参数仅提供目标主机、方法及字段名等元信息，**不暴露任意原始参数值**；员工须主动提交审核说明供负责人核对。审批本身不能替代外部写入审计、出站策略或公司审批政策。

## 员工操作流程

1. 使用独立 Studio 账号登录，打开左侧「公司运行与审批」。
2. 员工只有待审批 Agent 运行时，才会在「委托负责人审批我的任务」看到可委托步骤。
3. 从已启用的管理员中选择负责人，**主动填写8～500字、不得包含内部机密和密钥的审核说明**。点击「授权24小时」，确认待处理 Agent、工具及授权边界。
4. 负责人登录同一路由，在「委托给我的审批」查看**员工主动填写的审核说明**、工具名称和仅含目标主机/字段名称的参数元信息。所有原始请求参数值、URL 路径与请求体均隐藏。负责人点击「批准」或「拒绝」时，必须再次确认。
5. 负责人操作后不能重复决定同一待办；员工可随时撤销尚未执行的委托。若原运行的步骤改变，授权自动失效，需重新授权。

## API 与源码

服务端 Hook: `pocketbase/pb_hooks/studio_company.pb.js`，共享辅助模块：`modules/studio_company_ops.js`。

| 路由 | 身份 / 限制 |
| --- | --- |
| GET `/api/studio/company/overview` | `studio_users` 当前启用的管理员；仅统计 |
| GET `/api/studio/approval-delegations` | 当前员工；只显示自己待审批 Agent 和可用管理员 |
| POST `/api/studio/approval-delegations` | 仅该运行所有者可 grant/revoke；grant 校验接收人角色、有效期与当前步骤 |
| GET `/api/studio/manager/approvals` | 仅管理员；返回当前有效授权步骤的脱敏预览及指纹 |
| POST `/api/studio/manager/decision` | 管理员 + 有效授权 + 确认 + 原步骤指纹匹配；事务内单次批准/拒绝并写审计 |

执行期间管理员身份和员工身份均从 PocketBase 的已验证 Token 读取。接口不得通过用户自行提交的 `X-Rh-User-Id` 判断所有权。

当前持久化数据为：
- `agent_studio_approval_delegations`：每运行最多一条授权、待审批步骤指纹及员工主动提交的审核说明；
- `agent_studio_review_audit`：不可由普通业务端删除的追加式审批记录。

数据库创建按新表幂等执行；如已有内部测试环境旧表，增量补充 `pending_hash`、`review_note` 字段。不在本次开发中修改生产数据库。正式升级前必须备份、检查现有对象和做回滚演练。

## 可复现验收

```sh
pnpm test:company
pnpm test:e2e
pnpm check
```

`tests/studio-company.integration.mjs` 在**临时数据库**中验证独立管理员与普通员工的 Token、403 权限拒绝、公司级汇总不泄露员工邮箱/指令、未经员工授权不能代审批、撤销、指纹过时拒绝、一次性审核、负责人及所有者审计、一旦产生新审批步骤旧授权不可复用。

本地测试通过也不等于正式员工验收。正式部署需对两名真实员工、一个公司管理员完成完整操作，以及 24 小时 Worker 驻留与备份回滚验证。

## 明确未完成

- 还没有可由负责人直接进入员工私人运行详情的全公司审查权限；这需要更细的保密分级、授权模型与审批证据规范。
- 本轮审批只覆盖 Agent 待审批工具步骤；Workflow 审批及多级会签尚待开发。
- 员工组织架构、团队/部门角色、共享可编辑 Agent、团队知识库权限、离职同步撤权仍待进一步建设。
- 没有真实生产环境负载/出站网络/密码重置策略/业务审批规则的验收。正式员工应用仍判定为 **NO-GO**。
