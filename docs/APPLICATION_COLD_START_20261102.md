# 本地应用冷启动与任务执行修复验收

桌面版本：`0.1.0-preview.11`。内置连接器：`0.1.0-preview.20`。

本次以已验证的桌面 preview.9（`30abb1fd7269ba2f48ffb35716f9b5aeb3667632`）为基线，修复应用冷启动、窗口识别、任务入口和结果核验。不包含另一工作区尚未完成的 preview.10 自动更新改动。不部署服务器，不切换数据库，不修改生产数据。

## 原因及改动

1. Qoder 外层启动器与窗口进程不是同一个 EXE。原逻辑只匹配外层路径，导致实际启动后仍显示无窗口。现在在本人保存应用授权时解析其已准备好的版本目录，同时固定启动器和实际程序的 SHA-256；运行时两者都需匹配。不会把任意子进程或未来新版本自动纳入授权。
2. 原逻辑在进程创建后立即返回，只枚举一次窗口。现在复用已打开的匹配窗口；冷启动只提交一次，最多等待 25 秒。尚未就绪会显示等待状态，提示检查启动弹窗，不自动重复启动。
3. 原页面主要提供手动调试控件。现在可直接填写“希望应用完成什么任务”，创建应用任务并进入现有 Agent 试跑，保留所选电脑和任务。选择模型并点击运行后，Agent 才执行；创建入口本身不调用付费模型。
4. 原观察结果缺少控件内容，无法核对输入。现在返回可读值和支持的动作，显示观察有效期；动作后重新观察，以实际页面或文件回执验证结果。敏感控件不返回内容。
5. UIA 读取、控件值写入和控件调用不再错误地依赖前台焦点；需要真实键鼠输入的回退仍检查前台、遮挡与焦点。用户键鼠活动保护保留：发现活动即停止，不继续后台操作。
6. 避免每次观察重复启动窗口枚举助手；原生观察仍重新验证实际 EXE 身份，并等待应用输入队列。原生只读观察超时提高到 35 秒，低内存下的等待不再误报为应用未启动。

Electron 应用冷启动使用固定的 `--force-renderer-accessibility` 参数；不接受模型提供的任意命令行。此机制见 [Chromium 辅助功能说明](https://www.chromium.org/developers/design-documents/accessibility/)。没有暴露可用控件时显示具体诊断，停止猜测操作。

## 用户操作

1. 从旧版本菜单选择“退出并停止本机连接”，再安装新版。只关闭窗口会保留旧托盘进程。
2. 在主界面确认当前电脑在线，打开“管理连接 → 应用授权”。对于旧版 Qoder 授权，核对显示的实际版本程序后重新保存一次授权。应用二进制更新后同样需要重新核对保存。
3. 如果 Qoder 原先已打开，请先自行保存工作、关闭原窗口，再从新版启动。旧进程不会因为升级 Agent Studio 自动重启或获得启动参数。
4. 在“本地应用”选择目标应用，填写任务，点击“创建应用任务并进入试跑”，选择模型并运行。逐步批准具体操作，查看最终结果证据。也可继续使用下方手动检查区。
5. 登录、管理员权限、不可访问控件或用户接管等障碍会明确停止。不要在结果未确认时重复提交有副作用的动作。

## 验证口径

真实桌面验收使用专用 WinForms 测试程序、隔离 PocketBase、实际连接器子进程和本机确定性模型，没有向外部付费模型请求推理，没有向聊天软件发送信息，没有修改 Qoder 项目。

验收从测试程序关闭开始，经现有员工页面创建应用任务、进入 Agent 试跑，完成实际冷启动、观察、输入、回读、点击保存和最终回读。共 6 次真实本机工具调用，2 次本机内容操作确认，保存回执只生成 1 次；核对内容为 `AGENT_COLD_TASK_VERIFIED`。额外的模型调用为引擎记忆摘要，不被当作应用动作。

同一用例还验证：首次单窗口连接向导、网站可留空、主界面文件读取、撤销应用授权、稍后增加网站、切换电脑，以及程序重载后仅恢复最近选择的本机。验收 JSON 中 `realBackend=true`、`realConnectorChild=true`、`productionData=false`、`uiErrors=[]`。

Qoder 在本机已验证启动器与实际版本程序的双摘要和 Electron 识别；未验证向其真实项目提交任务或消耗模型额度。通用 Windows UI Automation 不保证所有软件的所有页面都可操作。Qoder 官方另提供 [脚本任务接口](https://docs.qoder.com/cli/run-in-scripts)，本次没有新增该 CLI 适配器。

项目回归：完整 34 项端到端首轮通过 32 项，第 33 项发现原有排程编辑器焦点竞争，第 34 项因运行器遇错停止未运行。修复焦点后，Agent 组 9 项定向重跑全部通过，包含第 33、34 项。34 个场景均已覆盖通过；不把首轮日志标为全绿。最终单元测试、桌面单元测试、包内容审计、安装包启动和安装后 EXE 启动结果见发布目录的 `acceptance.json` 及原始日志。

## 复现

```powershell
pnpm check
node --test desktop/tests/*.test.cjs
pnpm test:e2e:parallel --workers=1
node desktop/tests/connection-flow.integration.mjs --native-applications --cold-task-only
node desktop/audit.mjs
node desktop/tests/packaged-smoke.mjs <安装包> --system-temp --native-file-actions --install-dir=<独立测试目录>
node desktop/tests/packaged-smoke.mjs <独立测试目录中的Agent Studio.exe> --system-temp --native-file-actions
```

真实控件测试期间应保持键鼠空闲；不能通过关闭接管保护来让测试通过。原始日志和截图只进入本地发布验收资料，测试数据库、设备凭据和个人配置不进入 Git 或安装包。
