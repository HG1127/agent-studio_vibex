# Agent Studio 企业内部上线：Go / No-Go 验收闸门

更新：2026-10-15。当前项目是**不依赖 VibeX/RunningHub SSO 的独立部署源码**，不是原 VibeX 发布版本。**当前 NO-GO：只完成隔离本地验证，缺少真实内网、身份、持续运行、旧数据迁移和备份恢复的上线证据。**

## 原问题清单追踪

| 功能模块 | 开发与测试状态 | 仍需落实/签收 |
| --- | --- | --- |
| Agent 创建与配置 | 核心实现、集成测试通过 | 真实员工创建→配置模型→运行→审查结果的实地 UAT |
| Agent 执行与 Harness | 工具调用、检查点、租约及外写审批有本地测试 | 长任务/长上下文运行、崩溃恢复、异常租约/严格幂等保护的生产观察 |
| Workflow 可视化编排 | 编排器及执行核心有自动化测试 | 复杂条件分支、循环、异常分支、多 Provider 使用场景的真人验收 |
| 定时任务与 Worker | 时区/计划、幂等/定时触发的隔离测试通过 | 真正常驻进程、连续24小时和故障恢复演练 |
| 知识库 | 个人与授权团队 RAG、跨员工语义检索、独立查询模型/默认拒绝、Agent/Workflow 引用在隔离测试通过 | 部门动态 RBAC、文档级许可、真实模型版本漂移、费用审计、扫描件 OCR、大规模检索质量 |
| 模型连接与工具集成 | 连接/密钥隔离/审批/外写测试有覆盖 | 真实 Provider、出站 SSRF/内网与元数据访问封禁、费控审计 |
| 内部 Agent 共享 | 同一 Agent 受控编辑、审核、逐字段差异、安全文本历史和 Owner 恢复通过隔离测试，普通 Owner 直接修改也记录安全文本快照 | 全字段（含敏感配置）审计/恢复、统一版本管理、分支合并、复杂审批及正式员工 UAT |
| 内部运行总览 | 员工个人运行总览及新增公司级**只读汇总** | 部门/负责人角色分层、正式员工使用反馈 |
| 负责人审批 | 本地新增员工**主动委托某次 Agent 步骤**，支持撤销/过时拒绝/审计 | 真实业务审批政策、多级/Workflow 会签、终端操作审核 |
| 员工身份与权限 | 独立 PocketBase 已签名 Token，员工/管理员账号、禁用及跨员工隔离通过测试 | HTTPS 网关、原始 PB 禁止公网直连、真实员工/离职撤权与管理员监督 |
| 数据库及运维 | SQLite 迁移、备份、恢复工具有自动测试，V8 PG 仍为隔离试验 | **真实**备份与恢复演练、告警、升级回滚批准；严禁 PG 试验接管生产 |
| 线上发布 | 独立 Nginx/systemd 示例模板、前端构建通过 | 完整部署、域名/证书/进程、运行版本校验与 UAT，尚未执行 |

“核心实现”“本地集成通过”与“正式部署/已上线”是不同状态，不得混写。

## 上线前必需的 P0 证据

1. 在批准的域名/IP 上，由管理员、员工 A、员工 B、禁用员工 C 测试独立登录、数据隔离；携带伪造 `X-Rh-User-Id` 的请求不得突破真实 Token 身份；原始 PocketBase 7000 端口对非授权客户端不可达。部署必须有 HTTPS 与安全反向代理。
2. 员工 A/B 各自运行至少一个 Agent 和 Workflow，使用授权测试资料验证知识库引用、工具审批和运行事件，检查隔离权限，避免真实金融/业务写入。
3. 负责人工作台仅显示被允许的跨员工具体运行统计。只有员工授权时才能看到脱敏待审批步骤，并验证撤销、失效、步骤改变、重复审批都被拒绝。操作真实环境必须产生审计。
4. 使用有授权的真实 Embedding/LLM Provider，核对模型用量、机密文件合规、外部工具目标地址准入与拦截，控制成本。
5. Worker 用常驻进程在员工关闭浏览器后连续运行至少 24 小时。核对心跳、补偿调度、重启恢复、失败任务可审计，并确保不会重复执行外部 POST。
6. 对真实待迁移数据建立校验备份；由所有者审核历史 RH 用户 ID 到新员工账号的映射，先在隔离副本演练迁移与回滚。严禁自动合并归属不明的数据。
7. 指定系统负责人、安全负责人、生产运维责任人、备份值班人以及发布/回滚审批人，留存真实的签收时间和测试结论。

## 本地可复现测试

```sh
pnpm test:company
pnpm test:standalone
pnpm test:semantic
pnpm test:team-knowledge
pnpm test:agent-collaboration
pnpm test:schedules
pnpm test:migrations
pnpm test:e2e
pnpm test:e2e:parallel        # 提速选项：2 路、每测试文件独立临时库
pnpm check
# 仅在被授权的部署主机、使用安全保存的生产配置文件执行：
# pnpm go-live:preflight --env /approved/server/studio.env --json
# 必须额外提供有负责人签收的 --evidence 文件，才可能进入待签字状态。
```

本地测试默认在临时 PocketBase / SQLite 上执行，**不会验证公司生产环境的安全或连续运行情况**。生产发布不属于本轮代码改造范围，需正式授权及另一次交付流程。

## 上线变更与回滚

先确定新独立站点与后端资源，不直接覆盖其他公司网站和已在运行的 PB 数据。运维先备份，再核对迁移日志及版本、验收纯净副本。批准后才部署经构建的 `dist`、PocketBase Hook 和常驻 Worker，最后在正式 HTTPS 地址上执行上述业务与安全验收。任何关键项不通过，继续 **NO-GO**。
