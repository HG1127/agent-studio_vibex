# Agent Studio V16｜桌面网页版高频任务体验优化记录

> 范围：独立的 `agent_studio_vibex版本`。本轮**只针对桌面 Web** 的真实员工使用流程；不做移动端迭代。保留原工作树中 PostgreSQL 迁移和其它并行未提交改动，不提交、不推送、不部署生产。

## 一、从用户任务而不是模块数量评估桌面体验

第一优先级用户旅程：

`进入工作台 → 查找需自己批准/回复的任务 → 直达原运行 → 批准方案并续跑 → 优先阅读成果 → 对结果反馈/生成改进稿 → 直接选中已保存的 Agent 试跑 → 按需调整高级配置 → 修改正式方案并明确保存`

用户体验要求：关键操作可见、一次点击能直达目标、页面不隐藏错误与待办、执行结果先于技术日志、试跑设置与正式 Agent 版本隔离、重复触发不得无意产生第二个付费运行。UI 无法自动代替外部 OAuth 或将未经审核的工具权限授予 Agent。

## 四、仍待继续的桌面 UX 项目

1. **桌面生产真实员工 UAT**：当前测试使用隔离浏览器、临时账户和模拟模型/MCP，并不等于内网生产已正式部署。需要真实员工完整试跑、审批及模型成本校验。
2. **大量待办分页**：总数包含全部，工作台最多显示最近 20 项；超过此数量时后续应提供独立可分页待办列表，不应声称所有待办都在首页可操作。
3. **Agent 列表规模与查找**：100+ Agent 的批量搜索、收藏和最近使用排序尚未做真实性能/用户研究。
4. **复杂桌面多标签协作**：方案草稿与版本冲突保护已有独立测试；应继续做实际多账号操作和权限检查。
5. **其它工作空间**：V15 已做覆盖矩阵，但 V16 聚焦桌面高频路径，不能声称所有业务模块每个操作都已完成桌面 UAT。
6. **PostgreSQL**：严格维持独立迁移、备份/对账/切换的 GO/NO-GO，不属于本轮 UX 优化。

开发状态：源码修改保存在用户原项目工作区，未自动提交、推送、部署；原数据库与生产环境未更改。
