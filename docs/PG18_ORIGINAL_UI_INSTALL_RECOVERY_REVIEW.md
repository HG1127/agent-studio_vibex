## 先确认安装 profile，不沿用旧数量绕过检查

1. 锁定同一审阅来源的原 UI、Native API、Worker/Broker、解析器/依赖、SQL map、unit/drop-in 和签名/运行时清单。源码 ZIP 是运维材料；桌面客户端仍沿用独立的签名应用内更新交付约定。
2. complete069 是基础 profile；现有原页 profile 是独立组合入口。其明确排除的可选版本不能被默默加入。将当前所需全部原页后端合同逐项映射到已审阅来源；没有统一 profile 及恢复证明时保持 NO-GO。
3. 旧050、059/060 冻结来源、旧六账号与 full069/后续独立账号协议分别保留。禁止过滤 ledger、角色、表或 session 来套过 fresh-only 校验器；已发生员工登录或独立账号准备后，不再冒充空库阶段。
4. 沿用原 NativeAuth 和首位管理员流程，身份由服务端真实验证；客户端任意 owner/header 不能成为认证。不得把旧文档的外部 SSO 方案当作当前独立登录的必装组件。
5. 源模板包含 preflight 模式，也有独立批准的 serve 路径；必须逐项审阅实际 `ExecStart`、`ExecStartPre`、unit 名、凭据 ABI 和沙箱。模板存在、注释示例或预检通过均不意味着已安装或获准启动。
6. 安装 COMMIT 或外部副作用回包不明时保留原 operation/request 身份与 unknown，使用原只读确认协议；不自动换身份重试、重新初始化或清空后再跑。

Worker 验收沿用原 BEGIN/SAMPLE/END 协议和至少二十四小时要求，保留现有 5/8/15/30/45 秒边界、全部八类 fresh-ready、完整十四 LOGIN 串行/max1/pool1、即时来源/owner/OID/ACL 与清理检查；不以进程存在、短故事或预检退出零代替长跑，不扩大期限来完成签收。

## 分别准备三个恢复集

### A. 旧 PB 可恢复集

- 由获授权运维在受控位置保存在线一致性数据库快照及工具完整清单；不手工拼热写入 DB/WAL。
- 另行盘点对应的文件存储、应用/PB/Worker 版本及来源摘要、反向代理和服务配置、加密密钥与 TLS 材料。秘密只进受控保管，不进仓库、PR、聊天、源码包或通用 CI 工件。
- 仅在新的独立恢复位置演练，旧源保持不变。核验数据库完整性、全部应保留对象、原独立员工登录与 owner/权限、实际文件和 Worker 的禁用状态。
- 未明确允许真实副作用前，恢复副本不调度、不调用外部模型/工具。旧系统仍保持可恢复；不以测试数据可丢弃为由删源或撤销恢复材料。

### B. PG18 最终组合恢复集

- 复用现有 guarded PG18 合成恢复流程作为基础，先由 Root 另行授权一次性合成 CI 验证最终统一 profile；本文件不新增执行脚本或授权目标演练。
- 备份范围要覆盖业务、认证、审计、回执/账本、任务/计划/未知结果、全局角色/成员/ACL 等对应 profile 要求；只核对表数或恢复成功退出码不足。
- 恢复只允许新的、归属明确的隔离目标，已有目标一律停止审查；不使用覆盖、清库或全局杀会话作为默认恢复方式。保留源库未变的证明。
- 核验完整表映像、函数/约束/来源、强制 RLS 与真实 LOGIN 的完整原审计。秘密恢复按原独立保管协议处理，不能把口令/校验器写进普通 dump 证据、日志或模板。
- 恢复后实际集群、数据库 OID 或进程身份发生变化时，按原协议为新的获授权目标重新审阅和绑定签名/运行时材料；不伪造旧身份、编辑旧签收值或跳过 fresh/OID/owner 检查。
- 认证使用后不能删 session 来重跑 fresh-only 门禁。保留 unknown outcome 及请求/回执，禁止重放付费或外写操作来“验证恢复”。

### C. 应用与运行材料恢复集

- 保存与数据库 profile 匹配的原页构建、Native/Worker/Broker 来源和依赖摘要、受审 unit/drop-in、网络/TLS 配置版本及受控凭据保管记录。
- 独立确认原页入口、真实 Cookie 登录、同源请求、跨员工拒绝、默认禁用的 provider/执行能力和回滚版本匹配。
- 不混用旧独立工作台前端、旧 Native 源包或只有基础库的安装结果。部署路径、地址、面板入口与秘密保存在用户控制的运维记录，本文只引用不含位置的证据编号。

## 明确的手动切换和回退边界

| 时点 | 所需人工决定 | 必须保留的边界 |
| --- | --- | --- |
| 仅源码/合成验证 | 审阅候选与下一轮一次性合成 CI | 不接触目标；旧 PB 和 Worker 保持原职责；没有切流许可 |
| PG 安装或启动失败，尚无新业务 | 核对目标归属、保存失败证据，决定隔离候选的后续处理 | 不自动重试写入、不修改旧 PB、不自动 DROP/覆盖 |
| 获准切换前 | 明确停写窗口、当前单一认领者、恢复集、RPO/RTO、回退条件及签收人角色 | 旧 PB Worker 与新 PG Worker 不并行认领同一真实任务；新执行能力逐项独立批准 |
| 切换后已有新写入或未知外部结果 | 冻结新的业务接纳，保存 PG 状态和回执，由负责人决定对账/导出与可接受数据损失后再批准切回 | 旧 PB 恢复不等于自动恢复切换后 PG 新数据；不把 unknown 标成功、不自动重放副作用 |
| 回退后 | 实际验证原页、旧独立身份、文件及唯一 Worker，再单独签收 | 保留失败 PG 副本和审计证据；恢复结果不能反向冒充过去的 GO |

任何路由、服务、数据库连接或启停改变均留待独立明确授权。本材料没有此类操作命令。没有恢复演练、原页员工 UAT、原长跑及最终来源对应的安全/网络/权限签收时，状态继续为 **NO-GO**。
