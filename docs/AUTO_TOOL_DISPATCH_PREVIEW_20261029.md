# Agent Studio 自动调度体验迭代（2026-10-29）

## 本轮交付

本轮在既有 Agent Harness 和运行事件基础上，新增一个透明的任务预检与实际调用摘要层；不另建绕过权限的执行引擎。

- `src/lib/agentTaskDispatch.ts`：从用户指令识别候选能力，按依赖顺序生成计划建议，列出能力缺口、所需具体工具和副作用审批提示。
- `src/components/agent-run/TaskDispatchPreview.tsx`：任务输入时显示预检，区分“已匹配 / 能力缺口 / 待执行”，展示前置依赖，并提供工具连接、插件市场和电脑连接的直接入口。
- `src/lib/agentToolExecutionTrace.ts` 与 `AgentToolExecutionTrace.tsx`：根据真实已保存的 `tool_call`、`tool_result`、`error` 和 `approval_pending` 事件，显示等待结果、成功、失败或等待审批；不会将预检计划当成已执行结果。
- `tests/agent-task-dispatch.test.mjs` 与 `tests/agent-tool-execution-trace.test.mjs`：覆盖能力缺口、工具匹配、精确文件权限、只读连接拒绝、副作用审批标记、依赖顺序和真实事件状态。

## 重要边界

1. 预检是可解释的启发式规划建议，不是完整的 LLM 任务规划器，也不直接执行工具。真实运行仍由已有 Harness 模型决策与后端授权、工具策略、审批门和运行检查点负责。
2. 候选能力只有在当前保存的 Agent 工具选择、试跑开关和可核验连接/设备目录范围内才会被标记为可用；未知状态默认不可信。
3. 文件读取、编辑、打开、移动、删除分别要求实际的设备能力和目录授权。外部写入需匹配可写工具，GET/只读连接不能满足写操作。
4. 复杂指令可能超出关键词预检的覆盖范围。若预检无法识别，不代表任务没有依赖；执行引擎仍应按真实工具调用结果和授权状态停止或请求用户介入。
5. 真实运行中的工具事件摘要基于数据库保存的事件；只有匹配的工具结果事件才能显示“已返回”，只有审批事件才能显示“等待审批”。

## 继续实现的优先级

- 用模型生成可编辑的结构化任务 DAG（输入、输出、依赖、验收标准），但将规划和执行分开。
- 运行前做工具发现与能力映射：内置工具、已验证 HTTP/MCP 插件、本机连接器分别报告支持程度与缺口。
- 只允许在用户已授权的工具集合内自动路由；写入/删除/对外提交在执行前显示具体目标、参数、风险并逐次审批。
- 将计划节点与实际运行事件绑定，支持暂停、失败定位、从安全检查点继续，以及按验收条件核实结果。
- 对每个新增路由/工具使用真实隔离服务和浏览器 E2E，避免只测静态界面。

本轮未执行提交、推送、生产部署或自动扩权；保留原有数据库、设备绑定和连接器版本。
