# Agent Studio 桌面版 — WorkBuddy 5.9.3「组织 OS 方案设计」闭环验收

日期：2026-11-06。来源：用户截图、精确任务运行记录的只读核验、源码检查和隔离测试。

## 复现与证据

- 用户任务为“新建任务去调研『组织OS』方案设计”，要求真实打开 WorkBuddy、创建新对话、提交问题并读取实际回复。
- 对截图中的失败运行只读查询：前一步 `apps.launch` 已成功；下一步 `apps.observe` 状态为 `failed`，参数含 `app`、`window`、`activate:true`，类型分别符合要求。
- 旧连接器将底层异常统一转成“本地工具执行失败或已停止”，**未保存原始原因代码**，因此无法从历史记录判定是原生确认超时、焦点丢失、权限或窗口不可达。不得编造确定根因。
- `apps.observe` 在目标窗口已经前台时，旧实现仍请求额外的本机激活确认；这使本可只读完成的操作增加了最长约 90 秒的确认等待。本次调整仅取消“已在前台”这一无动作场景的冗余激活，后台窗口仍需本机逐次审批。
- 2026-11-06 只读服务器检查：`/srv/agent-studio-lan/current` 仍指向旧版本 `43acc2f...`，缺少 `modules/agent_run_retry.js` 和 Agent Engine 重跑路由。客户端更新不等于后端更新。

## 已实施的源码修复

1. 删除 Agent 下拉框下方重复说明；保留「资源与设置」。
2. 合并重复的本机任务结果分支；持久化完整回执、关联 `result_id`，重跑尝试以独立结果命名空间存储，保证历史结果不覆盖。
3. 应用工具报错分类：参数错误、不可用、控制权限、原生确认超时／取消／不可用，返回安全且可执行的中文提示。不自动重放可能有副作用的操作。
4. `apps.launch` / `apps.windows` 输出明确的 `app` 授权ID和窗口ID；`apps.observe` 对已在前台的授权窗口只读观察，不再触发无必要的确认；后台窗口仍由用户审批激活。
5. 空 `evaluation: {}` 不再被当成有效缓存；运行记录 API 正确解析评分和反馈 JSON，使已保存五维评分在 UI 可见。
6. 如果旧后端缺少重跑端点，界面将给出明确的 HTTP 404 中文诊断，且不擅自创建替代任务。
7. 迁移演练覆盖新增的第 16 项 Attempt 归档迁移，验证既有记录保留及重启幂等。
