## 新增的窗口视觉能力

- `apps.observe_visual`：仅截取已授权应用的指定窗口，不要求应用暴露可操作控件。
- `apps.act_visual`：根据当前截图的图片坐标点击、追加输入、按键或滚动。
  绑定应用文件身份、窗口句柄、进程、标题和边界。
- 每个可操作截图凭据 30 秒有效且只使用一次；每次动作后自动返回新截图。
  背景只读截图不授予操作凭据，动作后的截图失败也不会重放提交。
- 保留本机逐次审批、失焦/遮挡/接管停止、受限按键和已识别敏感控件保护。
  `accepted=true` 只是动作回执，不能代表业务完成。
- 原生辅助程序是构建时编译的固定实现，不接受模型脚本或任意终端命令。
- 主界面中选点与执行动作分离，换图后旧选点失效，输入草稿保留。

此能力目前位于开发分支，**已安装的 preview.26 不包含新增视觉路径**。
不会宣称通用视觉操作已经适配所有软件、所有密码控件或所有显示环境。

## 修复的质量闭环问题

实际隔离 Chrome 回归发现：评估接口已生成分数，但运行记录投影丢失 JSON
评分及反馈，导致界面仍显示「生成评估」。现在从记录字段读取结构化 JSON，
空对象仍归一为 null，来源授权撤销时仍遮蔽结果；完整评估缓存不会再次计费。
创建向导测试也显式选择员工已授权模型，保留多模型时必须选择的产品保护。
