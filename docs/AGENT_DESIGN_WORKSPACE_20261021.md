# Agent Studio：任务、能力与角色工作台

本次改造以 `bad460d621aff6049b711ecf3d419955e5ea1f36` 为基线，集中处理创建 Agent 到连接工具、角色执行、人工介入、验收和再次优化的链路。开发分支为 `feat/harness-design-workspace-20261021`，与进行中的 PostgreSQL 迁移隔离。

## 1. 产品结构与主要判断

原体验的主要问题是：创建时要求用户先理解工具名称；方案字段、连接设置和执行状态混在一个长页面；多人协作与 Agent 角色容易混淆；运行步数容易被误认为完成进度；修改方案、正在执行的任务和成功试跑之间缺少清楚的版本关系。

新的导航按用户正在完成的工作组织：

| 一级模块 | 核心工作 | 主要入口 |
| --- | --- | --- |
| 工作台 | 找到已有 Agent、最近工作与下一步 | 我的 Agent、最近运行 |
| 设计与编排 | 设计目标、角色、任务与交付 | 设计 Agent、工作流、模板、团队 Agent、成员协作与评审 |
| 工具与连接 | 管理模型、资料与执行能力 | 模型、知识库、HTTP 工具、插件市场、电脑与浏览器 |
| 运行与验收 | 提交任务、处理待办、检查成果 | Agent 试跑、运行记录、运行监控 |
| 管理中心 | 管理组织、成员与系统设置 | 保留既有管理能力 |

“成员协作与评审”表示人对方案的协作；“角色与任务”表示一个 Agent 运行内部的职责和阶段。两者不再共用含混的团队概念。

## 2. 从任务到工具的创建链路

用户先描述任务。方案生成请求同时提供当前员工可访问的工具目录元数据，包括真实工具标识、说明、来源和读写属性，不把连接凭据发给设计模型。

模型可输出结构化能力需求 `capability_requirements`。每项包含：名称、用途、能力类别、读写动作、是否必需、负责角色、通用市场检索词及建议工具标识。建议字段经过有界白名单规范化；建议本身不会授予账号权限。

设计工作台分为四个模块：

1. **目标与交付**：目标、范围、具体交付物。
2. **角色与任务**：单助手或阶段角色、职责、输入、任务、交付、依赖与工具权限。
3. **工具与资料**：唯一一份 Harness 能力清单、候选连接、知识库，以及按需展开的手动工具选择。
4. **完成标准**：执行前方案确认、完成条件。

能力清单区分“已选用”“有候选，待选择”“需要测试连接”和“需要连接”。每项说明为什么需要、由哪个角色使用以及下一步动作。

匹配优先顺序：

1. 内置能力。
2. 当前账号的实际 HTTP 连接和已经验证、发现工具的 MCP 连接。
3. 当前已授权的 Smithery 目录返回的真实候选。
4. 自定义 API / MCP 接入。

匹配检查具体动作和文档类型。例如读取邮箱不能满足发送邮件；PDF 工具不能满足 Excel 导出；浏览器点击不能满足文件上传。候选基于工具名称、说明与元数据判断，仍需测试实际功能。

新接入的自定义接口和 MCP 工具可以在能力卡片的“绑定已有连接”中直接选用，不依赖重新生成方案。已知动作、读写类型及服务领域必须兼容；通用业务需求还需要用户查看工具说明并明确映射。工具已在全局清单中，不会自动证明它满足一个尚未映射的业务需求。选择绑定不执行工具，不给其他角色增加权限；未通过测试的连接仍显示待测试。

第三方市场只接收经过白名单整理的通用能力词。目录不可用或尚未授权时，页面明确显示状态，保留手动连接入口。

## 3. 角色是可执行的阶段

角色配置不是提示词中的一个标题。前后端共用相同的职责概念，后端独立验证结构、依赖、工具范围和运行预算。

每个角色包含：

- 名称与职责边界；
- 输入、任务列表、阶段交付与完成标准；
- 前序依赖；
- 本阶段允许调用的工具。

当前实现支持最多 8 个角色，按依赖顺序在同一次运行中依次执行。默认“资料研究 → 方案执行 → 审核交付”只是可编辑起点，初始工具权限为空。

运行使用冻结的 `spec_snapshot`。每个阶段的工具范围是全局工具与角色工具白名单的交集。模型通过 `role_complete` 提交明确阶段成果，后端持久化到 `checkpoint.role_state` 后再交接。前序角色不能通过提前 `final` 跳过后续角色；最后角色才可产生最终结果。

暂停、审批和服务重启保留阶段状态。批准工具调用后继续执行原来保存的调用；连接、参数或调用摘要变化时遵循既有重新审批逻辑。

运行摘要展示真实当前角色、下一阶段和已保存成果。时间线展示实际的角色开始、交付和对应工具调用。缺失、未知版本或不一致的检查点不会被猜成已完成。

切换单助手会清除能力需求的旧角色关联；删除某个角色只移除对应关联，不将工具权限转交给其他角色。历史草稿的失效关联有明确提示与修复按钮。恢复先前角色分工是显式操作，恢复的角色工具始终受当前全局工具清单约束。删除角色造成的阶段依赖缺口单独提示，需由用户确认调整。

**范围说明：**这是同一运行内的顺序角色执行，尚未实现多个独立 Agent 并行工作、角色专属模型或角色间自由协商。阶段提交也不等于已独立核验其事实准确性。

## 4. 电脑与浏览器能力

新增“浏览器与电脑工具”入口，统一显示实际已登记的 HTTP / MCP 能力，支持浏览器、电脑软件和其他接口分类，并提供浏览器读取、浏览器操作、桌面文档操作的 HTTP 接入模板。

模板需要真实执行器地址。Agent Studio 后端通过既有 HTTP / MCP 执行链路调度连接中的具体工具，保留工具作用域、账号隔离和写入审批。电脑上的执行器负责其软件、目录、动作范围与浏览器登录会话。

界面区分 HTTP 最近测试状态、MCP 工具发现状态、停用和未知状态；没有设备心跳时不会显示“电脑在线”。HTTP 的 `localhost` 指后端所在机器，其他电脑需提供后端可达地址。

**范围说明：**本次没有在用户电脑上安装远程控制服务，也未自动获得桌面软件或浏览器会话权限。接入入口和运行调度复用真实执行链路；具体浏览器和桌面任务需要完成对应执行器连接后验证。

## 5. 运行页与验收

运行页以任务为中心。设置默认折叠，展开后分为模型与工具、完成标准与确认、执行预算、方案步骤。结果区分为成果与反馈、执行过程、验收条件、长期记忆。

工具审批和补充信息始终处于工作区标签之外，切换结果、过程或验收时不会隐藏待办。验收草稿保持挂载，避免切换标签丢失未保存输入。

步数显示为资源使用量。预算耗尽明确显示未完成；成功结束提示用户检查成果并按验收条件判断，不将运行状态当作质量证明。

直接打开运行页也执行新任务准备检查，核验必需能力、连接测试状态和角色工具范围；有阻塞项时给出返回方案或连接页的入口。该检查用于启动新任务，不会阻止对已有任务的审批、补充信息或恢复。

创建向导的发布准备检查比较当前方案与成功运行的完整快照；角色或能力需求变更后，旧成功运行不能继续充当新方案的验证证据。已配置的质量断言继续检查真实输出。

## 6. 修改、保存与历史边界

AI 调整先生成可比较的建议。生成建议不改草稿；应用只改草稿；明确保存才写服务器。修改期间存在版本防护，避免异步建议覆盖用户的新编辑或另一个 Agent。

保存请求独立核验编辑器当前关联的 Agent。保存 A 时切换到 B，A 的迟到成功、失败或响应正文均不能改写 B 的记录 ID、版本、草稿或保存状态，也不能触发旧的试跑跳转。同一 Agent 在保存期间继续编辑时，服务器版本仍正常更新，后续新内容保持未保存状态。已经完成的服务器保存不会被回滚。

角色和能力需求会随方案保存、恢复当前浏览器草稿，并保留在运行快照。旧客户端省略新增字段时，后端保留原字段；所有者明确提交空列表可以清除。

现有“描述与规划版本”只恢复目标、范围、任务步骤、交付物和完成标准。角色、能力需求、工具、模型和知识库权限保持当前配置，界面说明这一范围。发布版本和运行快照继续记录各自既有的配置快照。

## 7. 验证方法

新增单元与行为测试已纳入 `pnpm test`；角色真实接口测试纳入 `pnpm test:e2e:parallel`。另外提供 `pnpm test:design-workspace`，使用正常员工登录、Chromium、临时真实 SQLite、本地模型和 MCP fixture 验证完整交互。

覆盖重点：

- 能力动作匹配、角色工具作用域、第三方搜索词约束；
- 依赖循环、最小阶段预算、禁止提前结束；
- 真实重启后的阶段恢复和成果交接；
- 写入审批前零执行、批准后执行一次、越角色和越账号拒绝；
- 旧客户端字段保留、明确移除、运行快照不随草稿改变；
- 创建、四模块编辑、AI 建议预览与保存、执行环境真实空态；
- 新增连接的显式能力映射、组织切换后关联修复、异步保存和切换隔离；
- 运行设置折叠、待办跨标签可见、验收草稿保留、人工补充后续跑。
