# Agent Studio：任务、能力与角色工作台

本次改造以 `bad460d621aff6049b711ecf3d419955e5ea1f36` 为基线，集中处理创建 Agent 到连接工具、角色执行、人工介入、验收和再次优化的链路。开发分支为 `feat/harness-design-workspace-20261021`，与进行中的 PostgreSQL 迁移隔离。

## 1. 产品结构与主要判断

原体验的主要问题是：创建时要求用户先理解工具名称；方案字段、连接设置和执行状态混在一个长页面；多人协作与 Agent 角色容易混淆；运行步数容易被误认为完成进度；修改方案、正在执行的任务和成功试跑之间缺少清楚的版本关系。

新的导航按用户正在完成的工作组织：

| 一级模块 | 核心工作 | 主要入口 |
| --- | --- | --- |
| 工作台 | 找到已有 Agent、最近工作与下一步 | 我的 Agent、最近运行 |
| 设计与编排 | 设计目标、角色、任务与交付 | 设计 Agent、工作流、模板、团队 Agent、成员协作与评审 |
| 工具与连接 | 管理模型、资料与执行能力 | 模型、知识库、HTTP 工具、插件市场、电脑与浏览器 |
| 运行与验收 | 提交任务、处理待办、检查成果 | Agent 试跑、运行记录、运行监控 |
| 管理中心 | 管理组织、成员与系统设置 | 保留既有管理能力 |

“成员协作与评审”表示人对方案的协作；“角色与任务”表示一个 Agent 运行内部的职责和阶段。两者不再共用含混的团队概念。

## 2. 从任务到工具的创建链路

用户先描述任务。方案生成请求同时提供当前员工可访问的工具目录元数据，包括真实工具标识、说明、来源和读写属性，不把连接凭据发给设计模型。

模型可输出结构化能力需求 `capability_requirements`。每项包含：名称、用途、能力类别、读写动作、是否必需、负责角色、通用市场检索词及建议工具标识。建议字段经过有界白名单规范化；建议本身不会授予账号权限。

设计工作台分为四个模块：

1. **目标与交付**：目标、范围、具体交付物。
2. **角色与任务**：单助手或阶段角色、职责、输入、任务、交付、依赖与工具权限。
3. **工具与资料**：唯一一份 Harness 能力清单、候选连接、知识库，以及按需展开的手动工具选择。
4. **完成标准**：执行前方案确认、完成条件。

能力清单区分“已选用”“有候选，待选择”“需要测试连接”和“需要连接”。每项说明为什么需要、由哪个角色使用以及下一步动作。

匹配优先顺序：

1. 内置能力。
2. 当前账号的实际 HTTP 连接和已经验证、发现工具的 MCP 连接。
3. 当前已授权的 Smithery 目录返回的真实候选。
4. 自定义 API / MCP 接入。

匹配检查具体动作和文档类型。例如读取邮箱不能满足发送邮件；PDF 工具不能满足 Excel 导出；浏览器点击不能满足文件上传。候选基于工具名称、说明与元数据判断，仍需测试实际功能。

新接入的自定义接口和 MCP 工具可以在能力卡片的“绑定已有连接”中直接选用，不依赖重新生成方案。已知动作、读写类型及服务领域必须兼容；通用业务需求还需要用户查看工具说明并明确映射。工具已在全局清单中，不会自动证明它满足一个尚未映射的业务需求。选择绑定不执行工具，不给其他角色增加权限；未通过测试的连接仍显示待测试。

第三方市场只接收经过白名单整理的通用能力词。目录不可用或尚未授权时，页面明确显示状态，保留手动连接入口。

## 3. 角色是可执行的阶段

角色配置不是提示词中的一个标题。前后端共用相同的职责概念，后端独立验证结构、依赖、工具范围和运行预算。

每个角色包含：

- 名称与职责边界；
- 输入、任务列表、阶段交付与完成标准；
- 前序依赖；
- 本阶段允许调用的工具。

当前实现支持最多 8 个角色，按依赖顺序在同一次运行中依次执行。默认“资料研究 → 方案执行 → 审核交付”只是可编辑起点，初始工具权限为空。

运行使用冻结的 `spec_snapshot`。每个阶段的工具范围是全局工具与角色工具白名单的交集。模型通过 `role_complete` 提交明确阶段成果，后端持久化到 `checkpoint.role_state` 后再交接。前序角色不能通过提前 `final` 跳过后续角色；最后角色才可产生最终结果。

暂停、审批和服务重启保留阶段状态。批准工具调用后继续执行原来保存的调用；连接、参数或调用摘要变化时遵循既有重新审批逻辑。

运行摘要展示真实当前角色、下一阶段和已保存成果。时间线展示实际的角色开始、交付和对应工具调用。缺失、未知版本或不一致的检查点不会被猜成已完成。

切换单助手会清除能力需求的旧角色关联；删除某个角色只移除对应关联，不将工具权限转交给其他角色。历史草稿的失效关联有明确提示与修复按钮。恢复先前角色分工是显式操作，恢复的角色工具始终受当前全局工具清单约束。删除角色造成的阶段依赖缺口单独提示，需由用户确认调整。

**范围说明：**这是同一运行内的顺序角色执行，尚未实现多个独立 Agent 并行工作、角色专属模型或角色间自由协商。阶段提交也不等于已独立核验其事实准确性。

## 4. 电脑与浏览器能力

新增“浏览器与电脑工具”入口，统一显示实际已登记的 HTTP / MCP 能力，支持浏览器、电脑软件和其他接口分类，并提供浏览器读取、浏览器操作、桌面文档操作的 HTTP 接入模板。

模板需要真实执行器地址。Agent Studio 后端通过既有 HTTP / MCP 执行链路调度连接中的具体工具，保留工具作用域、账号隔离和写入审批。电脑上的执行器负责其软件、目录、动作范围与浏览器登录会话。

界面区分 HTTP 最近测试状态、MCP 工具发现状态、停用和未知状态；没有设备心跳时不会显示“电脑在线”。HTTP 的 `localhost` 指后端所在机器，其他电脑需提供后端可达地址。

**范围说明：**本次没有在用户电脑上安装远程控制服务，也未自动获得桌面软件或浏览器会话权限。接入入口和运行调度复用真实执行链路；具体浏览器和桌面任务需要完成对应执行器连接后验证。

## 5. 运行页与验收

运行页以任务为中心。设置默认折叠，展开后分为模型与工具、完成标准与确认、执行预算、方案步骤。结果区分为成果与反馈、执行过程、验收条件、长期记忆。

工具审批和补充信息始终处于工作区标签之外，切换结果、过程或验收时不会隐藏待办。验收草稿保持挂载，避免切换标签丢失未保存输入。

步数显示为资源使用量。预算耗尽明确显示未完成；成功结束提示用户检查成果并按验收条件判断，不将运行状态当作质量证明。

直接打开运行页也执行新任务准备检查，核验必需能力、连接测试状态和角色工具范围；有阻塞项时给出返回方案或连接页的入口。该检查用于启动新任务，不会阻止对已有任务的审批、补充信息或恢复。

创建向导的发布准备检查比较当前方案与成功运行的完整快照；角色或能力需求变更后，旧成功运行不能继续充当新方案的验证证据。已配置的质量断言继续检查真实输出。

## 6. 修改、保存与历史边界

AI 调整先生成可比较的建议。生成建议不改草稿；应用只改草稿；明确保存才写服务器。修改期间存在版本防护，避免异步建议覆盖用户的新编辑或另一个 Agent。

保存请求独立核验编辑器当前关联的 Agent。保存 A 时切换到 B，A 的迟到成功、失败或响应正文均不能改写 B 的记录 ID、版本、草稿或保存状态，也不能触发旧的试跑跳转。同一 Agent 在保存期间继续编辑时，服务器版本仍正常更新，后续新内容保持未保存状态。已经完成的服务器保存不会被回滚。

角色和能力需求会随方案保存、恢复当前浏览器草稿，并保留在运行快照。旧客户端省略新增字段时，后端保留原字段；所有者明确提交空列表可以清除。

现有“描述与规划版本”只恢复目标、范围、任务步骤、交付物和完成标准。角色、能力需求、工具、模型和知识库权限保持当前配置，界面说明这一范围。发布版本和运行快照继续记录各自既有的配置快照。

## 7. 验证方法

新增单元与行为测试已纳入 `pnpm test`；角色真实接口测试纳入 `pnpm test:e2e:parallel`。另外提供 `pnpm test:design-workspace`，使用正常员工登录、Chromium、临时真实 SQLite、本地模型和 MCP fixture 验证完整交互。

覆盖重点：

- 能力动作匹配、角色工具作用域、第三方搜索词约束；
- 依赖循环、最小阶段预算、禁止提前结束；
- 真实重启后的阶段恢复和成果交接；
- 写入审批前零执行、批准后执行一次、越角色和越账号拒绝；
- 旧客户端字段保留、明确移除、运行快照不随草稿改变；
- 创建、四模块编辑、AI 建议预览与保存、执行环境真实空态；
- 新增连接的显式能力映射、组织切换后关联修复、异步保存和切换隔离；
- 运行设置折叠、待办跨标签可见、验收草稿保留、人工补充后续跑。

## 8. 第二轮：可编辑的能力清单与一致的下一步

第二轮以 `211f24822d2814c0a251d24b0206c6b41ab87234` 为基线。复查发现三处实际阻力：能力卡不能直接修订需求和分配角色；切换设计模块会卸载编辑组件并丢失角色恢复状态；保存修改后的方案，向导虽然阻止继续发布，仍可能显示旧的“试跑成功”和“没有阻断项”。本轮集中修复这些链路，并补齐资源接入后返回草稿的说明。

### 能力从建议变为可维护的配置

能力卡现在可以编辑名称、用途、类别、操作范围与是否必需，也可以新增、删除及撤销最近一次删除。修改先应用到当前草稿，再由用户保存。删除能力不会撤销其他任务可能仍需使用的全局或角色工具权限；页面明确说明这一点。

显式能力数组是用户当前的配置，包括明确的空数组。只有完全没有该字段的历史方案才按任务和工具推断需求。用户删除最后一项后，刷新连接不会把它重新生成。草稿恢复和已保存 Agent 编辑都保留“未声明”和“明确清空”的区别。

每张能力卡可以直接选择负责角色。选择角色只调整职责关联；点击“选用并分配”才给选中的角色增加该工具，其他角色不扩大权限。已存在连接但缺少角色分配时显示“需要分配角色”；未通过连接测试时提供测试入口。已有候选与外部寻找插件不再混作同一个下一步。

### 编辑状态随工作模块保留

目标、角色、工具和完成标准统一为四个模块。角色与资源面板切换后保持挂载，隐藏面板同时退出焦点和无障碍导航。所选角色、单助手切换后的角色恢复快照、尚未应用的能力字段和删除撤销状态保留在当前编辑会话；切换到另一 Agent 或重新开始草稿时重置。

角色工具使用真实目录中的名称、来源与读写说明，具体标识放入展开详情。相同工具名称不会混用另一连接的身份或权限；无法核验的连接明确标注。空工具角色有直接前往“工具与资料”的入口，导航本身不授予工具权限。

### 接入页说明原草稿的位置

从设计页打开资源设置时，链接仅携带有界的设置标记、Agent 标识及能力标识。未保存方案也有清楚的“在原标签继续编辑”提示。已保存 Agent 的备用返回入口标为“打开已保存的 Agent”，并明确它不包含原标签的未保存修改。

在工具、插件、电脑与浏览器页面之间继续配置时保留这一上下文。回到已保存版本时可以定位原能力卡；定位限定在当前可见编辑器实例内，避免弹出编辑器与背后页面竞争焦点。

### 试跑卡、阻断说明与发布条件使用同一判断

webCodex Agent 实际参与实现本轮试跑状态修复。现在试跑卡标题、下一步动作、桌面与移动检查区共用 `trial` / `trialIssues`。状态明确区分未保存、尚未试跑、进行中、等待人工、失败、中止、旧版本成功、缺少可核验快照、时间无法核验、质量断言未通过，以及当前版本成功待人工验收。

完整方案快照不同，即使时间戳相同，也必须重新试跑。读取失败或尚在刷新时，缓存中的旧成功不能解锁发布。原运行有独立入口用于继续审批、补充信息或查看原因；重叠刷新和切换 Agent 的旧响应不能覆盖新记录。运行成功仍需人工核对结果、来源及完成标准。

独立复查还修复了两处状态问题：模型资源暂时不可用时，已经核验通过的真实输出不会被误报为质量断言失败；模型连接的旧响应、延迟 JSON 或卸载后响应不能覆盖最新状态。相应回归直接执行真实判断函数及从页面 AST 抽取的真实异步回调，没有复制被测逻辑。

本轮继续使用独立开发工作区。未改变后端执行、数据库迁移、生产配置或真实连接权限。

## 9. 复杂 Agent 自主验证与进化：第三轮

本轮新增/扩展的端到端验收场景是“发行人尽调与财务交付 Agent”，由网页研究、PDF 证据提取、表格分析、交叉审核和邮件交付五个顺序角色组成。输入、资料、模型响应、MCP 工具和写入端点均为隔离的本地 fixture，不访问真实发行人、不发送真实邮件。

### 真实验收链路

- 以正常员工身份登录，使用临时 PocketBase / SQLite，调用确定性本地模型生成和修订方案。
- 通过创建工作台调整能力需求、单助手/角色切换、角色权限、能力绑定、保存与重新打开，直接查询服务端记录核对持久化内容。
- 启动真实 Agent 运行 API；依次运行网页来源、PDF 页码、财务表格、审核与最终交付角色。
- 在每个有副作用的工具调用前验证 `awaiting_approval` 和当前角色；批准后检查真实 MCP 事件与 fixture 计数。邮件写入仅在最终角色审批后执行一次。
- 检查五个角色均有持久化阶段状态、后续角色接收到前序证据、审核角色没有写工具调用、最终报告包含来源 URL、PDF 页码、表格行号及计算值。
- 修改成功运行对应的方案后，检查旧快照不能继续作为当前版本的成功验证，并阻止未经重新试跑的发布。

### 本轮发现与处理

1. **浏览器验收脚本不具备跨平台依赖定位。**它默认写死 Linux 的 PocketBase、Chrome 和 Playwright 路径，在 Windows 环境中无法启动。已改为优先使用显式环境变量、项目级 Playwright、Windows PocketBase 与本机 Chrome/Edge/Playwright Chromium，并保留 Linux 测试路径。
2. **复杂验收共享工具计数器，错误地把前一场景的浏览器调用计入新任务。**改为保存复杂任务启动前的计数基线，并严格断言本次运行每项工具的增量恰为一次；没有降低工具调用的断言强度。
3. **复杂场景的本地模型 fixture 对最后一个角色返回了 `role_complete`，却没有返回最终交付动作，导致界面一直等待运行成果。**对照已通过的后端角色集成契约后，修正 fixture：最终交付角色在批准本地写入后返回 `final`；其他角色仍须通过 `role_complete` 交接。该修正针对测试模型行为，不放宽产品验收，也不把 fixture 错误归因于产品缺陷。
4. **健康状态提示区域在无阻断项时会隐藏。**测试改为允许该提示区域不存在，同时要求运行按钮真实可用、运行 API 成功启动；如果提示区域存在，则继续检查不能有未连接/未测试的阻断项。
5. **复杂角色审批中缺少语义上下文。**原审批卡只展示内部工具标识与参数，很难直观判断哪个角色发起、当前属于第几阶段及工具声明的读写性质。产品已改为显示可读工具名称、精确连接来源、阶段与下一角色、插件声明的访问类别；内部 ID 可展开核对。插件声明仍不是安全证明，继续逐次审批。
6. **五角色中途重启与实际设计界面查看存在覆盖缺口。**现在在 D2/D3 边界重启独立 PocketBase，核验已保存成果和工具不重放；Chrome 也逐一打开五个角色，核对审核角色没有外部工具权限、最终角色仅拥有对应邮件工具以及四项能力全部可见。
7. **五角色选择器匹配到了删除按钮。**这是 Chrome 脚本使用宽泛角色名匹配造成的定位歧义，已经改为精确匹配有阶段序号的角色按钮，不修改产品删除按钮语义。
8. **AI 修订失败时错误提示可能显示在弹窗背后的页面。**失败截图确认弹窗仍在，但修订输入区没有可见原因，用户会以为预览一直卡住。现在修订输入区在等待时显示状态，失败时在当前弹窗内显示可访问的错误提示及重试指引；原草稿不变。Chrome 注入格式错误的模型响应，验证无预览/无写入，并在同一弹窗中重试成功。
9. **快捷编辑器在挂载时发生真实运行时崩溃。**Chrome 错误日志捕获到 `Promise.resolve().then(... ) is not a function`，导致五角色 Agent 完成后快捷编辑器无法打开，后续选择器超时。根因是初始化 effect 在 `Promise.resolve().then(async()=>{...})` 末尾又多调用了一次 `()`，错误地把 Promise 当函数执行。已移除多余调用；修复后的完整 Chrome 流程能打开快捷编辑器、选择另一个 Agent、保存修改并完成发布前快照检查，未再出现浏览器异常。
10. **MCP POST 断线后结果不明，不能自动重复执行。**新增故障注入：以本地 MCP 服务模拟请求发出后 EOF，即使插件声明只读，无法保证服务端没有发生其他副作用。外部调用完成状态不确定时明确返回 `write_outcome_unknown`，停止自动重试，要求人工核查连接与目标系统；正常五角色运行仍通过。Chrome 验证一次运行只有一次发送，不把全局累计计数误判为重复调用。
11. **AI 修订的迟到响应可能污染另一个 Agent 的编辑状态。**在正式创建编辑器与跨页面快捷编辑器中，模型返回前使用方案上下文/加载序号校验。切换或关闭旧 Agent 时主动停止对应加载状态；旧成功或错误结果不再影响新 Agent 的预览、错误或修订按钮。真实源码异步回调的专项回归 23 项全部通过，覆盖旧成功与旧失败。
12. **Smithery 未授权时重复搜索造成多个 HTTP 400。**HTTP 路径诊断显示此前 8 次 400 全部是 `GET /api/market/smithery/v2/catalog`；服务端在无 Key 时按契约返回 `smithery_key_required`。修改前端为先按当前员工身份请求 `/api/market/smithery/status`；未授权则展示明确的连接与复验入口，不再发送目录查询；授权后的目录结果仍需验证和用户确认。新增 5 项回归，Chrome 18 组操作实测授权核验 4 次、无 Key 的目录请求 0 次、HTTP 400 和控制台错误均为 0。
