# 原 Agent 运行页：逐步确认与请求生命周期

本次仅适配现有员工运行页的控制器、费用说明和 API 传输，不改变页面布局。
使用既有 Native 审批合同；后台仍验证员工身份、owner、来源权限、资源版本和审批输入指纹。

模型、语义检索及外部工具的批准分为两次明确确认：先核对当前输入、发送范围和费用风险，再批准当前运行的当前步骤。接口没有金额报价，界面不显示估算金额或零费用承诺。免费本地计算、业务记录操作及关键词检索仍须确认实际操作；拒绝步骤不需要付费调用授权。语义检索只使用既有的单步计费确认标记，不产生持续授权。

运行、步骤、输入指纹、输入正文、固定配置、知识来源或员工身份变化后，旧确认不能继续提交。切换选择后即使返回同一对象也要重新确认。提交、取消、人员回复、反馈和记忆删除同样绑定确认时的对象；写入前重新读取对应来源。反馈草稿在等待确认前复制，调用方后续修改不能替换已确认内容。结果未知的审批只读取原结果，不发送相反决定或重放原 POST。

两个原运行详情传输器在完整读取响应 EOF 后释放 reader，不再中止已经完成的 HTTP 响应。无效 JSON 或 UTF-8 仍拒绝；未完成、超限、超时及关闭中的请求仍取消。关闭会立即拒绝不响应取消信号的发送，并丢弃迟到的响应正文。

验证为终端控制器／传输纯测试：审批、选择和身份恢复 79 项；传输生命周期及相关读取 41 项。前端实际类型检查和隔离构建另行执行。这些证据不代表真实员工页面、真实 PostgreSQL、外部服务或生产费用验收。
