# Agent Studio V13｜全模块用户体验审计：自动工具匹配与随时编辑方案

> 范围：独立运行的 `agent_studio_vibex版本`，非原始 RunningHub/VibeX 项目。审计口径是**真实员工如何完成任务**，不是只看 UI 是否美观。本文区分「已编码」「单元/接口验证」「Chrome 浏览器验证」「未验收」；不能把模拟供应商、移动视口或测试账号表述为正式生产运行。

## 一、审计标准和真实用户路径

用户的核心任务是：
`描述需求 → AI 生成可编辑 AgentSpec → 识别所需能力 → 已验证能力匹配 → 未连接能力发现/授权 → 保存版本 → 试跑 → 需要人工确认时暂停 → 继续 → 读结果和评估 → 提交反馈 → 对比改进 → 人工确认新版本 → 再试跑`。

执行标准：

1. **方案就是正式任务配置**：LLM 只产出建议，不伪造接入或运行；前端展示可执行 ID、实际链接和缺失权限。
2. **工具连接不等于全局授权**：已连接并已核验的工具由后端按当前员工、AgentSpec 工具白名单和执行时实时连接状态检查。外部调用按策略审批，OAuth/API Key 不自动绕过。
3. **编辑随处可达，但运行快照不可变**：创建向导和工作台编辑当前草稿；其它路由快捷打开当前账号已保存 Agent，且任何修改须执行服务器版本 CAS；保存后只对后续任务生效。
4. **工作不能被 UI 意外打断**：正在运行或等待人工确认时的新版本试跑单独打开；重复审批、并发修改、凭据撤销在服务端保护。
5. **可见即真实**：反馈、模型评分、连接状态、连接候选都显示实际来源/条件；不把「插件搜索结果」描述为已接入，不把规则评分描述为事实准确性。
6. **宽屏高效率、窄屏不阻断**：桌面保留工作空间和结果高权重；390px 手机可操作、无意外横向滚动；浮动编辑入口与主导航同时存在但不互相遮挡。

## 二、本次实际发现的 P0/P1 断点与落地

| 严重度 | 模块/用户动作 | 审计发现 | 代码落地 / 验证 |
|---|---|---|---|
| P0 | 创建 Agent 自动工具连接 | 模型的「网络搜索」「知识库检索」「文档解析」仅为通用汉字，执行引擎使用不同 ID；错误的「待连接」阻止试跑 | `agentToolMatcher.ts` 依实际需求和工具状态匹配内置 ID；真实只读并经验证的连接可映射；无法调用的能力保留真实缺口；测试覆盖拒绝联网、PDF、写权限 |
| P0 | 第三方账号工具发现 | 只显示「待连接」无可操作路径；已连接插件和方案工具表隔离 | `AgentToolAutoConnect.tsx` 查询当前有权访问的 Smithery 目录并显示已验证候选；新标签进入插件市场并保留原方案；返回按焦点刷新并重新匹配。第三方 OAuth 由用户自己批准 |
| P0 | Agent → MCP 调用 | 市场单独试调成功而 Agent 调用时凭据解密函数未定义 | `agent_engine.pb.js` 服务器解密凭据、运行时 owner/enable/probe/已选白名单校验；隔离 PocketBase + 模拟 MCP 端到端包含真实 HTTP 请求、工具审批、撤权拒绝、跨员工隔离 |
| P0 | 手动确认和方案质量 | 草案虽提出确认要求，系统没有可继续的交互状态 | `ask_user/awaiting_input/respond`、强制 review gate、退回重审、运行检查点恢复；隔离浏览器实际操作 |
| P0 | 保存编辑与运行快照 | 中途编辑必须切换页面；跨标签旧方案可能覆盖新版本或放弃正在执行任务 | 全局 `SavedAgentQuickEditor` + `AgentDraftDrawer`；工作台/创建向导保持同份草稿；其它工作空间按当前员工加载真实 Agent；PATCH + `expected_updated`；新版本不会篡改已启动 AgentRun |
| P1 | 运行结果到方案迭代 | 评分、反馈及差异稿分散在左/右独立面板，难连续操作 | `RunResultPanel` 依次展示成果→评估→反馈→方案 diff 与确认写回；按运行所属 Agent 保证目标正确；冲突旧建议不可直接应用 |
| P1 | 刷新、长结果、取消 | 等待确认时难找回复入口，Markdown 输出变为裸 `##` 文本 | URL 绑定具体 run，刷新恢复待确认；结果安全排版（标题/列表/表格/代码等）；审批事件进时间线 |
| P1 | 当前试跑与重新编辑 | 编辑后跳到新任务可能放弃正在运行的上个任务 | 在当前运行活跃时保留当前页面，提供新标签试跑新版本；执行检查点与用户审批仍可恢复 |
| P1 | 创建向导的移动阻断 | 创建检查侧栏在移动屏幕隐藏，员工不知道为什么「下一步」不可点击 | 390px 下提供相同步骤的紧凑阻断说明，不只留下禁用按钮；自动工具缺口与插件连接操作在编辑区就地显示 |
| P1 | 浮动编辑入口性能 | 方案编辑器体积大，若所有路由同步导入可能增大首屏 | 编辑窗按需动态加载，只有点击时请求组件，不扩大其它路由首屏包 |
| P0 | 对外插件目录隐私 | 原方案工具名有可能包含公司内部项目/个人名称，直接填进第三方 Smithery 查询将泄露内部文本 | `toolSearchPrivacy.ts` 只发送经过白名单归一化的通用类别（如 `pdf`、`github`、`spreadsheet`），未知词不自动发送，员工可手动选择；支持目录中人工选定的严格 slug |

## 四、测试证据及严守边界

- `tests/agent-tool-matcher.test.mjs`：内置工具别名、否定性需求、可验证 PDF 插件、写入权限不自动授权。
- `tests/market-tool-selection.test.mjs`：禁用/失效/未知工具不展示为可调用。
- `tests/tool-search-privacy.test.mjs`：内部项目文本或疑似令牌不会被作为目录搜索词向外发送；通用关键词允许自动查询。
- `tests/smithery-connect.integration.mjs`：真实隔离 PocketBase + 模拟 Smithery 的工具发现、员工权限、人工审批、撤权后禁止调用；只在服务器使用解密凭据。
- `tests/agent-human-input.integration.mjs`：方案批准/退回/重审、检查点保存、同时批准只接受一条。
- `tests/agent-review.chrome.mjs`：真实 Chrome 员工登录、Agent 保存/人工审批/评分反馈/优化；全局快捷编辑；创建向导自动工具；移动主要路由巡检。
- `pnpm build`：**PASS**（最终 UI/隐私修复后重新执行，TypeScript、Vite 构建、PG pilot 产物隔离 96 资源检查均通过）。
- `pnpm test:e2e:parallel`：**20/20 PASS**（两并行 worker、隔离 PocketBase/SQLite，包含 Smithery 和长任务 Worker）。
- `tests/agent-review.chrome.mjs`：**1/1 PASS**（隐私修复、紧凑快捷编辑窗口后最后重跑）；390px 的 19 个主要业务路由均加载、无横向溢出；快捷编辑窗宽约 369px，保存/试跑入口可见。额外验证人工确认、反馈优化、工具匹配及旧运行快照不变。
- 自动工具、授权及隐私定向测试：`node --experimental-strip-types --test tests/tool-search-privacy.test.mjs tests/agent-tool-matcher.test.mjs tests/market-tool-selection.test.mjs tests/agent-human-loop-ux.test.mjs` **20/20 PASS**。最终还通过了 targeted `git diff --check`（仅有 Windows LF/CRLF 转换提示）。
- `pnpm check` **尚不通过**：独立 PG staging 的 `tests/postgres-staging.test.mjs` 仍要求旧版 `user!=="agentstudio_stage_login"` 检查，当前并行迁移入口已使用另一套 runtime target/role 机制；属 PG 迁移侧测试契约问题，未纳入本轮 UI 工作修改，不能报称全套单元测试通过。

**明确未做**：自动代表员工创建第三方账号、越过 OAuth、安全验证或写入审批；用户设备之外真正 iOS/Android 手势和软键盘验收；真实付费大模型/供应商结算和真实第三方 OAuth；全面“所有按钮”逐项业务 UAT；PostgreSQL 正式迁移切换；生产推送/部署。

当前源码工作树还包含大量未提交的 PG 迁移及其它平行改动。未经交付审批与隔离，不提交、不重置、不推送、不部署。
