# Agent Studio Vibex｜复杂 Agent 实测与可重复验收

**日期：**2026-10-22  
**目标项目：**独立 Agent Studio（不是原始 VibeX 运行应用）  
**工作分支：**`feat/harness-design-workspace-20261021`  
**测试类型：**真实 React/Chromium 页面 + 员工测试登录 + 临时 PocketBase/SQLite + 本地确定性模型 fixture；另含真实隔离 Chromium、PDF.js、ExcelJS 及本机 MCP 执行器。
**重要边界：**原有 UX 旅程使用确定性工具 fixture；第四轮新增真实本地浏览器/PDF/XLSX 执行器并通过真实 Agent Engine 调用。全部只访问临时本机测试资产，不是真实公司尽调，不连接真实发行人、Office 桌面应用或邮箱，也不向真实收件人发送内容。

## 1. 复杂任务定义

**Agent：发行人尽调与可审计交付。**

业务目标：从获授权的网页、PDF 附注与财务表格汇总事实，对数字进行交叉核验，保留可追溯证据，先审阅，最后经人工批准才提交交付操作。

输入包括授权的资料范围、报告要求和限制条件；交付包括来源索引、PDF 页码、表格行号与计算、风险清单、审阅意见和交付回执。验证过程中不能把模型生成的断言当作真实事实；必须核对 fixture 与运行事件。

### 隔离数据及期望值

| 资料 / 连接 | 测试返回 | 期望证据 |
| --- | --- | --- |
| 网页读取服务 | revenue 120、风险 R1、URL `https://fixture.invalid/issuer` | 来源 URL 与数字 |
| PDF 读取服务 | 附注 7、负债 30、页码 4、`fixture-report.pdf` | PDF 页码与附注 |
| 电子表格服务 | 第 2、4 行；120 − 30 = 90 | 行号、计算过程和结果 |
| 本地模拟邮件服务 | `LOCAL_EMAIL_FIXTURE` 回执 | 批准后执行一次；**无真实邮件** |

这里的 PDF 与表格工具通过本地 MCP/HTTP 模拟预设内容，不证明已经具备读取任意真实 PDF/XLSX 文件的兼容性。

## 2. 多角色职责与执行交接

| 阶段 | 角色 | 任务及允许工具 | 交付和验收要点 |
| --- | --- | --- | --- |
| D1 | 资料研究 | 网页读取，不能执行邮件操作 | 来源、收入、风险；附来源 URL |
| D2 | 文档分析 | PDF 文本与附注提取 | PDF 第 4 页及附注 7，接收 D1 证据 |
| D3 | 财务分析 | 表格计算与内置计算器 | 120 − 30 = 90，引用第 2、4 行 |
| D4 | 交叉审核 | 无外部写入权限 | 检查 D1–D3 的来源和数字，明确未核实部分 |
| D5 | 审批交付 | 仅本地邮件交付工具，必须经批准 | 结构化结论、来源索引、测试回执 |

当前多角色执行机制是**同一 Agent 运行中的顺序角色阶段**，不代表并行调度了五个独立 Agent。前序阶段通过 `role_complete` 保存成果，末阶段通过 `final` 提交运行结果；两个动作不能互换。

## 3. 能力需求及 Harness 验收

在完整任务中，用户应当能先表达目标，再判断所需能力，不必先熟记插件 ID。

| 能力需求 | 分配角色 | 目录匹配与授权约束 |
| --- | --- | --- |
| 浏览器页面读取 | D1 | 必须绑定真实存在的精确工具标识，网页正文抓取不能冒充已登录浏览器操作 |
| PDF 证据提取 | D2 | PDF 专用能力不得冒充 XLSX 导出 |
| 表格复核 | D3 | 明确表格类工具和实际读取/计算范围 |
| 审批后交付 | D5 | 读取邮箱不能替代发送；缺测试/授权不能标记为已就绪 |

验收时，首先从正常员工登录的 Web 创建与编辑界面检查角色分工、工具作用域和能力清单；复杂任务数据通过同一员工可访问的真实 API 创建保存后，再在实际页面检查全部五角色和四项能力。现有 Chrome 测试没有假称“全部五角色字段均由人工手动输入”。

## 4. 必须经过的真实运行检查

- **版本与权限：**保存的 Agent 记录必须包含全部五角色、能力需求、精确工具 ID 和权限作用域；运行使用冻结的方案快照。
- **角色交接：**阶段按 D1 → D2 → D3 → D4 → D5 进行；后续角色可读到前序证据；运行数据库包含有序的五段已提交成果。
- **工具执行：**本次复杂任务中的网页、PDF、表格、本地邮件各恰好执行一次；用启动前基线计算单次运行增量，不能用整场测试全局累计数。
- **审批：**外部 MCP 调用逐次等待确认；批准前邮件调用数保持 0；审批之后严格为 1；审核角色不存在未经授权的写入工具调用。
- **异常恢复：**在 D2 已交付、D3 待开始时重启真实的临时 PocketBase，要求检查点、阶段输出和下一角色一致，已成功的网页/PDF 工具不应重放。
- **成果核验：**最终结果包含 `revenue 120`、`PDF p.4`、`metric 90`，不出现 `UNVERIFIED_CLAIM`。
- **UI 可理解性：**审批卡应展示当次负责角色、第几阶段、工具可读名称、连接来源与插件声明的读写性质。插件元数据不等于真实行为的安全证明。
- **版本失效：**旧成功运行不能证明修改后的 Agent 方案有效；保存新版本后应要求重新试跑，且不应改变已完成运行的历史结果。

## 5. 已发现的问题及处理结论

| 编号 | 发现 | 类型 | 修复 / 处理 |
| --- | --- | --- | --- |
| QA-01 | 浏览器验收默认路径写死 Linux，Windows 无法启动 | 测试基础设施 | 改为环境变量、项目级 Playwright 和本机执行器可选路径 |
| QA-02 | 同一个网页工具在早先场景被调用一次，复杂任务累计调用被错误判为重复调用 | 测试隔离 | 每个复杂运行记录前置计数基线，核验增量恰好为 1 |
| QA-03 | 本地模型 fixture 末角色返回 `role_complete` 而非 `final`，导致结果未完成 | 测试模型契约 | 末角色修正为 `final`；不修改真实引擎完成条件 |
| QA-04 | 无阻断项时健康提示区域隐藏，脚本却要求“可以开始新任务”必须可见 | UI 自动化断言 | 验证真实运行按钮和后端启动成功；不强迫无障碍空态显示 |
| UX-01 | 连续角色审批中只看到内部工具 ID 和参数，无法迅速判断角色与调用权限 | **产品可用性问题** | 审批卡增加阶段归属、下一角色、可读名称、连接来源和工具声明读写类型；保留具体标识与逐次审批 |
| QA-05 | 五角色任务在长链路中断后能否准确恢复缺少直接回归 | 覆盖缺口 | 加入 D2/D3 中途真实数据库服务重启与前序工具不重放测试 |
| QA-06 | 复杂 Agent 保存后缺少逐角色的 Web 方案检查 | 覆盖缺口 | Chrome 增加逐一打开五个角色、查看审核角色空授权和邮件角色专属授权、检查四项能力及无副作用 |
| UX-02 | AI 修订模型失败时，错误出现在编辑弹窗背后的页面，用户不知道为什么没有预览 | **产品可用性问题** | 修订操作区内联展示等待状态、错误详情与重试说明；故障注入无预览和无写入，同一窗口重试成功 |
| UX-03 | 快捷编辑器在特定初始化路径中把 Promise 误当函数再次调用，引发浏览器运行时错误 | **产品缺陷** | 修复初始化 effect；Chrome 验证可打开快捷编辑器、切换 Agent、编辑与保存，无未处理异常 |
| SAFETY-01 | MCP JSON-RPC 的 POST 请求若发送后断线，连接是否已执行外部副作用无法确定 | **运行安全性** | 禁止结果不明的调用自动重放，运行记录明确提示核对连接与目标系统；模拟 EOF 后仅发送一次，人工核查后再决定后续操作 |
| QA-07 | 故障注入会影响全局 MCP 调用计数，容易误判五角色任务重复调用 | 测试隔离 | 故障注入与正常运行分别保存调用基线；正常复杂运行四项工具的增量均恰好为 1 |
| UX-04 | 用户在 Agent A 启动 AI 修订后切换到 Agent B，A 的迟到响应可能覆盖 B 的错误提示或取消 B 的加载状态 | **跨 Agent 竞态缺陷** | 在正式编辑器与快捷编辑器中增加运行上下文/加载序列检查；切换时立即重置旧加载态，迟到响应不改写新 Agent；新增正常/失败两种异步竞态回归 |
| UX-05 | 未配置 Smithery Key 时，能力规划页对多个关键词直接请求插件目录，持续产生 HTTP 400，无法区分授权缺失与目录故障 | **市场接入 UX 缺陷** | 先调用同账号 `/api/market/smithery/status` 核查 `has_key`；无 Key 时不请求目录，提示连接和重新检查；授权后仅以通用能力词查询，结果不自动授予权限。旧响应不展示到新能力查询。 |
| QA-08 | Chrome 原有 8 条 HTTP 400 未明确归因 | **监测覆盖缺口** | 逐条记录路径确认为 `GET /api/market/smithery/v2/catalog`；新增状态预检、无 Key 时目录零请求的 5 项专项回归及 Chrome 网络断言。 |

QA 类问题是验证设施或测试契约问题，不能包装成产品功能缺陷。UX-01 至 UX-05 是实际产品体验或运行时缺陷；SAFETY-01 则按保守的外部副作用策略处理。所有行为变更须同时通过回归、构建与实际浏览器操作，不得为了让测试通过而关闭审批或放松安全约束。

## 第四轮：真实本地工具执行与精确权限边界

本轮新增独立的本机 MCP 执行器 ops/local-executor.mjs，与之前的 fixture UX 测试分开。它直接启动真实的隔离 Chromium，使用 PDF.js 解析真实 PDF 字节，使用 ExcelJS 读取/生成真实 XLSX；Agent Studio 的临时 PocketBase 员工账号通过正式 /api/market/connect 保存连接，再由 Agent Engine 发起调用。

真实执行器工具及授权规则：

- browser_read_page：独立 Chromium context，只允许已登记 origin 和精确路径，且每个任务限制在启动时的单一 origin；GET/HEAD 以外的请求、WebSocket、下载和新窗口被拦截。
- browser_registered_action：只由操作员提前登记动作 ID、起始页面、固定 CSS 选择器、输入字段键及允许写入路径；默认不暴露，Agent 不能指定网址、选择器或脚本。明确启用后，必须通过员工角色授权与逐次审批。只允许注册点击窗口内、来自当前主页面的 HTML 表单导航 POST；网页脚本在加载/点击时试图用 fetch/XHR 向同路径 POST，仍须被拒绝。
- document_pdf_extract：读取显式沙箱内的 PDF，返回逐页文本、页码和文件 SHA-256；限制文件大小与页数。
- spreadsheet_analyze：读取显式沙箱内的 XLSX 数值单元格并执行独立数值运算；不把公式缓存值误报为已重新计算的公式结果。
- spreadsheet_export_report：默认不出现在工具列表。单独开启后才允许生成新 XLSX，路径固定在 artifacts/，使用原子新建方式且拒绝覆盖同名文件。

安全与边界测试覆盖了：无授权令牌、越界文件路径、符号链接逃逸、外部/未登记网页来源、另一个已登记 origin 的子资源、恶意 POST、WebSocket、外部重定向、未知动作 ID、额外参数、未批准表单提交、导出覆盖，以及敏感令牌不得出现在 API 响应或审计中。

真实五角色链：网页研究 → PDF 证据 → Excel 数值核对 → 无写工具的独立审核 → 审批后 Excel 导出。另以独立员工权限和第二个 Agent 运行验证预登记表单动作：审批前提交计数为 0，匿名审批返回 401，员工批准后恰好提交一次。测试文件、网页、模型和数据库都在本机临时环境；不使用用户日常浏览器登录态，不连接真实发行人或外部业务系统。

复验命令：

    pnpm test:local-executor
    pnpm check
    pnpm test:e2e:parallel

该执行器是 opt-in 的本地 UAT 能力，不是通用远程桌面，也不意味着任意真实网站、扫描 PDF OCR、Office 原生 UI、动态公式重算、跨机器身份管理或生产审计已经通过验收。启用前必须遵循 docs/LOCAL_EXECUTOR_PILOT_20261022.md，配置每个 origin 的精确 path 白名单，并使用独立随机令牌。

- **运行故障注入：**整场浏览器验收中 `browser_page_inspect` 共记录 3 次：独立审批场景一次、故障注入模拟发送但连接 EOF 一次、正常复杂任务一次。这是不同运行的合计，**不是任何一次任务被重试三次**。模拟失败后的外部结果视为未知，执行引擎停止，不重放。
- **后续范围：**本轮环境只测试本地确定性 fixture，真实外部插件重试幂等、长时间 Worker、Office 文件读写与 PostgreSQL 迁移仍需另外验收。
- **已结案的网络控制台观察：**原有 8 次 HTTP 400 均为缺少账号 Smithery API Key 时自动调用插件目录导致，属于市场发现链路的授权预检缺失；修复后同一 Chrome 任务记录 `smitheryStatusChecks=4`、`smitheryCatalogRequests=0`、`http400Responses=[]`、`consoleErrors=[]`。新增 5 项测试覆盖无 Key、正常 Key、非法状态、授权撤销和网络故障。未授权场景不会把“无插件结果”谎称为“已连接”或自动扩大角色工具权限。

以上结论仅针对当前开发分支、测试输入和确定性 fixture；在最终合并或升级真实执行器之前仍应再次运行相同验收。

## 7. 尚未由这次测试证明的能力

以下验收仍应单独使用真实授权账号和受控沙箱完成：

1. 真正的浏览器执行器完成网站打开、登录态管理、填写表单、下载/上传文件。
2. Office、PDF、XLSX 的真实文件输入输出质量、编码、格式保持与多文件并发。
3. 真实模型面对含糊指令、冲突证据和无答案资料的准确性与幻觉抑制。
4. 实际第三方插件限流、连接失效、授权撤销、网络超时与重试幂等性。
5. 高并发、持续数小时的 Worker 执行及真实 PostgreSQL 迁移后的恢复和数据一致性。
6. 独立多 Agent 并行、角色专属模型和自由协商（当前产品尚不具备）。

**上线口径：**仅证明当前隔离开发分支的可重复测试链路，不能据此宣布生产环境或真实外部工具已经验收通过。未经用户明确要求，不合并主分支、不推送或发布，也不更改生产数据库。
