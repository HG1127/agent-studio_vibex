# Harness V2 P0 · 共享 Step 执行契约与审批一致性

基于尚未合并的 PR #8（`8b4de7e`）独立增量实现，依次依赖 PR #6、#7、#8。
**此分支不直接合并生产 main、不改变 SQLite 表结构、不更新正在使用的 Ubuntu 内网服务器，也不触碰独立 PostgreSQL 迁移工程。**

## 代码交付范围

- `pocketbase/pb_hooks/modules/harness_step_executor.js`：纯 Goja、无网络副作用的共享 Step 接口：
  - `prepareModelStep`：在开始新的模型请求前复核任务绝对时限。
  - `prepareToolStep`：统一校验工具参数的类型、深度、大小、危险键名，以及任务总时限；结合现有 `tool_policy.js` 判断读取/写入、强制审批与重试资格。
  - `executeWithRetry`：读取类工具发生明确可重试错误时最多追加 **1 次** 调用；外部写操作和缓存命中不自动重试。实际工具执行仍使用已有鉴权、网络隔离与写入意图日志。
  - `approvalDigest` / `approvalMatches`：把批准结果绑定到工具名、HTTP 方法、连接 ID、目标 URL/凭据模板的指纹及经过校验的参数；仅将 SHA-256 摘要保存到运行检查点，不存储明文凭据。
- **Agent 执行引擎**：模型准入、工具预检与重试统一；外部写操作获批后再核对审批指纹，工具目标或参数变化时自动重新进入 `awaiting_approval`，不沿用原批准标记。
- **Workflow 执行引擎**：工具审批从“仅绑定节点 ID”升级为“绑定本次有效操作指纹”。前端批准后如节点渲染参数或目标连接变化，下一次 Tick 重新请求确认；外部执行使用风险分类时已核对的连接记录快照，避免 GET→POST 竞态导致未记账写入。已批准操作在分派前再次验证实际目标。内嵌 Agent 的工具调用也走共同预检。
- **员工界面**：Agent、Workflow 审批卡标明授权仅适用于本次操作，参数/目标更改会重新请求审批；Harness 面板明确区分安全读重试与不可自动重放的写操作。

## 回归与安全验收

1. 共享 Step 单测验证模型/工具准入、JSON 类型与参数大小、危险输入、审批指纹的参数/方法/目标绑定、只读重试一次、写操作禁止自动重试、已完成写操作走结果缓存。
2. 真实 PocketBase Agent E2E：先审批、后更换已绑定 HTTP 工具 URL，原审批自动失效，外部服务未收到 POST；重新审批后只写入一次。
3. 真实 PocketBase Workflow E2E：审批后模拟运行快照参数发生变化，原节点批准无效且要求再次确认；无额外写入。只读 GET 连接不触发写审批。
4. 原有并发/崩溃接管、执行中取消、幂等日志、模型预算、知识库 ACL/语义检索等完整回归应继续通过。
5. `pnpm check`、19 项独立 PocketBase E2E、改动 React 文件 ESLint 和两轮 GitHub CI 通过后，才能进入审核。

## 明确不包含

- 尚未将两个大型执行引擎的真实模型 Provider 适配、各内置工具函数、Workflow DAG 控制流或 Agent Planning Loop 合并为一套完整 Runner；本轮共享的是**模型/工具 Step 准入、风险政策、重试及审批一致性契约**。
- 模型真实 Token/美元预算、外部工具沙箱、DNS 解析/跳转安全代理、连续租约心跳、任意时点回放及第三方写入的全局 exactly-once 仍属后续 P0/P1。
- 运行中更改外部服务自身的处理语义、第三方服务不遵守 HTTP 幂等规则，无法仅靠本地工具指纹彻底消除副作用。审批所见参数摘要也不是第三方动作的完整合同。
- 旧的节点 ID 批准标记如缺少新审批指纹，将安全地要求重新确认，不会直接被信任；首次正式发布必须先做人工审批迁移/UAT。
