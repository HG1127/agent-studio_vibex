# Agent Studio V27｜复杂 Agent 多场景创建基准与安全验收

日期：2026-10-23  
开发分支：`feat/harness-design-workspace-20261021`  
范围：V27 多角色 Agent 创建能力扩展验证；仅隔离测试，不提交、推送或部署。

## 1. 目的与验收逻辑

用户希望证明平台能**面对不同复杂度与业务场景**，从自然语言需求构建可编辑、可保存、可授权、可执行并能提供真实证据的 Agent；不能把一次精心配置的五角色演示误认为对所有复杂任务都有效。

把评估分成四项：**模型规划完整性**、**能力匹配与最小权限**、**工具执行与角色持久化**、**交付与发布证据**。每项必须标记“本地隔离环境已通过 / 真实模型未测 / 真实第三方未测”，避免模糊的“系统已经可用”。

## 2. 多场景基准矩阵

| 场景 | 角色 | 必需能力 | 写操作 | 具体要求 |
|---|---:|---:|---|---|
| 企业政策合规审阅 | 2 | 2 | 无 | PDF 提取、知识库对照、带页码冲突清单 |
| 客服工单处理 | 3 | 3 | CRM 更新 | 收集→分类→经人工审核后记录处理结果 |
| 企业多来源投研 | 5 | 4 | 本地邮件模拟交付 | Chromium、PDF、XLSX、独立审计、人工审批 |
| 软件发布前审核 | 8 | 4 | 版本登记 | 需求、依赖、代码、测试、安全、QA、复核、批准后发布 |

创建能力采用 deterministic planning fixture 来触发**实际 Chrome 页面中的生产生成/解析器、工具发现、保存与数据库读取链路**。各场景故意使模型生成 `roles[].tools` 带有未经授权的读取/发送工具别名：用户未明确分配之前，这些声明必须被清空。写操作必须默认进入人工审批流程。

## 3. 已落地的产品纠偏

- `prepareGeneratedAgentPermissions`：模型生成的角色权限全部视为未授权建议；可用且只读的目录级工具可作为全局初始候选，但无法未经人工确认直接授予某个角色。结构化写操作必须启用运行中审批。
- `generatedAgentToolSelections`：只有匹配到当前员工真正可用的工具才进入结构化 Agent 初始可执行工具清单；未连接的 PDF、CRM、发布工具保留为缺口，不伪装成可执行。
- 角色依赖检查：验证阶段数量、顺序、合法 DAG，发现循环/缺失依赖时不能认定配置就绪。
- `evaluateComplexAgentAcceptance`：实测角色事件、检查点、必需工具调用结果和同一步审批，杜绝“仅凭最终回答”认定完成。
- 服务端版本审核 `harness_complex_release.js`：客户端不能自报 `test_passed` 绕过正式多角色验收。

## 5. 未解决且必须单独衡量的“真实 AI 智能”指标

**本矩阵的规划模型是确定性测试 fixture，不构成真实大模型面对陌生任务的泛化能力证明。**

生产决策前，应额外用**已明确授权**的真实模型，对至少 10 个此前没有出现在 system prompt 或 fixture 中的新任务做盲测，并至少重复 3 次；每次评估：

1. 不需人工修改结构化 JSON 的首次有效生成率；
2. 正确拆分的角色与依赖比例（人工盲评）；
3. 必需工具需求召回与过度索权率；
4. 已连接与缺失工具识别准确率；
5. 实际执行成功率、真实业务交付物和证据可验证率；
6. 完整审批及权限边界合规率；
7. 总模型/工具成本、时延、失败恢复成本。

不使用真实客户机密或向外部收件人发信进行盲测。未通过外部模型及真实第三方授权测试前，本项目仍处于**内部开发验证**而非生产交付保证。
