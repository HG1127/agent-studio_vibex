# 工作台连接体验优化与验收

日期：2026-10-29。范围：Agent Studio 当前独立工作树的电脑工作区、状态展示、授权草稿保护与下载指引。本轮不更新本机连接器二进制，不重配设备、不增加文件或网站授权、不部署生产。

## 本轮解决的问题

1. **下载版本不等于运行版本。** 本轮开始时，工作台下载包为 `0.1.0-preview.14`，`zhouqing #9xvoJI` 的实际权限通道仍上报 `0.1.0-preview.12`。此前这两条信息分散，用户容易以为刷新网页或下载 ZIP 就完成更新。
2. **设备清单收起时异常提示不可见。** 现在选中的电脑仍保留在界面内，状态获取失败会在清单之外明确显示“状态未核实”，不会把缓存中的在线状态当作新证据。
3. **同名电脑难区分。** 设备搜索支持名称、完整标识或 `#` 尾号；同名记录有区分提示。选择只作用于当前账号返回的设备清单，不执行任务或自动启动连接器。
4. **授权草稿和未结算请求需要保护。** 授权管理的草稿、文件选择和待确认请求参与统一忙碌状态；在保存、明确放弃或核实结果之前，禁止切换设备或工作区，防止误操作丢失上下文。

## 新的页面使用链路

入口：`http://127.0.0.1:8180/tool-hub?view=devices`，仅工作台所在电脑。

选择电脑后，顶部显示“连接与授权状态”“当前运行版本/最近上报版本”“本站可下载版本”。点击“核实版本与连接”只重新读取设备、权限和发布清单，不执行本机任务，不创建新的配对或授权请求。

发现版本较旧时，可展开“查看安全升级步骤”：先结束任务和待确认授权，再退出旧执行器，从新解压目录启动程序，并按名称、工作台地址与原授权范围恢复已有连接。回到本页核对标识及新版本心跳。管理网页关闭不等于执行器退出。运行版本高于本站发布版时，不建议降级，也不提供降级下载入口。

日常操作仍使用“文件工作区 / 浏览器 / 授权管理 / 办公与 Agent”四个标签。升级说明默认收起，不新增一套外部管理界面。

## 真实性与安全边界

- 运行版本来自当前账号、当前设备的已验证权限通道。失联、过期、未来时间戳、读取失败或设备切换后，历史版本只能显示为“最近上报版本（当前未核实）”。
- 发布版本通过同源固定路径清单校验，并检查 ZIP 的 HEAD、大小与非 HTML 类型。页面展示不等于下载了全部字节或完成数字签名验证。
- 对 `preview.9` 与 `preview.14` 按数字比较，不使用字符串排序；无法比较的版本视为未知。
- 连接/授权正常与版本新旧是不同事实；下载故障不伪造更新成功，版本提示也不会自动扩大操作权限。
- 切换账号和设备会隔离状态；上一台设备的迟到响应不能覆盖新设备。外部账号设备 ID 不能通过 URL 变成可操作设备。
- 本轮没有重新安装连接器、停止用户执行器、删除旧版本、读取真实凭据正文或改变既有授权。原12个连接配置/凭据文件的大小、修改时间与文件标识在预览重启前后保持一致；preview.14的public和dist下载ZIP摘要均与原交付完全相同。原生授权确认与 preview.14 的相关修复保持不变。

## 验收中发现并修复的两个底层体验问题

- **短暂误报离线**：组件自身的计时值可能早于刚收到的设备心跳。现在使用客户端收到设备清单、权限摘要的本地时间同步显示时钟，不采信设备提供的未来时间。连续主动刷新已加入回归用例，原45秒过期和未来时间戳拒绝规则仍保留。
- **源码更新但页面仍旧**：原保留预览全局忽略 `**/.worktrees/**`，而项目本身就在 `.worktrees` 下。已改为只忽略项目内部的嵌套工作树，并保留 `.tmp`、依赖、构建输出等高频临时目录的忽略规则。真实预览集成测试证明同一模块 URL 不加缓存参数、无需重启即可读到更新；重启后原账号、JWT、设备身份、设备凭据及设置保持一致。

已在确认没有活动设备任务和待应用授权请求后，只停止并重启本项目的保留预览；沿用原数据库。旧预览锁在系统确认其进程不存在后才移除，未重置设置或初始化新数据库。重启后 HTTP 服务返回新工作区代码及时间同步修复，后端健康接口为200。实际用户账号的自动登录浏览器复验未执行完毕；本轮可声明的浏览器 UI 验收是隔离账号/数据库环境，不将模块 HTTP 检查等同于实际账号全流程验收。
