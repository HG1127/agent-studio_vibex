# Harness 运行与治理中心 · 第一阶段

入口：运行中心 → Harness 运行与治理（`/harness`）。使用现有 SiteShell、二级标签、移动导航和命令搜索；员工和管理员均只看到本人统计。页面仅发送 GET，不驱动引擎、审批、恢复或重试任务。

## 数据口径

| 数据源 | 范围与限制 |
| --- | --- |
| `/api/worker/status` | 共享 Worker 心跳（180 秒在线阈值）；本人队列按每类最近更新 100 条运行取样，显示截断标识；有效租约、人工核查、定时计划计数另查本人范围。就绪数为估算。 |
| `/api/harness/monitor` | 本人最近创建 100 Agent + 100 Workflow，最近 500 工具调用聚合，工具仅展示前 12 名；不是近 7 日全量。平均耗时为创建至更新时间，含未终止任务；Token 是累计提示/输出字符数除以 4 的估算，不代表账单费用。 |
| `/api/tool-hub/stats` | 本人全量累计运行和工具计数，独立于 monitor 的采样窗口。 |
| `/api/agent-runs/recent?limit=20` | 本人最近创建最多 20 条 Agent，保留来源线索，可直达 `/run-detail?run=...`。 |
| `/api/workflow-runs/recent?limit=20` | 已核实无 workflow_id 时支持本人所有工作流最近 20 条；编排页暂无指定运行深链，所以仅提供明确标注的编排入口。 |

页面各来源独立记录成功时间、加载和错误，失败保留且标记旧快照；首次失败不显示 0。字段不完整视为失败。刷新会重新并发请求全部五个来源，有 20 秒总超时；请求中禁用刷新；卸载取消，无自动刷新或后台轮询。401 / 412 清空本页全部快照、取消并停止请求，提供员工登录入口；网络故障不清除凭据。快照仅存组件内存。

## 身份边界与后端变更

`vibexAuthHeaders` 仅发送 PocketBase Authorization。`studio_auth.pb.js` 全局中间件清除外部身份别名，通过 `currentUser` 验证 active studio_users，再注入旧路由兼容身份。所有上述查询保持 rh_user_id owner scope，无新增端点、字段、迁移或生产动作。

修正已有接口的静默失败：stats 不再降级到最多 500 条或 0；monitor/Agent recent 查询异常不再变成空列表；worker 心跳、队列和治理 SQL 查询异常返回 500。不存在心跳记录仍可正常表示尚无心跳。这些变化使后端故障可见，旧调用方也会收到失败状态。

## 有意保留的缺口

- recent 无结构化 failure_diagnostic，且不能证明 7 日覆盖，因此不按错误文本猜测失败类别。
- 人工核查目前仅有计数和只读提示，不提供自动恢复；应先核实外部副作用结果，避免重复执行。
- Worker 心跳为共享基础设施信息，不表示本人任务一定正在推进。
- 无费用图表、伪造趋势、生产监控推断；员工 UAT 与生产部署仍为 NO-GO。

## 验证

`tests/harness-governance.test.mjs` 覆盖字段适配、真假零值、旧快照、401/412 分类、筛选和深链、全量大于 500 的计数、owner scope、采样限制及数据库异常传播。加入 `pnpm test` / `pnpm check`。完整隔离集成验证使用 `pnpm test:e2e:parallel`；不连接生产 LAN、不迁移真实数据。
