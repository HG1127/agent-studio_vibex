范围：独立 Agent Studio `harness-design-20261021` 工作树，`fix/native-dialogs-unified-20261026` 分支。保留既有改动；不重启预览、不部署、不修改生产数据。

## 目标与交互

默认展示计划列表，移除常驻长表单及底部长历史。计划搜索、启用/暂停/单次结束筛选、Agent/工作流类型筛选和列表页码保留在 URL 中。每个账号现有服务端上限为 100 个计划，列表在这份有上限的完整集合内分页（每页 10 条），不冒充服务器端计划列表分页。

新建、编辑使用 900px 以内的响应式对话框：任务内容 → 时间规则 → 模型和启用状态。操作页脚固定可见。支持放弃未保存内容前确认、错误保留输入、资源加载失败后的刷新。只在打开编辑器时读取模型和执行对象；列表不读取不可见历史或编辑目录。

复制从原计划带入任务内容、执行对象、模型和频率，时间由用户确认，默认暂停，绝不继承原计划的启用状态。

执行历史为单独视图，直接从计划进入。查询条件和页码保留在 URL；返回列表保留原搜索与筛选。每页 20 条在服务器按本人及所选计划查询，有独立 COUNT 和稳定排序，覆盖原先“只在最近 60 条里过滤”的遗漏。已删除计划的历史保留。慢请求不能覆盖另一计划的历史，网络错误不能显示成零条记录。

## 修正的后端行为

- 原先更新计划强制 `enabled=1`，现在保留原启停状态。修改暂停计划不会悄悄重新启用。
- 新建接口支持显式 `enabled=false`；页面默认保存暂停，明确勾选并确认才能启用。旧客户端不传 enabled 的行为保持兼容。
- 新 UI 提交 `expected_revision`，服务端拒绝过期版本。删除也使用 revision CAS，不覆盖其他页面修改。
- 未修改时间规则时使用 `preserve_timing=true` 和 expected_revision；服务器复用既有频率和时间，在 SQL 中保留当前 start/next 时间列，避免覆盖 Worker 同时推进的下一次执行。
- 立即运行及启用有费用与执行影响确认。暂停/删除提示不取消已开始的运行；自动去重、重试条件、工具审批、账号隔离和 Worker 内部鉴权保留。
