# PostgreSQL 原生完整配置版本与发布

该能力用于独立 PostgreSQL 候选应用。PocketBase 仍是当前运行环境；代码和隔离 CI 的通过不等于正式切换授权。

## 数据与权限

`pg_v9_046` 增加四张私有、强制行级权限的表：版本计数与当前发布指针、不可变完整配置版本、专用验收运行来源和原请求回执。`agentstudio_releases` 为无登录、无继承、无成员的辅助角色。

17 个固定函数受精确的函数执行权限、列权限、RLS、不可变触发器及发布唯一索引检查。辅助角色不能读取模型密钥、工具凭据、知识正文或员工口令，也不能更新当前角色配置。普通 API、Worker、Broker 和认证角色不能直接读取这些私有版本表。启动检查在功能写入关闭时仍执行。

所有完整版本操作仅限经过验证且有效的原生员工所有者。协作中的读者或编辑者不会因此获得完整配置、版本管理或执行权限。完整版本与五项安全描述的协作历史是不同能力。

## 操作约束

- 保存从数据库当前角色冻结名称与完整配置。客户端不能提供快照、所有者或测试通过标记；版本号单调增加，删除草稿后不复用。
- 发布以当前角色、目标版本和发布指针的修订及摘要为条件，原子归档上一个发布版本。未验收或当前验收已失效的版本，必须明确确认后才能发布。发布仅管理版本记录，不执行模型、工具或部署。
- 完整恢复先按创建和编辑角色时的规则检查模型、HTTP 工具、MCP 与知识库权限，再核对当前角色与不可变目标版本。保存准确的历史配置，不自动规范化改写旧快照。事务内的恢复票据、角色写入、协作安全历史、待审提案失效、审计和回执一起提交或回滚。
- 删除只允许草稿，保留内部审计与原版本号；已发布或归档版本不能按草稿删除。
- 每次请求绑定独立请求 ID 和原始规范化意图。响应丢失后可只读核对回执；重新提交必须保留原请求。确认接口找不到回执时返回未找到，不转为执行。

## 专用验收

验收需要配置写入和独立 Agent 运行授权。可选择角色模型或本人另一条已测试、已启用且修订匹配的模型连接；通用 Agent 提交接口仍不接收任意模型覆盖字段。验收请求最多 2000 个 UTF-16 单元，默认页面选择 8 轮，可明确选择 1–30 轮。

验收来源与 Agent 运行、队列、审计和回执在同一事务中创建。来源保存完整角色摘要、修订、任务摘要、轮数和实际模型绑定。普通运行不能冒充专用验收。

通过证明还要求真实完成的 Agent 状态机、成功的 Agent 步骤与模型步骤、当前资源校验和原始知识来源校验。审批被拒绝而跳过的任务不能算验收通过。知识内容、授权或原始样本失效后，输出按既有规则隐藏，不能继续用于新的通过证明。历史 `test_passed` 保留当时事实；`test_current` 独立显示当前是否仍有效。

运行投影仅向所有者暴露已由服务端冻结的本次模型引用。审批页面使用这个引用核对实际模型，避免验收选择模型 B、角色默认模型 A 时错误显示或阻止审批。每一步审批、语义检索费用确认、来源校验和未知结果禁止自动重发的规则保持有效。

## 页面与接口

独立工作台的“版本与发布”包含角色选择、专用验收、保存、版本详情、发布、恢复和草稿删除。待确认请求在同一员工切换菜单时保留，退出或切换员工后清除。恢复和发布确认绑定打开确认时的原配置及目标版本，刷新不会默默扩大原授权。

接口固定在 `/api/v2/agent-releases/:spec_id`。详情使用 `/versions/:version_id`，验收读取使用 `/acceptance/:run_id`；普通变更、专用验收创建和只读核对分别使用 `/change`、`/acceptance`、`/confirm`。Cookie、同源和 CSRF 检查继续生效，忽略任意用户 ID 头。

## 初始化与验证

完整新库初始化真实执行到046：30 个 SQL 源文件、32 条来源版本加一条初始化回执、57 张表／56 张强制行级权限表、22 个核心角色。旧测试数据不导入，服务登录启用及目标执行仍由原有独立工具和授权控制。

验证入口：`pnpm test:pg18:releases`、`pnpm check`、`pnpm test:e2e:parallel`。实际 PG18／HTTPS／私有 TLS 和浏览器用例仅在受守卫保护的托管合成 CI 中运行，不能在普通机器绕过守卫启动。新增浏览器场景为 `releases.spec.mjs`。

当前046整合正在等待同一提交的初始化、完整回归、实际 PG18 和浏览器验证，尚不能据此签收。正式迁移还需要剩余功能对齐、真实员工 UAT、目标网络与权限、备份恢复和回退演练、长期 Worker 验证及签收。
