# 资源与连接的连续使用体验（2026-10-27）

## 本轮范围

连接器本轮版本为 `0.1.0-preview.2`。前端开发预览可加载源代码更新；已经解压的便携程序不会被网页自动升级，应在没有执行中任务时停止旧连接器，再使用新包恢复原配置。更新不要求重新配对。


继续独立分支 `fix/native-dialogs-unified-20261026`，保留既有修改；不重启用户预览、不清空数据库、不读取真实设备凭据、不配对真实设备，不推送或部署。

### 独立连接器

1. 新设备连接草稿和已有设备目录编辑分别保存。编辑草稿绑定具体设备 ID、配置指纹和独立 revision；切换设备清除待选目录，默认只读，不能把另一设备的选择带入。保存仍需本人明确确认，运行中的设备不可更换权限。
2. 导入无效或过期文件后立即作废旧连接草稿。过期时间可见，并在到期时取消旧确认、禁用绑定；提供取消准备和返回相应工作台入口。取消准备不撤销已有绑定、不删除文件，也不自动请求新凭证。
3. 刷新本地状态保留当前焦点及未变化的确认；另一标签修改授权范围后清除旧确认。所有写操作仍以服务器的 revision 为最终校验，不依赖 UI 勾选状态保证安全。
4. 只读查询和本地确认分开排序；较早的读取结果不得覆盖较新的操作。网络故障时保留显示但停止可执行操作；刷新成功后才能重新确认。失败不自动重试配对或文件操作。
5. 已有连接可直接打开对应工作台。新建、编辑与恢复不隐式共用文件权限；状态窗口中不返回凭证正文。

### 执行资源中心

1. 新增 GET-only `readResourceInventory` 和复用 hook。页面可见时每 15 秒核对资源，回到页面时节流刷新；后台标签暂停轮询。重复刷新合并；卸载及账号变化取消旧请求，回应再次核对员工身份。
2. HTTP、MCP、电脑清单独立核验。插件服务失败不会隐藏已核实设备；设备清单失败不会被当作没有设备。已确认的部分连接仍可查看，缺失结果显示未知，工具发现和历史测试不等于执行授权。
3. 未核实设备清单时优先“重新核实已有设备”，不立即诱导重复安装或重新配对。刷新仅获取清单，不触发付费推理、工具试调、角色授权或方案保存。
4. 任务用途记录在页面地址，保留原 Agent 上下文；浏览器返回、前进和刷新能回到所选用途，不保留上一个对象的隐藏选择。

## 同事试用与升级

- 工作台中仍按任务选资料、在线服务或本机能力，不要求每位员工都下载连接器。
- 已使用 `0.1.0-preview.1` 的同事，在确认没有执行中任务后停止旧版；下载、完整解压新版包到新目录并双击 `Start-Connector.cmd`，选择已保存连接恢复。不要复制个人连接文件给他人，不需要重新绑定账号。
- 新连接选错文件时，重新选择正确文件即可。旧确认会清除；看到过期提示时点击“返回对应工作台”更新原设备的连接文件，不另建同名记录。
- 更换已有设备目录时先停止对应连接，再从折叠设置中明确选择设备。取消或切换设备不会把目录与写入权限转给另一设备；新连接草稿保持独立。
- 资源中心使用浏览器返回/前进会恢复用途选择；返回页面会自动核对只读清单。网络读取失败时不要反复安装、重新配对；先用“重新核实已有设备”恢复状态。

## 验证口径

- `tests/connector-distribution.test.mjs`：新旧草稿隔离、跨设备目标拒绝、错误文件/过期、跨标签旧确认失效等；用临时目录，不操作用户配置。
- `tests/resource-inventory.test.mjs`：只读三路请求、单来源故障、设备格式异常、账号变更与取消、部分有效资源复用。
- `tests/connector-manager.chrome.mjs`：真实 Chrome、本地管理器、临时 PocketBase 与真实子连接器；注入原生目录选择适配器验证流程，不声称已完成真实系统选择窗口的人工验收。
- `tests/guided-connection.chrome.mjs`：资源用途历史导航、独立清单故障、聚焦恢复、新连接、实际文件/网页与 390/768/1440/1780px。
- 最终包需重新构建，在项目外目录使用自带 Node 执行包内验收；文件散列校验与源码范围围栏分开记录。不使用历史测试替代本轮结果。

## 交付边界

当前仍为 Windows x64 未签名便携预览包，Chrome 需已安装。没有修改系统默认浏览器、开机自启或企业部署配置；团队共享 HTTPS 工作台与纯净 Windows 终端验收仍须单独完成。
