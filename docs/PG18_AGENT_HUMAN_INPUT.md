# Agent 人工澄清与方案审核：隔离开发中

更新：2026-10-26。完整功能尚未完成，正式迁移 NO-GO。
本阶段未提供公开回复路由、SDK 或员工界面，048也未纳入默认全新初始化。
内部 Agent 准入、Worker 人工协议及回复写入均默认关闭；不能据此宣称功能已验收。

已有代码草稿：

- 原生角色可保存可选的 `require_plan_review` 布尔值，缺省字段保持缺省，避免改写旧快照。
- 显式内部启用的新状态使用 `human_protocol=agent_human_input_v1`。旧状态继续使用原提示词和解释规则；固定的快照及模型—工具—模型指纹用于验证兼容。
- 新状态机支持提问、同一任务回复、方案修改与批准。模型 final 不能绕过所需方案批准；回复不增加轮数，不代表后续模型或工具已获批准。
- 048提议增加本人范围的只插入回复回执，记录问题 / 来源 / 操作者请求与答案摘要。API不能修改或删除已登记回执，其他员工、认证及普通 Worker 角色不能读取。
- 内部回复仓储在同一事务核对当前员工、任务、来源、知识观察和固定问题，更新 checkpoint、队列、审计及回执。原请求重放和只读核对不恢复旧问题，也不重复执行。
- Worker会持久等待输入；私有模型 / 工具执行的共同来源检查会核对当前 Agent 的真实回复登记。若登记丢失或不匹配，不能凭 checkpoint 中的“已批准”文字继续发送。

当前已有纯契约 / 状态机检查与严格类型检查；新增 SQL / 私有 mTLS 隔离用例尚待托管 CI 实测。
