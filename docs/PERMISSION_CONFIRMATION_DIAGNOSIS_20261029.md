# 网站授权等待本机确认：排查与 preview.14 验收

日期：2026-10-29。项目：Agent Studio 独立工作树。范围：工作台内嵌授权管理、本机确认窗口、设备状态同步与交付包；没有生产部署。

## 结论与证据

截图中的“等待本机确认 · 42秒”不是访问百度或目标网站的网络加载，而是授权变更流程尚未取得本机同意。

本轮只读查询原保留预览数据库中的请求元数据：设备 `zhouqing #9xvoJI` 在新加坡时间17:49:38、17:52:45、17:56:38发起的三个 `sites-save` 请求最终均为 `cancelled`，没有成功保存。第一条记录标明 `user_cancelled`，其余两条旧版本未区分本机拒绝与超时，不能倒推出用户当时点击了哪个按钮。本次没有读取这些请求的私有授权载荷或设备凭据。

已实际复现的窗口缺陷：确认进程存在、窗口句柄存在且名称正确，但 Windows `IsWindowVisible` 为 false。仅增加 TopMost/BringToFront 仍不足以可靠显示。隐藏控制台启动状态会影响首次 GUI 显示；新版在 WinForms 完成首次显示之后，对该确认窗执行显式 ShowWindow，并请求前台焦点，保留任务栏入口。

另发现独立状态缺陷：执行器等待确认时暂停普通设备任务轮询，而此前授权专用心跳只更新授权状态表，不更新设备心跳和本机管理器状态。超过45秒可能被错误显示为离线。新版同时更新经认证、归属正确且已应用版本一致的设备心跳，并向本机管理器报告活动。

## 本轮修复

### 本机确认

- 明确标题“Agent Studio · 本机授权确认”，居中、置顶、任务栏可见，显示准确设备、工作台和本次范围。
- 正文为只读、可滚动文本；不能将网站或路径文本作为 PowerShell 代码执行。
- “拒绝 / 取消”为默认按钮和默认焦点，Enter、Esc、关闭均不能意外授予权限。只有明确点击“确认并保存”且后续服务器提交栅栏仍有效才会保存。
- 默认90秒确认期限，显示剩余时间。超时自动关闭并明确返回“未保存”；窗口启动失败与用户拒绝分别处理。
- 取消会等待本次确认子进程真正关闭，避免残留窗口与后续操作重叠。

### 工作台反馈

- 区分“正在提交请求”“等待设备接收”“等待本机确认”“本机正在应用”“确认生效”。不再尚未提交就显示等待本机确认。
- 等待本人时使用时钟提示，明确“正在等您确认，不是在加载网页”，不是无解释的无限旋转。
- 同时显示已等待时间及服务器请求剩余期限；本机窗口另有90秒倒计时，两者不是同一个时钟。
- 8秒后自动展开找不到确认框的提示：准确标题、电脑名称、Alt+Tab/任务栏及原连接升级说明。
- 等待期间仍可刷新状态，刷新只查询、不重复提交。授权状态轮询持续运行；丢失心跳或查询失败不再假装正在保存。
- 取消、拒绝、超时、确认框无法启动和服务端过期后保留当前页面草稿；同一请求的回执恢复使用原幂等编号。
- 成功必须同时核实保存回执和执行器实际应用的新授权版本。提交中或结果未知时不会误报取消或保存成功。
- React渲染状态、账号/设备切换隔离与异步过期回执处理已一并修正；未通过关闭安全规则规避检查。
