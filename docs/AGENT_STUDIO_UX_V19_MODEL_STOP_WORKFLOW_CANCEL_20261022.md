# Agent Studio V19｜模型决策拦截与 Workflow 协作式取消（2026-10-22）

## 目标与范围

基于 V16–V18 已完成的创建向导、资源连接、Agent 安全暂停/取消，本轮补上“模型请求返回后到外部工具真正调用前”的停止窗口，并使 Workflow 的取消机制遵循与 Agent 一致的执行租约安全规则。独立开发分支 `feat/harness-design-workspace-20261021`，不修改 PostgreSQL 迁移环境与生产数据。

## A. Agent 模型→工具之间的停止检查

旧问题：用户在模型请求期间发起暂停/取消，模型响应中仍可能生成 tool 决策。旧代码直接继续派发工具，导致操作不符用户的停止意图。

改动：

- 在模型请求完成后重新读取**当前持久化检查点**中的 `cancel_requested` / `pause_requested`，并使用执行租约进行事务栅栏核验。
- 在工具调用副作用日志创建前增加第二处检查，覆盖工具参数解析、权限与审批判断期间收到的停止请求。
- 检查命中时只写入脱敏状态事件并终止本次决策，不发送后续工具请求。取消由本次 tick 的安全边界转入 `cancelled`；暂停由下一次调度先于新操作应用。
- 已经发出的第三方请求不会被强行回滚；当前步骤的既有副作用审计规则继续生效。

集成测试使用延迟的模拟模型和真实 PocketBase/SQLite：在模型收到请求、尚未回传 tool 决策时分别发起取消与暂停，确认没有 `tool_call` 事件及外部 POST；原有正在执行 HTTP 写入的协作式暂停/取消测试仍保持通过。

## B. Workflow 取消的安全化

旧问题：工作流取消接口一律立刻写 `cancelled` 并清空 `claim_until`，抢占当前租约，导致执行中的节点响应即使成功也可能无法提交检查点。与 Agent V18 采用两种不同语义。

改动：

1. 取消请求通过数据库事务核验员工归属、状态及有效工作流执行租约。
2. 若处于 `running` 且有有效租约，先记录 `cancel_requested=true`，保留 `running` 与当前执行租约；界面显示“取消请求中”及当前节点先收尾的说明，阻止重复点击。
3. 节点的统一 `saveCp` 在租约保护下合并最新取消标志，先保存状态、节点输出、执行统计和副作用审计，之后切换 `cancelled` 并清空待审批字段。未知外部写入结果导致的明确失败仍优先保留诊断。
4. 新接手的执行者若发现遗留的取消请求，在调用新节点前直接执行取消。
5. 工具连接/授权准备之后、外部副作用日志创建前增加一次停止检查，尽量缩小取消与外部写入之间的竞态窗口。
6. 无活跃执行的 `running` / `awaiting_approval` 可以立即取消；后者还会清理待审批状态，迟到的旧审批无法再启动外部写操作。
7. 统一检查点函数返回数据库实际状态，常用外部工具节点和待审批节点的 tick 响应反映 `cancelled` 而非错误显示 `running`。
