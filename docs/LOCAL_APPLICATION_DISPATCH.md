# 本地应用调度（桌面预览版 0.1.0-preview.8）

本次在已验证的 preview.7 桌面版上增加应用调度，保留原员工页面、账号、文件、浏览器和审批流程。不切换数据库、不修改线上服务。内置连接组件版本为 preview.18。

## 使用

1. 在主界面选择本机，展开「管理连接 → 应用授权」。
2. 搜索并勾选已安装或正在运行的应用；可批量选择，最多 30 项。普通应用默认仅允许启动和观察，可分别开启窗口输入。截图、Codex 工作目录写入分别勾选。
3. 勾选长期授权确认并保存。正在运行的连接会短暂停止后自动恢复；手动暂停的连接不会自行恢复。
4. 在「工具与连接 → 我的电脑 → 本地应用」选择应用，启动、查看窗口、观察控件并执行操作。所有内容操作由本机主界面再次确认。每次观察只能执行一次，操作前 30 秒内需获得观察凭据。
5. 在 Agent 运行界面选择同一台电脑；其本机工具清单包含新增的 `apps.*`。所有权、执行审批、任务回执、授权版本和禁止自动重试机制沿用现有链路。
6. 取消勾选应用或关闭应用调度后保存，即可撤销。应用更新导致二进制摘要变化时会停止调用；核对新版应用后重新保存授权。

没有另开连接器窗口。主界面可以暂停、恢复、管理权限和查看执行状态。浏览器网站授权仍可稍后添加。

## 能力与边界

| 类型 | 接口 | 执行方式 |
| --- | --- | --- |
| 普通应用 | `apps.launch` / `apps.windows` | 已核对 SHA256 的固定 EXE，无模型提供的命令行或脚本 |
| 普通应用 | `apps.observe` / `apps.act` | Windows UI Automation，限定已选应用和指定窗口；点击、文字输入、有限按键 |
| Codex CLI | `apps.task_start` / `apps.task_list` / `apps.task_status` / `apps.task_cancel` | 非交互任务、任务列表、进度及结果、停止自有任务；默认只读 |

普通应用不是只针对微信和 Codex 编写的名单，但不代表所有软件的所有界面均可可靠操作。未暴露 Windows 控件的画布界面、特殊弹窗、管理员窗口等可能需要专用适配。当前不提供任意桌面坐标点击，也不接管终端、密码管理器或本软件的授权窗口。

截图只截取指定应用窗口，不回退到全屏截图。需要本人单独授权，单张最多 1 MB；当前截图窗口尺寸不超过 1920×1080，超过时可缩小窗口或关闭截图，继续使用控件观察。

长期应用授权不等于批准所有业务动作。发送消息、删除、付款等必须核对具体目标、内容和结果；工具收到窗口操作回执后仍要求重新观察，不会把“已点击”当作“消息发送成功”。本次验收没有发送真实微信消息。

Codex 使用本机已安装 CLI 的现有登录。按照 [官方非交互接口](https://developers.openai.com/codex/noninteractive)，固定使用 `codex exec --json --sandbox read-only|workspace-write --cd <已授权目录> -`，任务文本通过 stdin 传入。不开启完全访问或绕过 Git 检查。写任务还需应用及目录的相应授权；外部 CLI 不继承本系统文件工具的逐文件权限。任务最长 30 分钟，同一连接同时最多一项；断开连接停止其启动的任务，不自动重交。真实调用可能消耗模型额度，仍需本机确认。本次只验证 `--help` 和模拟任务事件，未发起付费模型任务。

## 验证与实现

preview.9 / 连接器 preview.19：在 Agent 创建向导第三步选择本人电脑，再在具体能力下点击“选用工具”或“选用并分配”。系统核对应用名称、控件操作和截图授权；Codex 写任务同时核对应用与工作目录写权限。选择会保存到 Agent，设备会带入试跑；角色权限不会由模型自动授予。连接变更后需重新核验。

- `pnpm check`：原有单元测试、TypeScript 和生产构建。
- `node --test tests/local-applications.test.mjs`：持久授权/撤销、摘要变化、固定 argv、一次性观察、拒绝、批量目录上限、Codex 事件及并发控制。
- `node --test desktop/tests/*.test.cjs`：私有 IPC 和账号隔离。
- `node tests/local-applications.windows.mjs`：专用 Windows 测试程序的真实窗口、截图、密码标记、中文输入及点击回执。
- `node desktop/tests/connection-flow.integration.mjs --native-applications`：原员工页面 → 私有授权管理 → 实际连接器子进程 → 应用控件 → 本机确认 → 真实回执；另用本机确定性模型验证真实 Agent 调用链，不产生外部模型费用。
- `pnpm test:e2e:parallel -- --workers=1`：完整隔离回归，避免影响生产数据。

原生控制实现在 `local-executor/application-native.mjs`，普通应用工具及 SHA256 校验在 `applications.mjs`，持久授权在 `application-permissions.mjs`，Codex 任务生命周期在 `codex-tasks.mjs`。配置和审批入口仅在本机私有会话内开放；模型不能新增应用权限、修改可执行路径或自行批准操作。

## preview.11 冷启动与任务入口修复

新版内置连接器 preview.20。选择应用后可填写任务并进入原 Agent 试跑页面，所选电脑随任务带入；选择模型并运行后才开始执行。启动应用会等待窗口就绪，复用已有窗口，观察结果包含可读内容与可用动作。每次操作后仍须重新核验结果。

Qoder 采用外层启动器和版本目录内实际程序的双摘要授权。旧授权需要在主界面核对显示的版本程序后重新保存；已打开的旧 Qoder 窗口请自行保存工作、关闭后再启动，以使用辅助功能参数。更新后的二进制不自动继承旧摘要授权。没有可用控件时停止并说明原因，不能保证任意界面均可调度。完整原因、真实冷启动验证和限制见 [本地应用冷启动验收](APPLICATION_COLD_START_20261102.md)。
