# Agent Studio 独立版｜五大工作空间、创建向导与真实质量断言

> 实施范围：`agent_studio_vibex版本` **独立版**。本文是源码与验证说明，不是生产发布说明。运行时仍为 PocketBase + SQLite + Worker；PostgreSQL 17/pgvector 仍为隔离迁移，生产 NO-GO。

## 1. 任务来源与设计目标

针对产品复核提出的五组问题，优先实现可直接让非技术员工使用的、现有后端支持的真实交互。原则：保留已有代码与员工认证，不合并旧 ZIP，改变信息架构但不弱化权限或凭空补全未建设的后端。

### 五大工作空间（一个统一路由表）

1. **工作台**：我的 Agent、最近运行与待处理情况；支持直接进入引导创建。
2. **创建与编排**：五步 Agent 向导、Workflow、模板、共享/协作、发布、集成。
3. **资源中心**：模型连接、知识库、工具连接、插件。
4. **运行中心**：Agent 试跑、执行记录、定时任务、诊断。
5. **管理中心**：员工、权限、管理审批、公司总览，**仅管理员**显示，并由路由守卫/后端另行保护。

原本重复的大量横向页签缩为面包屑。左侧默认显示名称并可按组展开，允许手动折叠并记住选择；`Ctrl/⌘+K` 统一搜索由同一份已授权路由表驱动，支持键盘、Esc 和焦点围栏。普通员工无管理入口，但服务器 ACL/身份验证才是真正的权限边界。

移动端顶部是当前工作空间标题、搜索与全部功能抽屉，底部工作空间具备**文字标签**。适配 390px/768px/1440px，包含抽屉遮罩、Esc、Tab 焦点约束和放大的触控目标。Chrome 模拟不代表真实移动设备验收。

### 真实五步 Agent 创建

`/agent-create`：

| 步骤 | 后端对接与通过条件 |
|---|---|
| 1 描述需求 | 复用已有 LLM 生成可编辑方案；失败/格式异常如实提示 |
| 2 生成方案 | 人工审核目标、范围、交付物、执行步骤、完成标准，保存到已有 AgentSpec owner-scoped API |
| 3 连接资源 | 复用模型连接、工具授权和知识库 ACL 数据；未启用连接或资源不可访问阻断下一步 |
| 4 试跑验证 | 真实 Agent 运行页；链接保留 Agent ID，回到向导重新读实际 run/detail |
| 5 发布 | 要求最新保存版本之后存在本员工所属方案的 **succeeded** 真实运行；有自定义质量断言时需在真实 result 上逐项通过。仅打开现有版本发布页，最终发布仍需其独立确认 |

路由 `?spec=<id>&step=4` 用于恢复已保存方案和试跑后返回。未保存编辑不会被假标记为已完成，页面保留独立保存操作。此向导并非另造执行引擎，持续复用原有服务器校验。

### 工作台概览

统计通过已有 `/api/agent_specs` 与 `/api/agent-runs/recent` 读取当前员工的数据：已保存 Agent 数、最近运行中条数、近期待审批数、最近 5 次执行。**当前计数基于最近 12 条**，不声称是全量历史运行或全公司总计。网络失败显示未知状态，不用假数字填充。

## 2. Agent 可验证质量断言

新增 `quality_checks` 作为 AgentSpec JSON 可选字段，仍使用已授权 `/api/agent_specs/{id}` PATCH 且留下现有 Agent 配置历史；不增加另一路绕过权限的写 API。

断言类型只包含三种确定性规则：

- `contains`：实际输出必须包含指定字符串。
- `not_contains`：实际输出不能包含指定字符串。
- `json_object`：输出需能解析为 JSON 对象。

每方案最多 12 条断言，每个匹配文本最多 200 字；输入会进行格式清理。未配置时**没有虚构通过率**。有配置时，运行详情按方案、状态和归属读取；不能取到实际 result 就无法宣布验证通过。只根据指定规则输出逐条结果和通过比例，**不能将文本匹配、JSON 合法性解释成事实正确、来源真实或整体任务成功**。

重新保存质量断言属于方案变更；上一版本的旧运行记录不能替代新版本的重新试跑。真正的领域级 Golden Cases、证据核验、引用准确率和人工复核仍为后续质量建设。

## 3. Workflow 编排已经实现的重点

可复用之前 ZIP 中的交互增强已保持：拖线新建并原子连线/撤销、条件 true/false 与循环 body/done、非法回边拒绝、右键复制粘贴、Shift 框选、对齐分布、JSON 安全导入导出、节点本地沙盒、明确确认费用的真实模型单节点试跑、运行前诊断、移动画布及保存/刷新恢复。详细见：

## 5. 严格保留的边界与后续 P1/P2

- 未做新的 PostgreSQL 生产切换；已有 PG staging/CI 属另一条并行工作线，正式备份、对账、Worker 切换、灰度与回滚需要独立验收。
- 未把“需要管理员”只交给 UI；真正的权限在第一方员工 JWT、全局路由守卫与服务端 owner-scoping。
- 暂未实现单节点任意外部工具实时执行（仍需权限和审批）、端到端真实客户数据验收、真正全量运营监控、OCR、向量索引迁移和长期运行成本账本。
- 仍需在真实手机和平板验收多点触控、虚拟键盘、抽屉可访问性；Chrome 模拟不是替代。
- Agent 质量评价需要标准化 Golden Cases、可靠来源证据、结果是否达到业务验收条件、人工意见。当前声明的二元断言只能核验字面和 JSON 格式。
- 真实部署前仍需企业网络、备份恢复、员工 UAT、CI、模型服务额度/计费和安全边界复核。**生产 NO-GO。**
