## 设备：连接之后更容易继续使用

- 本人设备的清单、读取错误、心跳时间由可复用的只读 inventory hook 处理。选择设备、创建连接、授权操作仍是明确的用户动作。
- 读取失败不是“零设备”。清单或任务选择器显示可重试的未知状态，不引导用户重复创建配对。
- 在线设备排在前面；默认不混入已撤销设备，设备较多时支持按名称搜索。
- 离线设备可以在当前任务中直接查看/复制原设备的恢复命令；适用简化向导创建的设备，旧手工配对保留原配置启动方式。
- 只有一台在线电脑时提供明确的快捷选择按钮，不自动选择，也不自动扩大 Agent 角色权限。
- 当前选择已删除、撤销或不可核实时保留缺失提示，不悄悄换成另一台电脑。
- 前后台切换时更新只读状态；过期或未来时间的心跳不能认定为可用。

## 浏览器能力预检

旧逻辑对所有浏览器能力都要求截图工具，但连接向导默认没有开启图像能力，导致普通网页读取也被错误拦截。现在文本/DOM 读取核对 navigation + snapshot；显式截图/视觉类需求继续要求 screenshot，写入类需求继续要求相应输入/点击工具。全局工具授权、角色工具权限、有效心跳和 Skill 审核检查均保留。

## 知识库：一个库、四种工作视图

- 文档资料：上传、粘贴资料、文件名筛选，明确加载失败/正在读取/真正无文档。
- 检索测试：当前资料库的引用与检索结果，不再被共享表单和模型配置压到页面底部。
- 成员权限：所有者管理授权；共享使用者只看当前访问能力，不开放管理接口。
- 语义设置：所有者进入后才显示账号级模型与当前库的索引配置；删除资料库位于设置视图。
- 新建和编辑使用按需弹窗，失败保留输入，放弃未保存修改须确认。
- URL 仅保存已选知识库标识和工作视图，不保存查询正文或文档内容；返回当前 Agent 保留原上下文，仍需人工选择知识库与授权。
- 文档读取与检索请求按库标识及请求序号隔离。切库后的过期结果不展示；显式不可访问的知识库链接不冒充另一个库。

## 可复现验收

```
pnpm check
node tests/resource-workspace.chrome.mjs
node tests/guided-connection.chrome.mjs
pnpm test:e2e:parallel
```

`resource-workspace.chrome.mjs` 使用真实 Edge、隔离 PocketBase 与实际登录账号。慢检索、503、过期设备心跳使用明确标记的故障注入。其验证对象是界面隔离及错误恢复，不代表操作了真实桌面。现有 guided-connection 专项继续验证真实本地文件和浏览器 MCP 链路。不使用付费模型或公司数据。

最终通过/失败以本轮工具记录为准，不能把单元测试等同于视觉验收，也不能把故障注入当作实际设备执行证据。
