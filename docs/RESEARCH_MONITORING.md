# 范围监测、固定基线与应用内事件

本轮实现 G10 的受控路径，运行于独立 PocketBase/SQLite + Node Worker。
它不是全网人物监测、完整领域推理或生产上线验收；完整 G01–G12 仍未完成。

## 员工操作

在“跨运行业务任务 → 持续监测与语义变化”选择已有采集计划、已确认人物、
关系类型、明确来源请求及调用/耗时预算。预览后保存会暂停关联计划。员工核对后
启用，原有定时发生实例启动绑定 Agent Run，不另建调度器。

首次采集及来源内容/事实变化需员工读取保存原件，核对每个显示的关系版本、身份、
逐字引文和有效时间，再确认基线。模型和 Worker 没有人工复核权限。
复核会追加对应 SOURCE_SUPPORTED 关系的人工作业记录；已被员工撤回接受的事实，
即使下次采集相同，也必须重新复核。冲突可跳过本次检查，旧基线继续保留。

首页“监测待办与变化事件”汇总当前启用监测的最新待复核/未完成检查及未读事件，
使用 `(created_ms,item_id)` 游标分页。入口链接固定 case/monitor/check/event，
直接展开该历史检查和事件。首页与事件详情均可标已读；没有变化时保持安静。
没有邮件、Slack 或其他对外消息发送。
首页不展示事实正文，原件和历史事实仍重新验证当前来源权限。撤权后的入口仅显示
通用“监测来源不可用”，隐藏自定义标题和事实；暂停的配置仍可在任务页处理。
检查历史和事件分别使用 `(created_ms,id)` 游标分页，默认每页 20 条、上限 50 条，
支持前页、后页及回首页。事件未读数字明确只覆盖本页。来源不可读的事件不返回
正文，仍可翻过该页；不能把空白的一页当作全部历史无事件。

消息链接按事件自身的检查绑定读取来源，即使 URL 同时带另一个属于同一员工的
检查 ID，也不会将两者拼为一份依据。只有检查链接时，可直接打开不在当前页的
旧检查、固定事实集 ID 和保存来源。历史卡片显示原定义版本，当前定义修订不会
改写它。启动前拒绝等没有可读 Run 的检查不显示失效的运行链接。

员工 API 的分页与单条直读都重新检查所有权和当前来源 ACL；直读还核对监测与
检查/事件的绑定。单条事件不可读时返回 403；检查只保留受阻状态和本人元数据，
不返回旧差异或来源正文。标已读只改变本人通知状态，不恢复任何来源权限。

```text
GET /api/business/monitors/{monitor_id}
GET /api/business/monitors/{monitor_id}/checks?limit=20&after_ms=...&after_id=...
GET /api/business/monitors/{monitor_id}/checks/{check_id}
GET /api/business/monitors/{monitor_id}/events?limit=20&after_ms=...&after_id=...
GET /api/business/monitors/{monitor_id}/events/{event_id}
POST /api/business/monitor-events/{event_id}/read
```

## 已登记来源与完整性

只有以下可信适配器可进入已完成采集比较。每个请求的工具名和完整输入被封存；
运行中修改输入、增加其他外部工具或越界业务写入会在外发前拒绝。

- `http.json-items.v1`：已验证的当前员工 HTTP GET 连接，JSON 必须明确
  `scope_key`、`complete:true`、`has_more:false`、`next_cursor:null` 和有界 `items`。
  下例完整空清单是有效回执；遗漏分页标识或有下一页则是检查未完成。
- `web.text.v1`：已声明 URL 的原生 `web_fetch`，实际响应须为完整 2xx 文本页面，
  非空且含全部员工指定的正向范围标记。只覆盖保存的提取文本，不覆盖脚本、图片、
  动态加载内容或扫描文件，也不声称证明网站全部内容完整。

```json
{"scope_key":"employment","complete":true,"has_more":false,"next_cursor":null,"items":[]}
```

Worker 只认真实持久 ToolResult 和实际请求哈希，不能用模型声称“已采集”替代。
JSON 投影只比较 `items`，不把顶层更新时间或标题变化当作业务变化。
来源真实性和外部访问权限变化仍需供应商适配器；当前验证实际传输、声明范围和
已记录的内部 ACL，不能给不诚实上游作完整性认证。多个来源必须全部完成；网络
失败、截断、分页未结束、遗漏请求或预算耗尽不推进基线。

## 事实与时间规则

可信领域适配器 `research.relationship-events.v1` 比较固定事实集中的
`research.relation.v1`，只处理所选人物和 EMPLOYMENT/BOARD/CO_WORK。
端点必须为已确认且版本匹配的实际 ID；姓名相同不会自动合并。当前适配器要求
人物到非人物实体，不能覆盖全部人物协作本体。

事实键包含人物、目标实体、关系类型、有效起点。网页日期、报告文字和采集时间
不充当任职日期。年/月/日解释为 UTC 日期区间：

- 新发现但有效期早于基线的旧报道，仅记录历史信息，不提醒任职变化。
- 有效起点严格晚于基线的新角色，已有未明确结束的角色时提醒“新增角色”，
  不推断原职结束。只有明确且新近的结束日期才产生结束事件。
- 未知、未来或精度与基线重叠的起点，不产生已证实的新任职提醒。
- 明确冲突、事实失效与来源不可读分别处理；失效不等于离职。
- 原事实缺席、候选身份、重复事实键或缺失证据阻止基线推进；缺席不等于离职。

每次冻结事实集不可改写。定义修订使用 CAS、预览哈希和幂等键，暂停计划并清空
当前基线指针，旧版本、检查、复核和事件保留，仍受当前 ACL 约束。
已确认事件按监测版本、前基线及规范事实哈希去重；人工复核不能把冲突变成无变化。
严格路径、新旧现任分类、完整事件本体及更多领域规则仍需开发和实测。

## Worker、权限与恢复

监测不依赖页面保持打开；`worker/run.mjs` 在原有执行循环推进检查。采集使用原
定时发生实例和稳定子 Run ID；检查唯一绑定发生实例，相同已保存来源在重启后
不重复外发。同一监测等待复核时不会并行再建下一基线。状态转换和基线推进使用
事务/CAS，事件有唯一去重键。

定义锁定 Spec/计划/模型/连接配置及人物版本。当前员工失效、配置变化、来源撤权
或计划控制版本改变会停止后续推进。暂停取消待启动发生实例与活跃冻结作业，且
在下一次付费调用前重新检查；已发出的网络请求不承诺即时中止。预算沿用原 Run
原子预留，不能通过监测扩大模型/工具配额。
模型绑定还保存供应商、地址、已验证模型列表、启用状态及服务端凭据存储的组合
指纹；同一连接 ID 更换地址或密钥也会阻断新启动和下一次付费请求。预览仅返回
组合摘要，不返回密钥。原配置的再次验证不会因检查时间变化而单独失效。
旧定义若缺少模型指纹，须重新预览并修订，不能静默沿用新配置。

计划页与监测页共用事务控制：启停同时修改监测和计划。暂停停止本次未验收检查，
待复核检查转为取消，进行中的检查明确未完成；保存的原件、快照、对比和已确认
基线保留。恢复后使用新的发生实例，不能复活旧控制版本的采集。重复启用当前
已启用且配置未变的监测不增加控制版本，避免把已冻结的复核变成过期请求。

编辑绑定计划会暂停监测并取消待启动实例。实际采集配置变化后，必须重新预览并
修订监测定义才能启用，原基线直到新定义确认前仍保留。删除计划会在同一事务内
停止监测、取消待启动/重试/已领取未启动实例并保留历史。旧状态出现“计划缺失而
监测仍启用”时，员工仍可停止它；缺失计划不能被重新启用。立即运行检查当前
范围和未完成检查；不重试旧监测启动实例。普通未绑定计划保持原有控制路径。

五张新增 `agent_studio_monitor*` 表记录定义、不可变版本、检查、人工复核和事件。
已加入只读迁移盘点的运行时阻断清单，未迁移至 PostgreSQL。员工 API 使用验证后
的 `studio_users`，Worker 密钥不代表人工同意。

## 验证与未验证部分

`tests/monitor-semantics.test.mjs` 和 `monitor-sources.test.mjs` 覆盖日期、旧报道、
兼职、明确结束、冲突、事实失效、身份、版本和不完整来源反例。
`tests/research-monitors.integration.mjs` 使用真实隔离 PocketBase/SQLite、HTTP、
计划及两个 Worker 竞争，验证重启、精确范围、复核、去重、失败、暂停、修订、撤权、
首页已读归属和游标。日期前后测试仅在已停机的自有夹具内推进基线观察时间，
不修改系统时钟或预写业务成功状态。

`pnpm test:research-monitors-browser` 额外使用真实 Chrome 完成员工首页入口、预览、
保存、原文读取、复核、控制和刷新。通过结果及完整回归另记于
`RESEARCH_PLATFORM_PROGRESS.md`，不能以测试文件存在代替通过结果。
这些都是 synthetic DEMO，未证明真实模型质量、真实员工 UAT、长期运维、供应商
ACL 或 G10 全领域覆盖。生产状态继续 NO-GO。

历史分页另有真实 Chrome 验证：检查与事件各 121 条明确标注的分页夹具，使真实旧通知落在原先
100 条窗口之后；可从首页后续页定位、读原文、标已读，也可从检查/事件各自后页
定位旧依据。混合 URL 不混用检查，撤权刷新后不再出现原文。
夹具复制的是已有失败检查和已复核的 synthetic 事件，只证明分页/UI/权限行为；
不把插入的夹具解释为采集成功、新增业务变化或去重正确。语义与去重在插入这些
行之前已经通过真实采集/Worker 路径单独断言。
