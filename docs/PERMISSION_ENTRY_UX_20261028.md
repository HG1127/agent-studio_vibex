# 授权入口可见性与工作台到本机编辑器 — 2026-10-28

## 已核验的原问题

工作台 DeviceWorkspaceScope 原按钮只展开说明，没有打开本机权限编辑器。用户截图中的新摘要确实存在，但不能等同于工作台内已经提供网站增删、文件选择。不能将此问题归咎于浏览器缓存。

## 本轮实现

- 工作台直接分栏展示网站和文件/目录；独立的编辑网站、选择文件/文件夹按钮；本人设备的心跳和权限范围显示为最近上报信息，不伪称草稿已经生效。
- 当前设备的已登记工具确实含 connector.open_permissions 且声明 permissions-v1 时，点击编辑可发起一个仅打开授权窗口的请求。旧连接器显示明确的图形手工入口与更新信息，不提供假成功、不自动配对。
- 请求复用原 owner-scoped local job 队列和设备身份；无新增后端接口、无需为此 UI 入口重建数据库。参数仅 panel=sites/files；不接受任意路径、网址、命令或权限正文。
- 便携管理器启动的连接子进程才提供入口；独立 CLI 没有本机 UI 接收端，不会伪报能力。
- 队列 -> 子进程 -> 继承 IPC -> 本机管理器启动 Chrome；本机管理会话令牌只在本地进程与新窗口 fragment 内使用，不出现在工具清单、服务器 payload/result 或日志。地址栏随后清除 fragment。
- 本机编辑器定位同一设备、所选页签；不会新建配对、停止运行、改变目录、访问网站或保存授权。同一设备的未保存权限草稿保留；跨设备切换须本人确认放弃。
- 只有这个无权限效果的窗口打开操作独立于 permissionRevision；所有文件、浏览器及办公执行仍保留严格版本校验。现有权限修改/真正执行与同版本后端的要求不变。
- 上报失败、离线、打开回执超时分别提示，不自动重新提交。只有实际完成回执才显示已发送打开请求；不保证系统窗口已在最前，也不声称修改成功。

## 用户路径

刷新工作台 -> 授权管理 -> 编辑网站 / 选择文件 -> 本机 Chrome 授权窗口 -> 本人修改并确认保存 -> 恢复原连接 -> 工作台自动读取新清单，或点击“我已保存，更新授权”。

已解压的旧包须一次性更新到 0.1.0-preview.4 并从新包启动管理器、恢复原连接；不能只刷新工作台来升级本机程序。preview.3 的独立管理授权仍可手动使用。未签名便携预览，不改系统默认浏览器、不自动安装或启动后台服务。

## 验证与边界

新增 permission-entry.test.mjs：IPC 请求边界、取消不重放、只允许本机目标、执行权限隔离、目录清单与入口声明。
新增 permission-entry.chrome.mjs：隔离认证后端、真实子进程与 IPC、Chrome 中真正出现的授权界面、跨员工拒绝、旧连接器降级、四种宽度。窗口启动采用 headless Chrome newPage 适配器；不能将此测试说成用户桌面焦点切换已人工验收。系统文件选择器为受控适配器。

最终结果以本轮完成的日志与源码一致性校验为准。未改变用户实际设备、授权、文件、内网网站或 8188 数据库；未重启现有服务、推送或部署。
