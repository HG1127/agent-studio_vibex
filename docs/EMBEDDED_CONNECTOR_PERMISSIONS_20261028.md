# 工作台内嵌电脑授权管理 — 2026-10-28

## 本次交付

连接器版本：`0.1.0-preview.8`，Windows x64 未签名便携预览包。

后续恢复修复与最终验收见 [授权请求恢复与连接器验收](PERMISSION_REQUEST_RECOVERY_20261028.md)：连续丢失回执时恢复同一请求、提交检查竞态、完成回执重放、确证未写入后的状态收敛，以及 18 项权限 Chrome 与 37 项完整工作流检查。

工作台入口：工具与连接 → 执行资源中心 → 我的电脑 → 授权管理。

日常操作留在工作台：网站可批量粘贴、自动规范化与去重；可添加/移除/清空后重新添加；文件/文件夹可选择、切换只读/允许新建、移除授权并核验生效。不再请求打开独立 Chrome 管理网页。网站草稿在切换文件授权和关闭重开弹窗时保留，只有显式放弃才丢弃；文件选择有实时过期提示。原生文件选择与最后一次本机确认仍在目标电脑弹出。

只有一个有效已保存连接时，双击便携包 `Start-Connector.cmd` 自动恢复原连接并进入原工作台。首次绑定或多个账号无法唯一确定时，保留本机启动设置。源码目录的旧启动入口仅作兼容转发。新版不自动安装系统服务，不修改 Windows 默认浏览器，不复制日常浏览器凭据。

## 安全与状态闭环

- `studio_local_controls` 与普通 Agent 任务表分离；管理接口不加入模型工具目录。
- 员工端使用已验证登录身份及设备归属；设备端使用既有设备令牌。新通道不修改设备凭据。
- 支持四种有界操作：sites-save、file-pick、grant-save、grant-edit。网页不能提供本机绝对路径。
- 系统选择器返回的路径只在本机内存中保存，网页只得到短期随机授权编号、文件名、类型和有效期。
- 单文件授权只能只读，不开放相邻文件。目录默认只读；新建不覆盖同名文件。移除授权不删除文件。
- 本机显示准确位置、网站范围及工作台地址，由本人确认。静态原生程序通过数据通道接收显示文本，不拼接为命令。
- 保存核对权限版本和原始配置快照；工作进程持有配置锁。执行过程中不并发改变授权。
- 请求具有唯一标识、过期时间及设备领取凭证。同一标识重试不重复执行；冲突复用被拒绝。
- 提交栅栏使取消请求在本机写入之前生效。已进入应用阶段会明确显示不能再取消，不能伪报撤销成功。
- 写入后实际重建运行时，再上报 applied_revision。工作台只有在当前版本、运行时版本及新鲜心跳吻合时才显示“新授权已生效”。
- 即使完成回执丢失，也先替换旧运行时，避免收回权限后旧的较大授权继续可用。工作台可重新检查原请求，不重复执行修改或再次弹出确认；只有核实当前应用版本与目标权限一致才报告成功。
- 管理状态独立于工具清单，因此清空全部网站或全部文件权限后仍能重新授权。
- 对历史无权限版本的配置使用内容摘要核验，成功保存后写入新版本；无需为此重新配对。

## 预览的持久化修复

旧 `ops/v28-isolated-preview.mjs` 退出时删除临时数据库，不再作为日常联调恢复入口。

新入口：`node ops/retained-preview.mjs`。仅监听127.0.0.1，网页8180，API7180。数据与固定加密设置存放在当前用户 `%LOCALAPPDATA%\AgentStudioPreview\<工作树摘要>`，退出不删除，不启动付费模型或后台Agent Worker，不读取生产 .env / pb_data。

测试验证同一预览关闭并重新启动后，账号JWT、设备记录、设备令牌和加密设置继续有效。测试后只清理明确创建的隔离测试目录，日常预览数据保留。

此前检查旧临时预览目录时已无 data.db。该事实不等于已恢复原记录。没有从用户本机凭据反向伪造服务器绑定，也没有替用户撤销或重新配对。恢复旧绑定需要有效旧数据库备份；建立新绑定仍须本人明确确认。

本轮继续工作时复用了现有 retained preview 数据库和固定配置，重启自己的预览任务后检查内容未轮换、页面/API正常及新版ZIP可下载；没有把这一检查表述为找回已丢失的临时数据库，也没有替真实用户登录或重新配对。
