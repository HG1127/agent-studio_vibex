# 电脑与浏览器授权管理：交互改进（2026-10-28）

## 用户可见变化

- 网站支持直接粘贴多个域名或网址，换行/逗号/分号分隔，自动补全 HTTPS、归一到来源并去重。可以直接保存，不必先逐条点添加。
- 保存前展示新增/移除数量，禁止静默忽略错误项、含账号密码或访问令牌的地址，最终仍需要原来的本机确认。
- 关闭授权弹窗、切换网站/文件页签不会丢失当前页面草稿；返回设备页显示“继续编辑”。放弃草稿不会写入本机配置。
- 草稿不写 localStorage/sessionStorage；刷新或离开页面会清除，页面明确提示。更换账号或设备时清空，不能沿用其他人的草稿。
- 文件授权变更只更新文件部分，网站草稿保留；如果其他窗口同时修改网站，保留草稿并要求人工核对，不覆盖对方修改。
- 文件选择显示有效期倒计时，过期/版本失效提供重新选择，不需要重新配对。
- 保存过程按等待接收/本机选择或确认/应用/生效核实展示。结果提示固定在弹窗底部，不需要向下找。
- 轮询网络异常时保留原请求，提供“重新检查结果”，只读取原请求、不重复创建授权。取消与已应用阶段保持区分。
- 不再仅凭文件显示名判定丢失回执的文件授权已经成功。没有明确关联的文件保存结果仍要求核实。

## 本轮边界

本轮变更集中在工作台前端及测试，不改变 permissions-v2 协议，不替用户选择真实文件、扩大权限或重新配对。上述前端交互沿用 permissions-v2 管理接口，不需要仅为草稿或批量输入重新配对。收尾时实测下载清单和原解压目录均已为 preview.6；本文件不将旧包的历史测试当作新包测试。未提交或部署生产。

## 验证命令

```text
pnpm test:permissions-ux
pnpm check
pnpm test:e2e:parallel
```

专项使用真实隔离后端、Chrome、运行时与测试磁盘文件。原生选择/确认通过测试适配器；网络恢复场景仅在浏览器拦截一次状态读取响应，验证继续读取相同请求而不重复执行。不得描述为用户真实设备的人工授权验收。
