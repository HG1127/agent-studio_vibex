# Agent Studio V16｜试跑历史精确归属与执行连接页简化（2026-10-22）

开发目标：继续上一轮 `feat/harness-design-workspace-20261021` 的网页端使用体验优化，优先解决实际用户路径中的误阻断与信息过载。独立分支，不改 PostgreSQL staging、真实员工数据或生产配置。

## 1. 问题和修复

### A. 试跑列表的全局 20 条截断

原 Agent 创建向导调用 `GET /api/agent-runs/recent?limit=20`，服务端先按当前员工所有 Agent 的创建时间取最新 20 条，再由客户端按 `spec_id` 过滤。

当其他 Agent 的 20 次更新更近时，目标 Agent 的有效运行完全不在响应中。结果可能显示“尚无运行”，错误阻断下一步试跑核验或发布前置判断。

修复：

- `GET /api/agent-runs/recent?limit=20&spec_id=<15-char-ID>` 接受**可选**的精确 Agent ID，并先在数据库中添加 `rh_user_id + spec_id` 双条件，之后才做时间排序和数量限制；未传 ID 的既有最近运行 API 语义不变。
- 过滤参数使用绑定变量，拒绝非法 ID；服务器始终从已验证的员工身份确定 owner，不能靠查询参数跨员工读取。
- 向导只请求自己的 Agent；如果响应清单字段缺失或包含别的 Agent 记录，按接口异常处理，不能错误解释为“没有运行”。
- 最近列表的待审批全量统计与待办清单保持原有员工维度，**不是** Agent 专属计数；本次仅改变 `items` 运行列表的过滤语义。

### B. 工具与连接工作台难找到重要状态

原“浏览器与电脑工具”页把接入类别、本机试用说明、连接清单、适配器模板全部同时展开，连接状态及下一步被长说明挤到后面。

修复：

- 主视图显示本账号**已登记数量、历史测试/工具发现数量、失败数量**和部分清单读取错误；不得据此宣称执行器当前在线。
- 本机受控执行器的安全配置与自建 API 适配器模板默认折叠，用户需要时可展开，不隐藏已有功能；坚持说明 localhost 指后端所在主机、执行器不能接管整台电脑。
- 从 Agent 能力规划点击“配置执行环境”时，把 `browser/desktop` 能力类别显式带到连接页，并保留原 Agent、能力 ID 的返回上下文。
- 连接页 URL 参数改变但 React 页面没有重新挂载时，自动跟随新的能力类别；员工手动切换筛选仍被保留，直到下一次明确链接导航。

## 2. 验收范围

隔离环境验证以下行为：

1. 一名员工先运行目标 Agent，再运行另一个 Agent 20 次；全局最近 20 条中已经找不到目标运行，但 `?spec_id=` 仍可精确找到。
2. 其他员工即使传入该 Agent ID，或伪造用户查询参数，也不能取回该运行；恶意格式的 ID 返回 400。
3. 创建与资源连接的 Chrome 用户旅程仍保留原 `returnSpec` 和 `returnCapability`，同时正确打开浏览器筛选；手动展开受控执行器说明后才展示命令和操作步骤。
4. `pnpm check`、`pnpm test:internal-overview`、`pnpm test:design-workspace`、`pnpm test:e2e:parallel` 和源码差异检查。

测试用本地临时 SQLite/PocketBase、确定性测试模型及本机网页 fixture；真实公司登录、外部收费模型、第三方 OAuth、原生 Office UI、实际服务器部署和 PostgreSQL 切换均未在本阶段完成。

## 3. 生产界限

这些改动并不自动启动或接管任何电脑软件，也不授权第三方工具。MCP 连接需用户明确接入、验证、按角色分配；有副作用的调用需要逐次审批。成功试跑只证明保存的确切版本对应真实返回，还需要独立的质量与人工验收。
