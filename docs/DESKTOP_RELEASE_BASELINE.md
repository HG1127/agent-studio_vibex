# 统一桌面发布基线

用户在 2026-11-02 明确要求：所有已验收桌面功能统一合并，后续开发与更新必须以最新版为基础。

统一发布分支为 `codex/desktop-release`，长期工作树为项目根目录下 `.worktrees/desktop-release`。验收通过后本地 `main` 快进到同一发布历史。根目录当前正在进行的 PostgreSQL 迁移工作仍独立保留；它不是此次桌面交付的源码基线。

preview.12 整合了 preview.11 的应用冷启动、启动器与实际窗口双重校验、应用任务入口和结果回读，以及 preview.10 的软件内版本更新、发布签名校验和失败回滚；内置连接器为 preview.20。旧版本交付目录和测试样例仅用于追溯，不作为新功能分支的起点。

新开发应从最新 `main` 或上述统一发布分支创建分支。合入其他对话的改动前，核对其是否包含最新已验收基线；完成整合与验证后再增加版本号、构建、签名发布。同一个已发布版本不可替换不同内容，不能仅凭目录修改时间或版本号认定功能互相包含。

`desktop/release-baseline.json` 记录必须包含的已验收祖先提交。`node ops/verify-desktop-release-baseline.mjs` 和 `node desktop/build.mjs` 会检查 Git 祖先、版本一致性和必要功能文件；CI 获取完整历史后执行同一检查。浅克隆需要先获取完整历史。这是构建前检查，不影响员工运行已安装的软件。

按项目要求执行 `pnpm check`、`pnpm test:e2e:parallel`、桌面单元测试和真实安装/升级/应用冷启动验收。没有通过的实验改动不能因为位于同一个文件夹就进入发布；生成的安装包、数据库、密钥和个人凭据不得提交 Git。
