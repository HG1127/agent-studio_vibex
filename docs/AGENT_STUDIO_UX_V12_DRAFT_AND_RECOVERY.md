# Agent Studio 独立版 V12：草稿恢复、冲突保护与 Workflow 操作优化

**主线：** `agent_studio_vibex` 独立版，React/Vite + PocketBase/SQLite + Node Worker。
**边界：** 本说明仅涵盖开发工作区，**不表示上线批准**；PostgreSQL staging 及生产数据不在本轮改动范围，亦未提交、推送或部署。

## 1. 本轮产品目标及交付

上一轮 V11 将创建向导、资源中心、运行中心与画布改为全宽自适应。本轮不再以布局为核心，而是解决员工实际操作中容易造成数据损失、反复操作和误判状态的问题：

| 场景 | 原问题 | 本轮代码改造与交互 | 保留限制 |
| --- | --- | --- | --- |
| 自然语言创建 Agent | 需求录入后刷新／返回会丢草稿 | `src/lib/agentEditorDraft.ts` 对需求与结构化方案采用**允许字段列表**的当前标签页会话暂存；重新进入时明确提供「恢复」「舍弃」操作 | 12 小时 TTL、每份 64KB 上限，**不是服务器备份**，存储不可用时明确警告。输入框中若主动填写秘密，仍会按输入文本存到浏览器，不能作为密钥保管库 |
| 编辑已保存 Agent | 同一 Agent 多标签页／协作更新导致后来覆盖前者 | `/api/agent_specs/{id}` 的可选 `expected_updated` 乐观锁：不匹配返回 HTTP 409，编辑器原文不丢，可「另存为新 Agent」 | 后端仍兼容尚未带版本字段的旧 API 客户端；生产一致性仍需对所有写入口统一乐观锁 |
| 保存期间再次编辑 | 保存请求返回被当成整个最新草稿已保存 | 按编辑 revision 比较请求开始与结束状态；后续修改仍标为未保存 | 浏览器暂存与正式保存是两种不同持久性 |
| 无修改重复保存 | 不必要的请求更新版本时间，影响“保存后真实试跑”判断 | 若当前 Agent 已保存且未发生修改，主按钮显示「已保存」并禁用 | 不阻止显式另存副本（仅版本冲突时提供） |
| 打开已有 Agent 或换模板 | 可能覆盖当前未保存编辑 | 未保存方案和新输入需求均需确认；清空方案同步清除临时草稿。生成方案成功时清理已消耗的需求输入，如模型请求期间又输入新需求则保留 | 自由文本不建议填写密钥或个人机密 |
| 删除 Agent | 单击图标即可删除，正在编辑的版本可能仍显示“已保存” | `SavedSpecsList` 增加确认/取消；当前正在编辑的记录被删后，编辑区继续保留但转换为未保存新草稿，允许另存 | 删除仍是真实服务端操作，不支持撤销删除 |
| 我的 Agent 列表 | 随数量增加难以查找 | 展示目标简述、最近更新时间排序、名称或目标搜索，次要装饰减量 | 当前搜索仅针对已加载到前端的记录，列表总量和全量服务端分页需后续实现 |
| Workflow 画布 | 复杂画布操作更新多、缩略图默认占空间，手机连线句柄较小，初次加载中就能编辑可能被异步加载覆盖 | 节点、连线组件 `memo`；位置查找改为 Map；MiniMap 按需开关；手机/平板连接热区在缩放视图中实测约 32px；**首次载入现有工作流完成前不开放画布**；从 Agent 方案生成新 Workflow 前需先保存旧图 | 单图约束与真机触控、长期 Worker 执行的压力测试需独立验收 |
| 页面异常 | 动态导入／渲染异常可能白屏 | 各路由增加 `StudioErrorBoundary`，提供页面重试／返回工作台，隐藏原始堆栈和内部异常 | 不取代后端监控、网络重试或文件上传恢复 |
| 未保存导航保护 | 点击侧栏、Ctrl+K 或浏览器 Back/Forward 会直接丢编辑状态 | 全局导航拦截、被拒绝的 Back/Forward 原路恢复；**Agent 的编辑对象、Workflow 的 `?wf` 变化也视为切换文档**；同一向导步骤切换不重复提醒；离开后可选择恢复会话草稿 | 限支持 React Router 可安全恢复的历史条目和已接入页面；非同源跳转、系统崩溃或未知历史序号不承诺完全拦截 |
| 已打开 Agent 时输入新需求 | 保存已打开 Agent 时，另一份刚写的新需求可能被错误清理 | 需求与未保存 Agent 配置分别保留；需求单独备份时不会继承旧 Agent 的 ID/更新时间；切换模板和已保存 Agent 前要求确认 | 当前标签会话级恢复，不是跨设备同步 |

## 2. 安全性与一致性

1. 临时草稿以已验证员工 ID 为键，使用当前浏览器标签页 `sessionStorage`；只存允许字段（任务文本/AgentSpec/保存记录ID/版本标识），**不存身份 token、密码、模型 API Key、HTTP 凭据字段**。
2. 只有用户主动点击「恢复」才加载之前草稿。此操作不能静默覆盖服务器中的新修改；保留原记录 `updated` 后在正式保存时检测冲突。
3. `expected_updated` 在后端事务内、记录 owner 验证之后校验，不匹配不写入，不破坏已有协作审计、版本历史与审批队列。
4. 409 时显示发生了其他编辑及「另存为新 Agent」。HTTP 401/412 时提示重新登录；网络失败时不会错误声明成功。
5. 当前编辑器删除记录后，清除该记录 ID、版本戳和已保存状态，同时保留草稿以便重新创建，避免对已删除记录发送 PATCH。
6. Workflow 多节点性能优化仅优化视图重绘与最后一个拖动事件的对照；原有图谱数据、节点动作、Undo/Redo、安全导入导出、状态审批保持不变。

## 3. 可执行验收

```bash
pnpm check
pnpm test:studio-ux
pnpm test:integration
node --test tests/workflow-ui.chrome.mjs
node ops/e2e-parallel.mjs --workers=1
```

- 单元：草稿字段过滤、跨用户隔离、过期及清除。
- PocketBase 隔离集成：两个编辑方共享旧 `updated`，第一次成功写入、第二次返回 409，已保存结果不被覆盖。
- Chrome：真实登录、临时草稿恢复/舍弃、五步 Agent 创建与版本试跑、Workflow 单节点及多节点操作、慢保存/模拟 503 恢复、Smithery 模拟连接、390/768/1780px 布局、我的 Agent 删除确认及删除后仍可另存。
- 增加导航专项命令：`STUDIO_CHROME_NAV_ONLY=1` 时只检查 Agent 需求及 Workflow 的 Back/Forward、侧栏取消、草稿恢复。Chrome 本次验证已覆盖：拒绝返回时 URL/输入保留，确认后可以离开/返回并恢复草稿；Workflow 在确认取消后保留 3 个未保存节点。
- 需求与 Agent 方案同时存在时，草稿允许两者共存；生成完成清除已经消耗的需求，但不清除模型调用期间新输入的另一份需求。切换现有 Agent 不能静默舍弃新的需求。
- 手机触控：使用 Chrome touch emulation 检查 `pointer: coarse` 下连线把手的命中面积；仍需要真实设备操作验证。
