# 本地应用视觉输入循环修复

修订：`visual-input-loop-20261109.1`。类型：配套服务端修复；兼容已安装的桌面 `0.1.0-preview.31`，不另造同版本安装包。

## 问题与证据

真实 WorkBuddy 调研任务 `xgyuu8225ixb4q6` 的第 19 次尝试在观察、读取结果、再次观察之间循环，最终于第 9 步失败。只读核查本轮本机任务，没有派发输入或提交操作；不能把这个任务说成已完成。

- 本机结果保存了完整观察元数据，但规划历史只展示前 280 个字符，可能截断单次操作凭据和有效期。
- 图片已作为私有附件传给模型；`result_read.content` 并非读取图片的入口。原代码把不存在的字段转换成成功的 `"null"`，模型因而继续寻找截图。
- 附图说明又要求“操作前应重新观察”，即使刚取得有效观察也容易继续重拍。

## 本次行为变化

- 将同一本机结果中已有界限的完整文字与对应图片一起传入下一次模型请求。继续校验账号、运行和设备归属，不把图片写入短历史、事件或 trace。
- 缺失结果字段返回 `result_field_unavailable`（422）；显式保存的 JSON null 仍可读取，跨账号读取仍拒绝。
- 清楚区分图片附件和文字结果。当前图片可核对、观察可操作且凭据有效时，可以申请下一动作；图片不足、界面变化、只读或凭据失效时才重新观察。
- 提醒输入使用单段纯文本，输入和提交分开；原有人工审批、30 秒单次凭据、前台与键鼠接管保护、敏感控件拒绝和不确定结果不重放规则保持有效。

本次运行时代码只修改 `pocketbase/pb_hooks/agent_engine.pb.js` 和 `pocketbase/pb_hooks/modules/tool_results.js`。没有数据库迁移、Worker 行为或客户端权限变更。
