# Agent Studio Windows 桌面预览版

桌面版沿用正式网页版的全部生产路由、React 组件和员工身份验证。首个版本以主分支 `98ee9287fd224ffe2f61de6750d436b71c12f810` 为基线，增加 Electron 外壳、本机网关和集成连接管理入口；另修复一处 Linux 测试对符号链接的清理方式。PostgreSQL 实验页面不进入生产包。

## 使用

1. 双击 `AgentStudio-Setup-0.1.0-preview.5-win-x64.exe`。先在目录选择页选择自己的安装位置，例如 `D:\Agent Studio` 或 E 盘专用文件夹，再点击“安装并打开”。不自动默认到 C 盘；从系统盘运行安装包时，必须自行选择目录。所选位置应为本地可写目录，并预留至少 800 MB 可用空间。安装完成后，从桌面快捷方式或所选目录内的 `Agent Studio.exe` 启动，无需反复解包。
2. 首次界面填写现有公司工作台的 HTTPS 地址，默认 `https://192.168.1.133:8443`，点击“保存并打开工作台”。使用现有员工账号登录；浏览器和桌面版分别保存登录会话。
3. 助手、工作流、任务计划、模型连接、工具、Skill、知识库、协作、审批、排程及管理员功能使用同一套网页代码和服务器数据。点击“连接电脑 / 浏览器”，选择用途和范围后点击“授权并连接本机”。凭证在应用内传递，在当前向导中选择具体文件或文件夹，核对网站并勾选本人确认后启动。不需要下载连接器或导入 JSON。右下角“本机电脑”或菜单“Agent Studio → 本机电脑与权限”打开主窗口内的连接管理面板，可暂停、恢复、修改网站和文件授权，不会打开独立连接器窗口。程序不会自动新增设备授权。
4. 关闭工作台窗口会保留托盘和已连接设备；使用菜单或托盘“退出并停止本机连接”完整退出。不要只关闭窗口后直接替换正在运行的 EXE。

这是连接服务器的完整桌面客户端。服务器、Worker、模型服务及网络必须正常；不会将公司数据库、账号密码、模型 Key 或生产配置复制到 EXE。内置 Node 运行时，无须另装 Node.js。浏览器自动化仍需要本机 Google Chrome；可选桌面 MCP/软件适配器按原有连接配置安装。本机权限范围和逐项审批规则保持有效。

HTTPS 必须使用操作系统信任的证书。连接失败时检查服务器地址、VPN/局域网、证书与服务状态。端口冲突可在设置中勾选“重建本机入口”，会清除桌面登录会话。此预览包尚未代码签名，不提供绕过 Windows 或浏览器安全提示的操作。

## 自动启动与授权

组件随软件启动，无需另开连接器，也不额外安装 Windows 开机启动服务。员工登录验证完成后，自动恢复此账号、此服务器的首选本机连接；如果只存在一条本人连接，可自动采用。存在多条历史连接时，首次由用户选择“恢复连接并设为自动连接”，之后记住选择。手动暂停会保留到下次启动；退出登录或切换账号会停止旧账号由本软件启动的连接，并取消未确认草稿。不会自动新增绑定或扩大文件/网站权限。

授权编辑和权限变更的最后确认均在主窗口完成。保存本地授权前须暂停对应连接，保存后可恢复；从工作区发来的授权变更请求通过私有子进程 IPC 显示在同一面板，必须明确勾选同意，超时、取消、切换账号或关闭软件均不会自动批准。系统文件/文件夹选择器与实际自动化 Chrome 窗口按需要出现。

## 更新和数据

普通 Git 合并不会直接更新已分发 EXE。由维护者选择已验证的提交、运行桌面构建和验收、发布新版本文件。用户完整退出旧版后运行新版安装包，选择原安装目录完成更新；用户配置和桌面会话保存在 `%APPDATA%/agent-studio-desktop`，设备凭据仍保存在原有的 `%USERPROFILE%/.agent-studio`，不在可执行文件内。服务器更新按现有独立部署流程进行，桌面内置前端须与服务器 API 兼容。程序文件放在用户选定目录，TEMP/TMP/TMPDIR 和网页磁盘缓存也使用该目录。原有账号和设备目录继续保留，以保留登录与授权；不迁移或删除旧凭据。分发时只分享安装包，不分享个人缓存或设备目录。首版未接入自动更新服务。

## 可复现构建

在干净的目标源码工作区安装根项目依赖及桌面独立依赖（锁定文件均保留）：

```powershell
pnpm install --frozen-lockfile
pnpm --dir desktop install --frozen-lockfile --ignore-scripts
node desktop/node_modules/electron/install.js
pnpm check
pnpm test:e2e:parallel
node --test desktop/tests/*.test.cjs
node desktop/build.mjs
```

建议将 TEMP、TMP、TMPDIR、ELECTRON_CACHE、ELECTRON_BUILDER_CACHE 指向项目磁盘的专用目录。低内存环境可使用 `pnpm test:e2e:parallel --workers=1`；不要与高压缩构建同时运行大型浏览器测试。`desktop/build.mjs` 验证生产资源隔离，构建官方校验过的 Node 本机组件，并生成 `.tmp/desktop-output/AgentStudio-Setup-<version>-win-x64.exe`。不下载或携带员工数据。

可使用 `node desktop/tests/packaged-smoke.mjs <exe绝对路径>` 验证实际包：创建全新隔离 PocketBase、正常员工 JWT、去掉开发 Node PATH 后启动程序，检查伪造身份拒绝、生产 API 、单窗口、内置组件自动恢复、真实文件任务和应用内授权确认。用例不会连接生产数据库。测试报告不含凭据，临时配置不进入发布包。

## 运行边界

工作台渲染器启用 sandbox、contextIsolation 和 webSecurity，关闭 Node integration；原网页没有任意原生执行接口。设置窗口有两个受限的设置 IPC；工作台仅向当前主框架提供列举状态、准备配对、选择范围、连接启停、编辑授权及回应特定确认请求的受限 IPC。每个请求通过私有 Node 通道交给本机代理，代理向所选服务器验证 studio_users 身份与本人设备清单，按账号和服务器筛选连接；不向网页暴露管理器令牌、长期设备凭据或任意路径/命令接口。配对服务器必须匹配当前工作台。此通道不会自动完成绑定或授予目录权限。文件和程序操作统一经现有连接器，保留白名单、审批与审计。网关仅监听回环地址，验证 Host/Origin，转发正常员工 Authorization，禁止上游重定向及实验 PostgreSQL API。外链打开系统浏览器前询问；下载使用保存对话框，不自动运行。

从旧版升级前，请在旧版菜单选择“退出并停止本机连接”，再打开新版。只关闭窗口会保留旧托盘进程，此时双击新版仍可能打开旧界面。新版重复启动时会提示检查现有实例，并恢复最小化的工作台。

安装包直接将程序文件写到用户选定目录，不把完整压缩包先落到 C 盘临时目录。它使用内嵌清单逐一核对安装文件的 SHA-256，再启动程序；不再以旧 NSIS 长路径元数据错误标志判断复制失败。安装失败会显示可核查信息，详细逐项结果保存在所选目录的 install-verification.json。

安装包测试：`node desktop/tests/packaged-smoke.mjs <安装包绝对路径> --system-temp --install-dir=<隔离测试目录>`。测试传入默认 C 盘 TEMP，断言安装目录与指定目录完全一致，并验证程序与临时文件都使用该目录。直接运行所选目录内 Agent Studio.exe 也会保持同盘临时存储。测试模式不创建桌面快捷方式，不修改真实账号或设备授权。
