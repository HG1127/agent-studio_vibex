# PostgreSQL 原生定时任务准备

迁移 044 接续真实 043，支持原生员工自己的 Agent 与 Workflow 后台计划。
PocketBase 仍是当前运行环境，正式迁移保持 NO-GO。此文、SQL 和服务示例均不授权部署。

新计划先保存为停用草稿；旧导入记录继续隔离。员工选中计划后，核实目标版本、
任务说明、Agent 轮数、总触发次数、有效期及每次运行的自动审批步骤上限，明确
确认模型和读取工具费用后才可启用。可选择持续运行直至暂停；该选项不取消每次
运行的步骤上限。语义知识检索的嵌入 / 重排费用需要另一项独立确认。
MCP 与外部 HTTP 写入仍须逐步审批。达到自动审批上限后也转为逐步审批。
Agent 可选择 1–30 轮；轮数增加不扩大每次运行的自动审批步骤额度。
例如 30 轮规划及 29 次工具调用在额度不足时仍暂停等待本人核对，不能自动多付费。
私有协议、模型 / 工具身份解析及知识来源只接受 01–30 的精确两位轮次，00 / 31 均拒绝。
Agent 状态最多保留 60 个结果和 4 MiB，模型提示仍保持原有 131072 字符上限。
旧导入记录即使包含看似有效的重复规则，API 与数据库也拒绝新授权、编辑或删除；
只保留安全的暂停操作。原生草稿 / 原生执行记录以精确格式和支持标记区分。

## 默认关闭及运行边界

API、Workflow V2 Worker 和自主 Agent Worker 均需要独立 opt-in：

```text
AGENT_STUDIO_PG18_SCHEDULE_RUNTIME_ENABLED=true
AGENT_STUDIO_PG18_SCHEDULE_RUNTIME_APPROVED=APPROVE_DISPOSABLE_PG18_SCHEDULE_RUNTIME_ONLY
```

API 仍要求原有非 root、HTTPS、配置写入、Workflow V2 与自主 Agent 的隔离运行批准。
Workflow V2 Worker 在原有精确 PG18 目标、专用 Worker 密码文件、角色 / 凭据检查及
运行批准基础上增加调度；自主 Agent Worker 独立消费 Agent 队列。计划创建或启用
本身不会启动进程。`--plan` 不访问数据库；`--preflight` 只读检查并不启动调度。
模型、工具、MCP、知识功能继续使用其原有独立开关和私有双向 TLS 链路。
关闭 Worker 的计划执行开关会暂停既有排队计划，不能沿用旧审批自动执行。
员工仍可查看授权状态并暂停自己的计划；这些停止操作不依赖新的执行权限。

## 原子性、撤销和恢复

- 重复规则沿用一次、每日、每周和固定间隔计算；时区使用 IANA，跳过夏令时不存在的
  本地时刻，重复时刻取第一次且同一本地日期不再调度。异常规则 / 时区自动停用并留痕。
- 重复计划可选择首次生效日期与时间，按计划时区换算；固定间隔从该时刻起算，
  每日 / 每周取该时刻起的第一个匹配时刻。夏令时缺失时间拒绝保存，重复时间取第一次。
  授权有效天数从本次确认起计算，首次触发必须落在有效期内；响应丢失重试保留原时间。
- 手动立即运行按分钟去重；同一计划与到期时刻在修改版本后也不能重复创建。
  触发记录固定计划运行编号，每次启动最多四次、租约回收及指数退避。
- 同一计划上一轮还在启动、排队、执行、等待审批或暂停时，新的触发记录为跳过，
  不再创建运行或发送外部请求。数据库锁覆盖租约取得后尚未建立运行的窗口。
  跳过也计入总触发次数并保留审计；上一轮进入完成、失败或取消后才释放执行位置。
  运行终态在同一事务同步到计划历史，启动检查同时验证同步触发器没有缺失或被停用。
- Admission 复用现有服务端资源校验。运行、Job、唯一触发来源与审计在同一事务提交。
  丢失启动响应或重启不生成第二次运行；未真正启动的失败可由所有者明确重试原编号。
  已发出的外部效果继续遵守既有 started / unknown 账本，结果不确定时暂停，禁止自动重发。
- 自然完成的一次计划清空下一次时间并停用，不改变授权修订。暂停、编辑、删除会
  增加修订，撤销待启动触发及未完成运行的持续授权。目标、连接或员工权限变化也会
  阻止后续效果。已完成的历史仍可读取，知识 ACL 与证据来源检查继续适用。
- 三张授权 / 来源 / 自动审批回执表 FORCE RLS，只供无登录、无成员关系的
  `agentstudio_scheduler` 安全定义函数使用；API 无法读取触发租约或直接操作私有表。
  通用启动检查在功能关闭时也审计此结构；部分安装、额外授权、RLS 或函数表面漂移均拒绝。

## 验收范围

本地采用合成员工、嵌入式 SQL、假执行器和故障注入；真实 PG18 及浏览器验收仅在
GitHub 托管隔离 CI 守卫后运行。真实 PG18 用独立 API / Worker / 身份 / Broker 登录及
私有 mTLS 覆盖后台 Agent、Workflow、知识读取、外部写审批、语义费用确认和并发触发。
浏览器覆盖启用响应丢失恢复、去重、运行历史、暂停及员工隔离。
通过这些检查仍需完成其余功能对照、目标环境预检、真实员工 UAT、备份恢复、长时间
Worker 验证及签收，才能重新评估正式迁移。
