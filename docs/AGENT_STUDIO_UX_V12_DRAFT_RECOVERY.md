# Agent Studio V12：草稿恢复、Workflow 性能与页面故障恢复

**适用项目：** `agent_studio_vibex` 独立版。当前生产数据库仍为 PocketBase/SQLite；PostgreSQL17/pgvector 是单独的隔离迁移工作，生产切换 **NO-GO**。

## 一、用户面临的问题

1. 创建 Agent 时临时离开或刷新，尚未保存的需求/方案会丢失。
2. 同一 Agent 若被多个标签页或协作流程修改，较旧的编辑界面可能覆盖服务器上较新的版本。
3. Workflow 画布对所有流程默认绘制缩略图，拖动结束时对多节点重复查找；窄屏按钮较小且操作密集。
4. 某个路由分包加载、组件渲染异常时，员工可能面对整个网页空白且不知如何继续。
5. 对已保存且没有修改的 Agent 继续点击保存，会增加无意义的更新、干扰试跑/版本验收。

## 二、已实施的功能与边界

### Agent 浏览器会话临时草稿（不是服务器备份）

- `src/lib/agentEditorDraft.ts` 提供显式、可验证、按当前**员工 ID**独立的临时草稿保存/恢复。
- 使用浏览器同一标签页的 `sessionStorage`，限制**最长 12 小时**和 **64KB**；只保存白名单中的目标、任务范围、交付物、规划、完成标准、必要工具与知识库 ID、可核查断言、名称与上次服务器更新时间。
- 系统不会保存整份不可信 JSON 对象，也不会把 `api_key`、`password`、`token` 等未知配置字段原样复制到草稿。
- **重要隐私边界：** 这是当前浏览器标签页的非加密会话存储，用户自由输入的描述仍可能含敏感内容。员工**不要在 Agent 需求输入框输入 API Key、密码、个人机密或权限令牌**。如需强加密、多设备同步及端到端保留历史，仍需另行建设经过授权的服务端草稿仓库。
- 暂存为节流写入；关闭/路由卸载前再尝试保存。检测到同标签的未完成草稿后**不自动覆盖服务器内容**，而是显示恢复/舍弃明确操作。
- 完成服务器保存后清理不再需要的草稿；本地存储失败提供提示。编辑未保存的 Agent 时关闭页面显示浏览器原生提醒。

### Agent 冲突检测和独立副本

- 原生 PocketBase `PATCH /api/agent_specs/{id}` 在 owner 事务中支持可选 `expected_updated` 乐观锁。若编辑时的服务器修订与当前数据库不同，返回 `409 spec_updated_conflict`，从根本上禁止较旧标签页覆盖较新修改；未提供该字段的旧客户端继续兼容。
- 员工编辑器发送该字段。出现 409 时保留当前本地草稿，显示冲突解释及**「另存为新 Agent」**。另存用独立 `POST`，不会动原方案。
- 已保存且未修改的 Agent 将按钮改成「已保存」并禁用无意义重复提交；编辑时再次打开其他 Agent、清空或切换模板先确认。
- 在没有原始 serverUpdated 的情况下，编辑器不允许直接对原记录执行不带版本的覆盖保存。

### Workflow 节点画布可用性/性能

- 节点/边渲染组件使用 React memo；缩略图 MiniMap 默认关闭，员工点工具栏可开启或再次关闭，减少默认渲染噪声和工作。
- 结束节点拖动时，使用 Map 查找当前位置而非两层 `find()`；在更大流程图上避免不必要的嵌套查找。
- 手机可见核心画布控件提供 44px 左右触摸目标；缩放和跟随等次要操作收起，保留“添加、撤销、重做、适应画布、整理与专注模式”。
- 图数据保持原有版本、撤销/重做、安全 JSON 导入导出、循环/条件节点等行为，不改变 Agent Worker 的业务执行语义。

### 路由故障可恢复

- `src/components/site/StudioErrorBoundary.tsx` 和 `src/App.tsx` 在懒加载模块或 React 渲染失败时显示**重试当前页面 / 返回工作台**，不在员工 UI 显示内部堆栈/连接凭据。
- 只开发环境在控制台留下诊断。身份认证/服务端 ACL 不因异常恢复而被跳过。
- 该恢复页针对 React 页面异常，不等同于断网时仍能运行后台 Agent 或多设备草稿保存。

## 三、验证方式和当前覆盖

```bash
pnpm test:studio-ux
node tests/pocketbase.integration.mjs
pnpm check
node --test tests/workflow-ui.chrome.mjs
node ops/e2e-parallel.mjs --workers=1
```

- 单元测试检验草稿有效期、员工隔离、未知凭据字段过滤、舍弃行为。
- 独立 PocketBase 集成测试验证两页面冲突：旧 `expected_updated` 被 409 拒绝，服务器已保存修改仍完整。
- 真实 Chrome 模拟单标签页内输入需求、刷新、选择恢复或舍弃；验证 Workflow 缩略图按需开/关、原有拖线、条件/循环、右键菜单、复制粘贴、保存/503 后恢复、模型节点本地模拟调用。
- 390px、768px、1440px、1780px 的向导与主要资源/运行页面布局继续回归。

## 四、未完成，不提前宣告生产就绪

- 真机 iOS/Android 多点触控与屏幕阅读器可访问性还未完成正式 UAT。
- Agent **多设备、加密服务端草稿与历史版本合并**尚未建设；本轮仅可帮助当前浏览器标签页恢复。
- 页面异常下的任务后端自动重试、长期断线恢复、外部模型费用确认和多渠道运营告警需要独立迭代。
- PostgreSQL 17 的正式对账、备份回滚、Worker/租户权限全域等价验收保持独立，现阶段不进行生产切换。
- 不擅自提交/推送/部署该工作区，继续保留并行修改的 PG 源码。
