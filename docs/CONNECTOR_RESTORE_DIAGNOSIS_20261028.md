# 电脑连接恢复失败排查与操作说明（2026-10-28）

## 结论与当前边界

本次排查对象是本机已保存的 `zhouqing`，服务器为 `http://127.0.0.1:8180/__pb`。原本机配置和凭据仍存在，启动所需的文件与浏览器组件可以加载；当前工作台对原设备身份返回 HTTP 401，且当前保留预览数据库中没有对应设备记录。

已修复连接器吞掉失败状态的问题，便携包版本为 **0.1.0-preview.9**。这项修复能正确报告和保留失败原因，不能补回缺失的服务端设备记录。没有自动配对、替换身份、扩大权限或伪造在线状态。

此前“找到 zhouqing 后直接恢复”的建议缺少服务端原设备记录仍存在这一前提。在当前数据库下，重复该操作不能使原绑定上线。

## 已核实的原因

| 层次 | 核实结果 | 影响 |
| --- | --- | --- |
| 本机配置 | 服务器、配置 ID 与凭据 ID 一致，授权目录存在，启动预检加载 15 个工具 | 不属于本机配置完全丢失或基本组件无法加载 |
| 原身份认证 | 无任务执行的 control-check 探针返回 401 / device_unauthorized | 当前工作台不接受原设备身份 |
| 当前服务器数据 | 只读查询没有找到原设备记录 | 相同的 8180 地址不能证明使用的是原来那套设备登记数据 |
| 旧连接器状态 | preview.8 实际子进程遇到 401 后以退出码 0 结束，管理器删除进程状态 | 页面退回“未由本程序启动”，具体错误消失 |
| 工作台进程寿命 | 前一次自动启动的预览实际在 3600 秒被执行宿主终止 | 工作台停止后，连接也会失败；它与身份拒绝是两个不同问题 |

用户截图发生在前次预览超时之前，因此不能把截图中的失败全部归因于服务后来关闭。

在当前保留预览目录、项目已知旧预览目录，以及两个匹配的旧临时预览目录中进行了有界只读查找，只找到当前数据库；未找到可用于恢复原设备记录的副本。这不等于证明其他位置或外部备份绝对不存在。

## preview.9 的修复

- 子进程通过有限的安全错误代码报告认证、组件和启动失败；401 不再被当作正常完成。
- 管理器保留本次启动失败结果。刷新状态或刷新同一管理页面，不再抹掉错误。
- 401 卡片显示“原绑定未通过验证”、HTTP 401 说明和“重试原连接”。
- 启动、运行、失败和停止分开判断；只有真实服务端连接确认才显示在线。
- 取消重试保持原失败；重试继续使用同一身份和原授权。
- 预检阶段重复点击、停止后迟到消息、旧子进程退出、等待控制重启期间停止，都不会误启动第二个连接。
- 普通 stderr 警告不再直接视为连接失败；原始 stderr、凭据和配置内容不显示到卡片。
- 页面、工作台握手与便携包使用同一个版本来源，修正原页面仍写 preview.7 的问题。
- 新增项目根目录 `Start-Workbench.cmd`，供用户在自己的本机窗口启动保留数据的工作台。该入口不安装服务或自启动。

错误保留在当前管理器进程内；关闭管理器后，不承诺跨进程持久保存诊断历史。

2. 核对当前账号、电脑名称、用途及允许访问的网站，点击“生成并下载连接文件”。

5. 以工作台显示设备在线、所选能力就绪为完成标准。CMD 打开或本机窗口出现都不代表配对完成。

本次没有代替用户确认新的账号绑定及网站、文件授权。旧 `zhouqing` 的配置继续保留，便于后续查证；不要把“重试原连接”当作新配对入口。

## 通用流程：新电脑与恢复原连接

| 场景 | 正确流程 |
| --- | --- |
| 新电脑或当前工作台尚无有效绑定 | 工作台生成一次性 JSON → 本机连接器导入 → 本人核对范围并确认 → 工作台核实在线 |
| 原电脑、原工作台、服务端记录仍有效 | 启动连接器 → 选中对应已保存连接 → 恢复并确认 → 工作台核实在线 |
| 本机存在多个已保存连接 | 手动核对名称与服务器；不能按列表第一条自动判断 |
| 当前服务端缺少原记录或已拒绝身份 | 先核对原数据与绑定；重启程序不能自动重建原记录 |
| 只是工作台服务停止或网络中断 | 先恢复对应工作台服务或网络；不因此重新配对 |
| 另一台电脑使用此系统 | 使用那台电脑可访问的正式 HTTPS 系统地址生成连接文件；127.0.0.1 只指向操作电脑自身 |
