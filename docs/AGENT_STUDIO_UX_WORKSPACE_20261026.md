# Agent Studio · 执行资源工作区与视觉体验改造（2026-10-26）

适用代码：独立开发工作树 `harness-design-20261021`，分支 `fix/native-dialogs-unified-20261026`。仅调整自有 Agent Studio；不代表旧 VibeX 网站或内网已经上线。

## 产品原则

- 按用户任务而不是底层技术划分入口：接入资源 → 配对设备 → 验证工具 → 查看调用 → 排查运行。
- 主任务编辑区优先，配置在需要时打开；避免常驻第三列挤压执行结果。
- 同一个数据源的多种视图使用页面内工作区导航，不重复制造一级模块。
- 区分“已登记连接 / 曾测试成功 / 当前设备在线 / 有权发起动作”。其中任何一种均不能代替其他状态。
- 涉及外部写入、付费模型、本地电脑操作及敏感配置时仍保留原有独立授权与审批。Skills 只能在用户审查后按角色绑定，不自动扩大工具权限。
- 页面应优先展示用户当前可以做的下一步；技术细节和高级选项按需展开。

## 当前导航与闭环

主导航维持工作台、设计与编排、工具与连接、运行与验收、管理中心五个工作空间。

**资源接入闭环：**
1. 进入执行资源中心，选择浏览器、电脑软件、HTTP 或 MCP 接入方式
2. 如果是本地执行器，配对指定设备并确认实际在线与可访问动作
3. 选择具体工具进行受约束的试调，发生外部写操作时须单独授权
4. 从调用记录按状态、来源、工具与页码定位失败，展开错误与运行 ID
5. 运行监控查看队列、Worker 心跳、统计窗口，进一步分析可进入 `/harness`
6. 返回原 Agent，刷新资源、显式分配工具及角色，保存后进行真实试跑，依据证据验收，不因为“已连接”就自动发布

**Agent 执行闭环：**选择已保存 Agent → 检查模型和必需工具 → 补齐连接与角色授权 → 设置预算与确认规则 → 启动任务 → 运行过程/成果/质量验收。调整配置不修改正在运行任务的冻结快照。

## 交互与性能约束

- 自适应基线为 390px 移动端、768px 平板、1440px 桌面和 1780px 宽屏，不能出现整个文档的水平溢出。
- 运行设置抽屉采用焦点进入/恢复、Escape 退出、Tab 焦点循环和背景滚动锁定。
- 工具调用仅查询当前员工，分页和过滤在服务端执行；不把“浏览器加载前 50 条并分页”冒充全量分页。
- 历史分页不自动滚动或每 5 秒刷新，首页可在页面可见时刷新。
- 过滤与翻页异步响应须做请求顺序校验，避免慢响应覆盖较新的选择。
- 查询条件仅在服务端已验证的业务字段上执行；来源、状态使用固定白名单，所有 SQL 参数绑定。
- 右侧抽屉的简化不放松任何登录校验、数据归属及危险工具审批规则。

## 测试与上线门槛

必须验证 `pnpm check`、`tests/tool-debug.integration.mjs` 以及 `pnpm test:e2e:parallel`；另设 `STUDIO_CHROME_UX_ONLY=1 node --test tests/workflow-ui.chrome.mjs` 检查工作区、全宽 Skills、390px 溢出与运行设置抽屉。

Chrome/Edge 已被观察到在当前 Runner 隔离模式下不生成 `DevToolsActivePort`（测试浏览器直接退出），因此这项浏览器测试的环境失败不得写成产品功能失败，也不能宣称 UI 浏览器验收完成。只有真正完成渲染、动作与断言，才记录通过。

此工作树不部署、不推送主分支；正式上线需要人工 UAT、内网访问与权限、安全备份和稳定 Worker 的 GO/NO-GO 验证。

## 2026-10-27 深化体验改造（独立开发分支）

### 从“页面集合”升级为“当前任务的下一步”

- Agent 试跑页增加 `RunJourneyGuide`：使用已保存 Agent、模型绑定、运行前真实预检、任务输入和实际 Run 状态，给出唯一的主要下一步；可直接跳到创建、模型连接、资源设置、输入框、运行按钮、待审批操作、执行过程或验收结果。所有指引只解释既有状态，不替代服务端校验。
- 运行提交处于尚未确认阶段时明确展示“提交中”，阻止引导用户重复发起可能计费的任务。
- 将冗余的“下一步”说明从 Agent 选择栏移除，保留四阶段紧凑进度与一个行动入口，减少重复文案和纵向堆叠。
- 用户主动打开资源抽屉时直接展开当前运行模型与工具配置，避免“先打开外层抽屉、再打开内层设置”的二次点击。
- 已成功执行仍需查看成果与验收条件，不得将执行成功等同于内容质量达标。

### 记录与排障的可靠性

- 引入 `invocationViewKey`：筛选条件、员工、Agent Run、页码任一发生变化，旧请求返回的结果不再在新列表中闪现；未完成请求显示读取状态；查询失败显示明确错误，而不是假装“零条记录”。
- 调用记录保持对当前任务 Run ID 的服务端精确筛选，点击运行结果上的“查看本次工具调用”直接定位到相应运行，不再手工复制 ID。
- Harness 的完整分析仍可由统一工作区的监控视图进入，但不再独立占用侧边栏入口，避免相似功能在主导航重复。
- `toolHubView` 统一解释当前的诊断子视图。设备、调试、记录、监控各自只加载所需接口，避免筛选历史记录触发工具目录/队列/Worker 全量请求。设备页使用其本身的刷新功能，不展示无效的重复刷新按钮。
- 新增测试覆盖引导优先级、跨页身份/Run 过滤、视图身份匹配及导航收敛；真实界面响应式仍必须由可用 Chromium 或人工 UAT 完成验证。

## 后续优先优化（未在本轮冒充已完成）

1. 在 Agent 角色/能力缺口列表里自动聚焦对应执行资源步骤，并结合真实连接、权限、工具试调证据完成闭环。
2. ToolHub 统一支持按时间范围、Agent、具体失败类型归类查询，并把运行异常导向对应工具配置和服务端审计。
3. 工具选择器进一步融合 HTTP、MCP、浏览器、本机和已审核 Skill 的能力发现，但严格区分“方法引用”和“实际执行授权”。
4. 获取真实浏览器可用环境后，针对 390/768/1440/1780px 截图、键盘操作、窄屏交互和全过程按钮验证，修复剩余的布局和焦点问题。
