# PG18 员工语义设置、索引与查询界面

原生员工工作台的知识库页已接入 SQL035–038 的设置、费用授权、索引与查询。四项能力分别读取服务端能力声明，默认关闭；页面参数不能启用后台执行。既有关键词搜索继续可用。Agent/Workflow 的语义执行仍待接入，正式迁移保持 NO-GO。

## 员工操作

1. 在“语义检索设置与索引”选择本人已启用的 OpenAI 兼容连接、已声明的向量模型和管理员允许的服务地址，保存设置。该操作不调用提供商。存在未保存草稿时，费用授权和索引启动保持冻结。
2. 分别选择索引或查询费用授权，明确确认承担当前配置的提供商费用。授权绑定当前配置 UUID、配置修订与授权修订；历史回执不代表当前仍有权限。
3. 索引还须单独确认启动，确认范围为本人当前配置下全部待索引内容及后续新增内容。按本人知识库读取已完成、待处理、活动批次及不明结果。停用和重建需单独确认；重建保留历史计费记录，重新处理历史片段需要再次明确授权和启动，可能增加费用。
4. 查询最多选择 10 个本人或获授权知识库，输入不超过 300 个 UTF-16 单元的查询。默认免费关键词；auto 未逐次确认费用时也仅查询关键词。semantic/hybrid 必须逐次确认本人当前配置的费用，严格模式失败不静默降级。

共享语义查询还须原所有者允许且已有兼容索引。索引费用由原所有者承担，查询使用读者自己的模型和密钥；提供商只收到读者查询文本。界面不接收原始向量或返回密钥。

## 丢包与会话

设置、费用授权及索引启动一次只保存一个不可变请求。丢包后保留原 UUID 和原配置，员工先 GET 回执，可手动重试同一请求；不会自动 POST。收到历史回执后重新读取当前状态，不能用回执恢复已撤销授权。

查询独立保存完整意图。丢包后仅核对回执，只有 GET 确认暂未找到记录才开放手动重试原请求。已分派的不明结果不能通过重试控件重新执行；新查询仍需另行确认费用。后台处理时最多轮询 30 次，只读取状态；之后仍可手动核对。

导航保留待核对请求，离开查询页、失焦、权限变化和重新读取期间清除可见片段。重新进入或聚焦后重新核对服务端回执。登出或更换员工身份重置控制器，迟到响应不能填回新会话。请求和结果只存在当前组件内存，不写入浏览器存储。

结果仅接受所请求的知识库和查询方式，验证数量、文本长度与有限得分，丢弃无关字段。文件名、员工名称和片段均作为普通文字渲染。当前授权、内容与向量版本仍由 SQL038 每次核对；前端状态不是授权依据。

## 验证与剩余边界

控制器与渲染专项覆盖默认免费、费用确认、不可变意图、丢包核对、会话隔离、严格模式和文本转义。托管浏览器用例使用合成员工、实际 Cookie/SQL、私有 mTLS 以及合成 Embedding 提供商，覆盖所有者设置和索引、读者费用与共享查询、撤销/重新授权、提供商异常回退、功能关闭及登出清理。浏览器只在指定非 root GitHub Linux 环境运行。

精确候选的最终通过结果见[迁移草稿 PR](https://github.com/HG1127/agent-studio_vibex/pull/26)。这些用例不能替代真实员工 UAT、长期 Worker、实际备份恢复、回滚及运维签收。后续 Agent/Workflow 语义检索必须位于明确批准的执行阶段，并保留实际生成提示词的审核，不能在准备或预览时产生费用。
