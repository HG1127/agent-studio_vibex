# Agent Studio 独立版 V11｜全屏自适应与全模块 UI/UX 审视

> 本文件记录已实施的 UI/UX 变更、逐模块问题、可验证的验收条件和后续工作。适用对象为 `agent_studio_vibex` 独立版，不是原始 VibeX 网站。生产环境 PostgreSQL 迁移仍为 NO-GO。不要将本文件视为生产发布批准。

## 一、设计原则

1. **充分利用主工作区，而非无限拉长阅读行宽。** 页面外层不再限制为 `max-w-6xl / max-w-7xl` 的中央岛屿，使用整个可用工作空间；复杂编辑器采用合理的分栏宽度，单行长文本由组件限制阅读密度。
2. **用户下一步操作最显眼。** 向导重心是需求输入与生成按钮；运行中心重心是任务指令、运行时间线和结果；资源中心重心是连接/上传/验证；管理员优先看到待处理审批。
3. **说明从「始终展开」变为「按需查看」。** 不应让三步教程、技术指标、模型成本说明、记忆管理和辅助优化抢占主操作视线；它们仍可通过可访问的 `details` 展开。
4. **坚持功能真实和权限边界。** 不因为美化按钮就修改审批、员工具体归属、质量断言、Workflow 版本持久化或数据库路径。未完成/无数据时显示真实状态。
5. **响应式导航与输入适配。** 390px 手机与 768px 平板采用带文字标签的底部工作空间及顶部功能菜单；1024px 及以上采用桌面侧栏。移动详情不依赖 hover、正文不能出现意外横向滚动。
6. **一致的设计节奏。** 标题、容器左右留白、二级信息灰度、边框与阴影、主按钮高度等保持一致。主操作优先占用视觉权重，避免大面积无意义渐变、重复的页面品牌页脚和高密度徽章。

## 三、已通过的浏览器布局基线

独立 Chrome 测试 `tests/workflow-ui.chrome.mjs` 使用真实独立登录、隔离 PocketBase/SQLite、模拟模型/Smithery 服务执行。

- Agent 创建输入区在 **390/768/1440/1780px** 响应式布局均无横向溢出。
- **1780px**：创建向导主工作区约 1540px，需求输入卡约 1092px（扣除桌面侧栏与说明区）；不再是固定 930px 中央岛。
- **768px**：切换平板导航，主内容可使用完整 768px 宽；Workflow 画布从旧的约 486px 扩展至约 726px。
- 工作台、模型、工具、知识库、插件市场、Agent 运行中心在 390/768/1780px 的 **18 个页面-宽度组合** 均验证主容器宽度与无横向溢出。
- 同时保留既有 Workflow 拖线建节点、循环回边、Shift 多选、对齐分布、慢保存及 503 重试、JSON 导入导出；创建向导保存/试跑回跳；Smithery 授权与工具发现（模拟第三方）。

## 五、优先级与禁止提前宣称的事项

**P0：** 客户端恢复和真实员工权限、生产迁移审批及回滚、真实模型/工具调用、账号和第三方 OAuth，属于上线阻断项；V11 UI 变化不能视为完成这些验收。

**P1：** 实机移动端/平板手势、屏幕阅读器与焦点导航、长表单自动保存/离开提示、多角色员工 UAT、标准化组件库和响应式视觉回归截图。

**P2：** 更大规模下的列表虚拟化、仪表盘用户定制、模块可用性分析与按角色简化功能入口。

本轮未进行 Git 提交、远端推送和生产部署，也没有执行 PostgreSQL 正式切换。独立版的 SQLite/Worker 与 PostgreSQL staging 必须继续隔离。
