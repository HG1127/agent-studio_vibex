# Workflow 最终交付容量对齐：隔离验收

更新：2026-10-26。提交`f2e3deb5d047ef8f2abe401a8d7be7622f188e78`已通过 SQL、实际 PG18 与浏览器隔离验收。正式迁移仍为 NO-GO。

PocketBase 的 Workflow 每个节点保存最多4000个 UTF-16 单元，结束节点另把最终结果保存到20000。
原生解释器也有20000的最终结果字段，但共用模板展开函数会先在12000处拒绝，导致多个已保存节点组合的成果无法完整交付。

新 Workflow 与单节点调试任务使用 `output_protocol=workflow_final_delivery_v1`。
协议进入持久 checkpoint，并进入图摘要及后续效果请求指纹；删除、伪造或替换协议会被回放校验拒绝。
只有新协议的结束模板允许有界展开并截取到20000。每个节点 / 效果日志仍为4000，模型和工具输入展开仍为12000。
不增加模型次数、轮数或工具授权。

旧状态没有新字段，保持原图摘要、请求摘要和12000的拒绝规则。
原请求恢复先读取原运行，保留它的原协议；不会把恢复请求当成升级任务。
自主 Agent 的完整交付仍使用独立的 `agent_full_delivery_v1`，两条路径保持各自的旧行为。

当前26项纯状态机 / 编辑预览检查与后端、前端类型检查通过。
新增 SQL 测试覆盖20000字符持久结果及旧原请求恢复；实际 PG18 场景通过私有 mTLS 取得一次4000字符模型结果，组合为20000字符最终交付，核对原请求重放没有新增调用。
浏览器场景另覆盖无外部效果的完整结束模板。新增 SQL / PG18 / 浏览器均已通过：[质量42/42](https://github.com/HG1127/agent-studio_vibex/actions/runs/40303921585)，`pnpm check`623项、类型/构建和95项生产资源检查；[真实PG18](https://github.com/HG1127/agent-studio_vibex/actions/runs/40303921631)验证20000字符结果、一次私有模型调用和原请求恢复；[浏览器4/4](https://github.com/HG1127/agent-studio_vibex/actions/runs/40303921612)，主场景12项。版本作业曾在Chromium依赖安装取消，独立补跑后全部通过。两条成功效果记录分别是调用预留和Worker结果，不能把预留当成第二次模型调用；提供方计数仍为一次。
