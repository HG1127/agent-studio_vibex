# 原始需求保存与生成前能力预览

本轮补齐 G11 中“模型生成后原始要求丢失”的路径，未宣告完整自然语言编译器完成。
默认运行时仍为独立 PocketBase/SQLite；没有部署或数据库切换。

## 当前员工流程

创建器先以“预览需求与能力”保存本人需求记录，调用服务端能力注册表做依赖预览，
此时不调用模型。员工核对原始输入和原生/已连接/待配置/需开发状态后，才选择
“按已核对需求生成草案”。模型输出仍只是草案，没有执行、工具授权或自动发布。

草案携带 `_studio_authoring.request_id`，原文不靠模型回写。编辑器可读取完整原文
及修订，并持续核对当前草案。追加 AI 修订之前先保存员工的新指令，再调用模型；
模型即使省略 OCR、关系图或监测，服务端仍从原始要求推导这些依赖。
旧 Agent 没有记录时明确标为未知；从旧 Agent 开始的新修订标为 `revision_only`，
不能据此声称更早原始需求已经补齐。

## 服务端与版本边界

- `agent_studio_authoring_requirements` 为本人私有、不可变的父链；每条保留原文、
  类型、父引用、链哈希、幂等键和创建时间。API 不提供覆盖或删除原文。
- 单次最多 12000 UTF-16 单元，整链最多 24000、20 条；超出明确拒绝，不截断。
- 同一幂等键重试恢复同一记录，内容不同返回冲突。父链和读取都核对当前员工。
- Agent 保存钩子及普通所有者更新入口保护引用。更新漏掉引用时继承旧引用；
  只能沿原链追加，不能换成不相关需求。恢复旧配置时保留后来追加的要求。
- 版本快照保存当时的引用，后续新要求不会改写旧快照。发布按快照引用解析当时
  的真实需求；OCR/关系图等未开发能力仍阻断发布，不因模型省略描述而放行。
- 协作仅修改原有描述性字段，不能修改这个所有者保护字段。临时草稿保留准确
  引用及能力 ID；无效引用或超长能力条件拒绝恢复，不静默删除。
- 公开模板只传递服务端推导的能力 ID；原始私有引用和原文不复制给其他员工。
  展示、复制模板均保留能力 ID，不把它们当作授权或已连接凭证。
- 内部一次性共享也保留这些能力 ID，剔除原始私有引用与原文。接收者拿到的是
  仍需配置/开发的指令副本，不能把共享成功当作原始需求已实现。

```text
POST /api/authoring/requirements
GET  /api/authoring/requirements/{request_id}
POST /api/authoring/preview
```

这些入口要求验证后的 `studio_users`。任意 `X-Rh-User-Id` 不是认证；知道另一
员工的请求 ID 也不能读取、引用或接续其私有需求。能力检查返回来源摘要和状态，
原文只由对应私有入口返回。新增表进入只读 PG 迁移阻断盘点，未迁移业务数据。

## 未完成部分

目前按有界规则与显式能力 ID 推导依赖，保留原文不能证明所有自然语言语义均已
正确解析。文字步骤尚未自动变为可执行 DAG，丰富输入类型、依赖重建、完整创建
到发布的独立验收仍待完成。新增要求目前只追加；显式移除/替换旧要求的审阅流程
尚未提供，不能通过省略字段绕过。确需不同任务范围时可创建新的独立 Agent，
原任务记录继续保留。上述限制不算 G11 完成，也不缩减完整 G01–G12 目标。

`tests/authoring-requirements.integration.mjs` 在真实隔离 PB/SQLite 验证链、权限、
幂等重启、字段遗漏、版本恢复、发布阻断和模板隐私。`pnpm test:authoring-browser`
额外用真实 Chrome 验证先预览零模型请求，再生成故意漏功能的 synthetic 草案，
保存刷新后仍读取原始要求并显示未开发能力。它证明控制和传输，不证明真实模型
研究质量。最终完整回归记录见 `RESEARCH_PLATFORM_PROGRESS.md`，生产仍 NO-GO。
